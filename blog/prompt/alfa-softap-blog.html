#什麼是 Soft AP？Linux 如何運作

Soft AP（Software Access Point，軟體存取點）是指透過軟體，將一張普通的 USB 無線網路卡變成無線基地台（Access Point），讓其他裝置（手機、筆電、IoT 設備）可以連上網路，不需要購買專用路由器或 AP 硬體。

在 Linux 生態中，Soft AP 的核心元件是：

hostapd
建立無線基地台的核心程式，負責管理 SSID、認證、加密
nl80211
Linux 無線子系統標準介面，驅動必須支援此框架才能與 hostapd 協作
dnsmasq
DHCP 伺服器，自動為連線裝置分配 IP 位址
iptables / nftables
網路位址轉換（NAT），讓連線裝置共享上游網路

關鍵在於驅動層：網路卡的 Linux 驅動必須支援 Master Mode（AP Mode）。若晶片驅動不支援此模式，hostapd 就無法啟動——無論你的設定多完美都沒用。

驗證一張網路卡是否支援 AP 模式的指令：

# 查看 iw 回報的支援模式
iw list | grep -A 10 "Supported interface modes"

# 輸出中應包含 * AP 這一行才代表支援
💡 In-kernel vs Out-of-kernel 驅動

In-kernel 驅動已被合併進 Linux 官方原始碼，系統開機即自動載入，無需手動安裝。Out-of-kernel 驅動需要你自行從 GitHub 下載、編譯，並在每次 kernel 升級後可能需要重新編譯。對 Soft AP 的長期穩定性而言，in-kernel 驅動遠優於 out-of-kernel。

#AWUS036ACM（MT7612U）— Soft AP 最佳選擇

✅
Soft AP 完整支援。In-kernel 驅動 mt76x2u 自 Linux kernel 4.19 起內建，在 Kali Linux、Ubuntu、Debian、Raspberry Pi 4/5 均有大量成功案例，零需手動安裝驅動。

MT7612U 是目前 ALFA 現售產品中，Soft AP 表現最穩定的晶片。它的驅動 mt76x2u 早在 2018 年就進入 Linux 官方 kernel，意味著只要你的系統夠新，插上去就能用——不需要 git clone，不需要 dkms，不需要在 kernel 升級後重新編譯。

核心優勢

WPA2 + WPA3
MediaTek in-kernel 驅動原生支援 WPA3 SAE，是 Realtek 驅動無法比擬的優勢
VIF 虛擬介面
同一張卡可同時作 AP + Managed + Monitor 三種模式並行，無需額外添購第二張卡
超低耗電
最大 400mA，Pi 4 USB 子系統 1200mA 總量下可安全使用，不影響其他 USB 裝置
全平台相容
Kali / Ubuntu / Debian / Raspberry Pi OS — 每個主流 Linux 平台均有驗證

hostapd.conf 正確設定（MT7612U 專用）

這是社群（morrownr/USB-WiFi）多年測試確認的能力旗標，必須完全對應 MT7612U 的實際硬體能力：

# /etc/hostapd/hostapd.conf — AWUS036ACM (MT7612U)
interface=wlan1
driver=nl80211
ssid=YourNetworkName
hw_mode=a               # 5GHz；改為 g 則使用 2.4GHz
channel=36              # UNII-1，非 DFS，最安全的選擇
ieee80211n=1
ieee80211ac=1
wmm_enabled=1
country_code=TW

# MT7612U 正確的 HT / VHT capabilities
ht_capab=[LDPC][HT40+][HT40-][GF][SHORT-GI-20][SHORT-GI-40][TX-STBC][RX-STBC1]
vht_capab=[RXLDPC][TX-STBC-2BY1][SHORT-GI-80][RX-ANTENNA-PATTERN][TX-ANTENNA-PATTERN]
vht_oper_chwidth=1
vht_oper_centr_freq_seg0_idx=42   # channel 36 對應的中心頻道索引

# 安全性
auth_algs=1
wpa=2
wpa_key_mgmt=WPA-PSK SAE         # WPA2 + WPA3 混合模式
wpa_pairwise=CCMP
rsn_pairwise=CCMP
wpa_passphrase=YourPassword
⚠️ 最常見錯誤

若 ht_capab 包含 MT7612U 不支援的能力旗標，hostapd 會直接崩潰退出，錯誤訊息非常不明顯。請務必只使用上方確認的旗標組合，不要複製其他晶片（如 RTL8812AU）的設定。

#AWUS036ACH（RTL8812AU）— 可用，但有限制

⚠️
Soft AP 有條件可用。AP 模式本身可以運作，但不支援 WPA3、不支援 VIF，且驅動在 Kali Linux 2025.x 上有已知相容問題。

RTL8812AU 是 ALFA 最具知名度的滲透測試晶片，長期以來是 Kali Linux 社群的最愛。它的 Soft AP 功能確實存在，但 Realtek 的 out-of-kernel 驅動架構帶來幾個長期限制：

已知限制清單

  • WPA3 不支援：RTL8812AU 驅動雖然在介面上顯示支援 WPA3，但多名使用者確認實際上無法運作，只能使用 WPA2-PSK。
  • VIF 不支援：無法同時在同一張卡上跑 AP 模式 + Managed 模式。需要 AP 兼監控時，必須使用兩張不同的網路卡分工。
  • Kali Linux 2025.x 驅動問題：最新版 Kali 的 aircrack-ng/rtl8812au 驅動有相容性問題，需回退至特定的舊版 commit（63cf0b4）才能正常掃描網路。Kernel 6.14+ 的 in-kernel rtw88 驅動有望改善此問題。
  • 高耗電：最大約 800mA，在 Raspberry Pi 上若同時連接多個 USB 裝置，可能導致系統不穩定，建議使用有源 USB Hub。

hostapd.conf 設定（RTL8812AU）

# /etc/hostapd/hostapd.conf — AWUS036ACH (RTL8812AU)
# 注意：與 MT7612U 的 capabilities 完全不同
ht_capab=[HT40+][HT40-][GF][SHORT-GI-20][SHORT-GI-40][TX-STBC][RX-STBC1]
vht_capab=[RXLDPC][SHORT-GI-80][TX-STBC-2BY1][RX-STBC-1][MAX-A-MPDU-LEN-EXP3][RX-ANTENNA-PATTERN][TX-ANTENNA-PATTERN]

# 安全性：只能用 WPA2，WPA3 不要加
wpa=2
wpa_key_mgmt=WPA-PSK
wpa_pairwise=CCMP

安裝驅動（Kali Linux / Ubuntu / Debian）

sudo apt update && sudo apt install -y dkms git build-essential linux-headers-$(uname -r)
git clone https://github.com/aircrack-ng/rtl8812au
cd rtl8812au
# Kali 2025.x 需要指定舊版 commit
git checkout 63cf0b4
make && sudo make install
sudo modprobe 88XXau

#AWUS036AXML / AWUS036AXM（MT7921AUN）— 謹慎選擇

⚠️
AP 模式技術上支援（kernel 5.19+），但有已知的 Bluetooth 干擾問題導致不穩定。有成功案例，但需要額外手動處理，不適合對穩定性要求高的生產環境。

AWUS036AXML 與 AWUS036AXM 是 ALFA 的 WiFi 6E 三頻旗艦，能覆蓋 2.4 GHz、5 GHz 和全新的 6 GHz 頻段。它的 in-kernel 驅動 mt7921u 從 kernel 5.18 起就已內建，AP 模式支援則在 kernel 5.19 正式加入。

然而，MT7921AUN 晶片同時整合了 Bluetooth 5.2，這成為了 2024–2025 年社群最頭疼的問題根源。

已知問題與解決方案

問題一：Bluetooth 干擾導致 WiFi 崩潰

在 kernel 6.6 以後的版本，BT 子系統的變動導致 mt7921u 的 WiFi 功能偶發崩潰，重現率因系統環境而異。目前最有效的解決方案是禁用 btusb 驅動：

echo "install btusb /bin/false" >> /etc/modprobe.d/local-dontload.conf
sudo reboot

問題二：韌體版本過舊

若系統的 MediaTek 韌體過舊，網路卡可能無法被正確識別。需安裝 2024年11月以後的最新韌體：

# 確認當前韌體版本
dmesg | grep "WM Firmware"
# 應顯示：Build Time: 20241106151045 或更新

# 若版本過舊，從 kernel.org 下載更新
sudo cp WIFI_MT7961_patch_mcu_1a_2_hdr.bin /lib/firmware/mediatek
sudo cp WIFI_RAM_CODE_MT7961_1a.bin /lib/firmware/mediatek
sudo reboot

#AWUS036AX / AWUS036AXER（RTL8832BU）— 不建議用於 Soft AP

❌
不建議用於 Soft AP。Multi-state 裝置（內建 Windows 驅動）、Linux Soft AP 社群驗證案例幾乎為零，且需要 USB mode switch 才能在 Linux 下正常運作。

AWUS036AX 和 AWUS036AXER 雖然是 WiFi 6 規格，但 RTL8832BU 晶片是所謂的「multi-state」裝置——出廠預設以 USB 大量儲存模式枚舉，Linux 需要先做 USB mode switch 才能切換為無線網路卡模式。這層複雜度，加上 Linux 社群對此晶片在 Soft AP 用途幾乎沒有驗證案例，使我們無法推薦它用於 hostapd 部署。

若需要 Soft AP 功能，請選擇 AWUS036ACM。若需要滲透測試，請選擇 AWUS036ACH 或 AWUS036AXML。

#技術深入：VIF、WPA3、DFS 頻道

VIF（虛擬介面）：一張卡同時做多件事

VIF（Virtual Interface）讓同一張物理網路卡可以同時以多個邏輯介面運作。例如：一個介面連上游路由器（managed 模式），同時另一個介面作為 AP（master 模式）供其他裝置連入。只有 MediaTek 的 in-kernel 驅動（MT7612U、MT7921AUN）完整支援 VIF；Realtek 的 out-of-kernel 驅動基本上無此能力。 

# MT7612U — 建立額外的 AP 虛擬介面
sudo iw phy phy1 interface add ap0 type __ap
sudo ip link set ap0 up
# 現在 wlan1 可以連上游網路，ap0 跑 hostapd

5GHz Soft AP 的頻道選擇：避開 DFS

DFS（Dynamic Frequency Selection）頻道（ch100–ch140）需要雷達偵測機制，MT7610U / MT7612U 等晶片不支援。使用 5GHz AP 時，強烈建議選擇 UNII-1（ch36、ch40、ch44、ch48） 或 UNII-2A（ch52、ch56、ch60、ch64）非 DFS 的頻道。

#社群真實案例整理

案例 1：RPi4B + AWUS036ACM = 長期穩定家用 5GHz AP

來源：morrownr/7612u GitHub 知識庫。morrownr 長期以 RPi4B + AWUS036ACM 作為家用 5GHz AP，搭配 Pi 內建 2.4GHz 提供雙頻服務。配置：hostapd + dnsmasq + iptables NAT，長期無需重啟。

案例 2：RPi3B+ + AWUS036ACM — 初始崩潰，調整後成功

來源：GitHub morrownr/USB-WiFi issue #2。使用者在 RPi3B+ 上以 USB 2.0 埠執行，hostapd 崩潰。根本原因：ht_capab 包含 USB 2.0 頻寬限制下不支援的 HT40 設定旗標。移除多餘旗標後，在 Kali Linux 上成功啟動。

案例 3：Pi PwnBox + AWUS036ACH = 紅隊測試 Rogue AP

來源：GitHub koutto/pi-pwnbox-rogueap。以 RPi3B+ 建立 Rogue AP 平台：一張 RTL8812AU（AWUS036ACH）負責跑 AP，另一張 RT3070（AWUS036NEH）負責封包注入攻擊。因 RTL8812AU 不支援 VIF，必須使用兩張卡分工。

案例 4：AWUS036AXML 在 RPi3B ArchLinux ARM 上穩定跑 AP

來源：GitHub issue #476。使用者在 RPi3B ArchLinux aarch64 上成功跑 AWUS036AXML AP 模式，評為該用戶手上 mt7921 系列中最穩定的一張。關鍵：從 git 編譯最新版 hostapd，並禁用 btusb。
