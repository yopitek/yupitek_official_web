حاسوب محمول يعمل بنظام Kali Linux هو محطة العمل القياسية لاختبار الاختراق — لكنه ليس الخيار الوحيد بالتأكيد. Raspberry Pi 4 أو Pi 5 مقترناً بمحول ALFA USB WiFi يمنحك منصةً مدمجة خاليةً من المروحة ذات تبريد سلبي، تتسع في جيب المعطف، وتعمل ببطارية USB-C المحمولة، ويمكن تركها دون رقابة في بيئة الهدف لساعات طويلة. تصدر صور Kali Linux ARM64 مباشرةً من Offensive Security وتعمل أصلاً على Pi 4 وPi 5 دون محاكاة، مما يمنحك الأدوات الكاملة: Aircrack-ng وKismet وWireshark وBettercap وسائر حزم Kali القياسية.

العقبة الأولى هي الدرايفر. شريحة RTL8812AU المدمجة في AWUS036ACH ليست ضمن النواة الرئيسية، مما يعني أنك لا تستطيع توصيل المحول وتوقع عمله فوراً. يجب تجميع الدرايفر مقابل نواة ARM64 الجارية — وإشارات التجميع تختلف عن x86-64. يأخذك هذا الدليل خلال كل خطوة.

## الأجهزة الموصى بها

لا تعمل كل مجموعة من طرازات Pi والمحولات ووحدات إمداد الطاقة بشكل موثوق. يعكس الجدول أدناه ما تم التحقق من عمله بشكل جيد والمقايضات المتوقعة.

| المكوّن | الموصى به | ملاحظات |
|---|---|---|
| الكمبيوتر أحادي اللوح | Raspberry Pi 5 (4 GB أو 8 GB) | Pi 4 (4 GB+) يعمل بشكل جيد؛ Pi 3B+ بطيء جداً للالتقاط الفوري |
| المحول الأساسي | ALFA AWUS036ACH | شريحة RTL8812AU؛ أفضل دعم لدرايفر ARM؛ ثنائي النطاق AC1200 |
| المحول البديل | ALFA AWUS036ACM | شريحة MT7612U؛ برنامج تشغيل مدمج في النواة (mt76x2u)؛ plug-and-play على Kali ARM64 |
| محول WiFi 6 | ALFA AWUS036AXM أو AXML | شريحة MT7921AUN؛ مدمج بالنواة منذ 5.18؛ يحتاج firmware-misc-nonfree |
| موزع USB | موزع USB 3.0 بطاقة كهربائية خارجية | AWUS036ACH يستهلك ~500 mW؛ قد يؤدي إلى انخفاض الجهد في منافذ Pi |
| التخزين | MicroSD 32 GB+ (Class 10 / A2) | بطاقات A2 أسرع بشكل ملحوظ في التشغيل وعمليات apt |
| مصدر الطاقة | مصدر طاقة Pi الرسمي USB-C (≥ 3 A) | المحولات من أطراف ثالثة سبب شائع لمشاكل الاستقرار |

{{< alert "triangle-exclamation" >}}
AWUS036ACH جهاز USB عالي التيار. توصيله مباشرةً بـ Raspberry Pi 4 أو Pi 5 دون موزع USB بطاقة كهربائية خارجية قد يتسبب في تقليص أداء Pi أو إعادة تشغيله تحت الحمل. استخدم دائماً موزعاً بطاقة كهربائية عند تشغيل AWUS036ACH مع ملحقات USB أخرى.

## تثبيت Kali Linux ARM64 على Raspberry Pi

### تنزيل صورة ARM

يوفر Kali Linux صور ARM64 رسمية لـ Raspberry Pi على [https://www.kali.org/get-kali/#kali-arm](https://www.kali.org/get-kali/#kali-arm). نزّل الصورة المسماة **Raspberry Pi 4 (64-bit)** أو **Raspberry Pi 5 (64-bit)**. لا تستخدم الصورة 32-bit — نواة ARM64 مطلوبة لخطوات بناء الدرايفر في هذا الدليل.

### الكتابة على MicroSD

يمكنك الكتابة باستخدام أداة Raspberry Pi Imager أو `dd` من سطر الأوامر:

```bash
# استبدل /dev/sdX بجهاز SD الفعلي (تحقق بـ lsblk)
sudo dd if=kali-linux-2025.1-raspberry-pi-arm64.img of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

مع Raspberry Pi Imager: اختر **Use custom** ← اختر ملف Kali `.img.xz` ← اختر بطاقة SD ← اكتب.

### التشغيل الأول والإعداد الأولي

أدخل بطاقة SD، وصل شاشة ولوحة مفاتيح (أو اعداد وصول headless أولاً)، وشغّل الجهاز. بيانات الاعتماد الافتراضية:

- **اسم المستخدم:** `kali`
- **كلمة المرور:** `kali`

بعد تسجيل الدخول، شغّل `kali-tweaks` واتبع التعليمات لتقوية الإعداد الافتراضي. ثم حدّث النظام بالكامل قبل الإعداد:

```bash
sudo apt update && sudo apt full-upgrade -y
sudo reboot
```

{{< alert "circle-info" >}}
إذا كنت تخطط للوصول إلى Pi عبر SSH، فعّل SSH قبل التشغيل الأول بوضع ملف فارغ باسم `ssh` في قسم `/boot` من بطاقة SD. هذه الآلية نفسها المستخدمة في Raspberry Pi OS القياسي.
{{< /alert >}}

## تثبيت درايفر RTL8812AU على Kali ARM64 (AWUS036ACH)

درايفر RTL8812AU غير مضمّن في نواة Linux الرئيسية. على ARM64 يجب إما التجميع من المصدر أو تثبيت نسخة DKMS المحزومة من Kali. كلا المسارين موضحان أدناه — ابدأ بنهج الحزمة وارجع للبناء اليدوي فقط عند مواجهة عدم توافق إصدار النواة.

### الخيار 1: حزمة Kali (نقطة البداية الموصى بها)

يوفر Kali Linux نسخة DKMS محزومة لدرايفر RTL8812AU تتعامل مع إعادة التجميع تلقائياً عند تحديث النواة.

```bash
sudo apt install realtek-rtl88xxau-dkms
```

بعد التثبيت، أعد التشغيل وتحقق من تحميل الوحدة:

```bash
sudo modprobe 88XXau
ip link show
```

إذا رأيت واجهة `wlan1` (بافتراض أن `wlan0` هو المحول المدمج في Pi)، فالدرايفر يعمل. قد تتأخر هذه الحزمة عن إصدار GitHub بأسابيع قليلة، لكنها نقطة بداية منخفضة الاحتكاك.

{{< alert "circle-info" >}}
حزمة Kali كافية عادةً لمعظم بيئات ARM64. تابع إلى البناء اليدوي أدناه فقط إذا فشلت حزمة DKMS في التجميع مقابل إصدار نواتك الحالي، والذي يمكن التحقق منه بـ `uname -r`.
{{< /alert >}}

### الخيار 2: البناء اليدوي من المصدر (ARM64)

إذا فشلت حزمة DKMS — الأكثر شيوعاً لأن نواتك أحدث من آخر نسخة اختبرتها الحزمة — ابنِ مباشرةً من فرع Aircrack-ng على GitHub. هذا هو المصدر الرسمي لدعم ARM64.

```bash
sudo apt update
sudo apt install -y build-essential dkms git linux-headers-$(uname -r)

git clone https://github.com/aircrack-ng/rtl8812au.git
cd rtl8812au

# تبديل إشارات المنصة من x86 إلى ARM64
sed -i 's/CONFIG_PLATFORM_I386_PC = y/CONFIG_PLATFORM_I386_PC = n/' Makefile
sed -i 's/CONFIG_PLATFORM_ARM64_RPI = n/CONFIG_PLATFORM_ARM64_RPI = y/' Makefile

sudo make dkms_install
```

أوامر `sed` هي الفرق الجوهري عن بناء x86-64. بدونها، يستخدم Makefile مسارات منصة x86 بشكل افتراضي والوحدة الناتجة لن تُحمّل على ARM64.

بعد بناء ناجح، حمّل الوحدة وتحقق:

```bash
sudo modprobe 88XXau
ip link show
```

يجب أن ترى واجهة جديدة — عادةً `wlan1`. إذا أظهر `ip link show` الواجهة، فالدرايفر يعمل بشكل صحيح.

## MT7921AUN على Raspberry Pi (AWUS036AXM / AXML)

شريحة MediaTek MT7921AUN المستخدمة في AWUS036AXM وAXML موجودة في النواة الرئيسية منذ الإصدار 5.18. صور Kali Linux ARM64 تشحن بنواة تتجاوز هذا العتبة بكثير، مما يعني أن الدرايفر يُحمّل تلقائياً عند توصيل المحول — لا حاجة للتجميع.

الخطوة الإضافية الوحيدة المطلوبة هي تثبيت حزمة البرامج الثابتة المغلقة المصدر التي يحتاجها MT7921AUN:

```bash
sudo apt install firmware-misc-nonfree
sudo reboot
```

بعد إعادة التشغيل، تحقق من اكتشاف المحول وتشغيل الواجهة:

```bash
lsusb
sudo modprobe mt7921u
ip link show
```

إذا أظهر `lsusb` جهاز MediaTek وأدرج `ip link show` واجهة لاسلكية جديدة، فالمحول جاهز. دعم وضع المراقبة في MT7921AUN تحسّن بشكل كبير منذ النواة 5.18 لكنه قد يكون أقل موثوقية من المحولات المبنية على RTL8812AU في بعض اختبارات حقن الحزم. للتوافق الأقصى مع سير عمل اختبار الاختراق الأقدم، يظل AWUS036ACH الخيار الأقوى.

## تفعيل وضع المراقبة على Raspberry Pi

Raspberry Pi لديه واجهة WiFi مدمجة (`wlan0`). أبقها متصلة بشبكتك للحفاظ على وصول SSH. استخدم محول ALFA (`wlan1`) حصرياً لوضع المراقبة والتقاط الحزم. لا تضع `wlan0` مطلقاً في وضع المراقبة على Pi بدون شاشة — ستفقد اتصال SSH.

```bash
# إيقاف العمليات التي تتعارض مع وضع المراقبة (NetworkManager، wpa_supplicant)
sudo airmon-ng check kill

# تفعيل وضع المراقبة على واجهة محول ALFA
sudo airmon-ng start wlan1

# التحقق من تفعيل وضع المراقبة
sudo iwconfig wlan1mon

# بدء الالتقاط على كل القنوات
sudo airodump-ng wlan1mon
```

{{< alert "circle-info" >}}
`airmon-ng start wlan1` ينشئ واجهة جديدة باسم `wlan1mon`. شغّل الأدوات اللاحقة دائماً مقابل `wlan1mon` وليس `wlan1`. يمكنك تأكيد اسم الواجهة بـ `iwconfig` أو `ip link show`.
{{< /alert >}}

{{< alert "triangle-exclamation" >}}
تشغيل `airmon-ng check kill` يوقف NetworkManager وwpa_supplicant. إذا كنت متصلاً عبر SSH من خلال `wlan0`، سيُقطع اتصال SSH أيضاً. للأجهزة بدون شاشة، اتصل عبر الإيثرنت أو واجهة سلكية ثانية قبل تشغيل هذه الأوامر، أو استخدم `tmux` حتى تستمر جلستك بعد الانقطاع.
{{< /alert >}}

لتعطيل وضع المراقبة واستعادة الوضع المُدار:

```bash
sudo airmon-ng stop wlan1mon
sudo systemctl start NetworkManager
```

## نصائح إعداد اختبار الاختراق المحمول

جعل الأجهزة تعمل هو نصف العمل فحسب. هذه الاختيارات العملية هي الفرق بين طقم ميداني مستقر وكومة محبطة من الكابلات.

**بنية الشبكة:** استخدم `wlan0` (WiFi المدمج في Pi) للحفاظ على اتصال الإدارة — ادخل إلى Pi عبر SSH من حاسوب محمول على نفس الشبكة المحلية أو نقطة الاتصال. خصص `wlan1` (محول ALFA) كلياً لنشاط اختبار الاختراق. لا تخلط الدورين أبداً.

**التشغيل بدون شاشة:** تجنب توصيل لوحة مفاتيح وفأرة وشاشة في الميدان. اضبط SSH عند التشغيل الأول، وادخل إلى كل شيء عبر محاكي طرفية على حاسوبك المحمول. جلسات `tmux` تستمر عبر إعادة الاتصال، وهو أمر لا غنى عنه عندما تكون الشبكة غير مستقرة.

**الطاقة:** استخدم مصدر طاقة Pi الرسمي USB-C بحد أدنى 3 A. للـ AWUS036ACH، أضف موزع USB بطاقة خارجية مقدر بـ 2.5 A أو أعلى. بطارية USB-C محمولة عالية الجودة (65 W+) تستطيع تزويد Pi والموزع والمحول بالطاقة في آنٍ واحد لمدة 4-6 ساعات حسب الحمل.

**التخزين:** اكتب سجلات Kismet وملفات الالتقاط على USB SSD وليس بطاقة MicroSD. بطاقات MicroSD لها دورات كتابة محدودة وتتدهور بسرعة تحت أحمال التسجيل المستمر. USB 3.0 SSD متصل بالموزع الكهربائي أسرع وأكثر متانة.

**الحافظة:** اختر حافظة Pi بمنافذ USB مفتوحة أو فتحات تستوعب الموزع الكهربائي. الحافظات الألومنيومية بزعانف التبريد السلبي تساعد على إدارة درجات الحرارة خلال الالتقاط المستمر.

## تشغيل Kismet على Raspberry Pi

Kismet ماسح WiFi سلبي يعمل كخادم خلفي ويكشف واجهة ويب مستندة للمتصفح. مناسب جداً لنشر Pi بدون شاشة: اتركه يعمل وتفقد واجهة الويب من أي جهاز على نفس الشبكة.

```bash
sudo apt install kismet

# تشغيل Kismet باستخدام محول ALFA في وضع المراقبة
kismet -c wlan1
```

{{< alert "circle-info" >}}
عند تمرير اسم الواجهة مباشرةً، يضع Kismet الواجهة في وضع المراقبة بنفسه. لا تحتاج لتشغيل `airmon-ng start` قبل إطلاق Kismet. يدير Kismet دورة حياة الواجهة داخلياً.
{{< /alert >}}

بعد التشغيل، ادخل إلى واجهة ويب Kismet من أي متصفح على شبكتك:

```
http://raspberrypi.local:2501
```

عند أول تشغيل، يطلب Kismet إنشاء اسم مستخدم وكلمة مرور للمدير. بعد تسجيل الدخول، تستطيع عرض الشبكات المكتشفة والعملاء المرتبطين وسجل قوة الإشارة وبيانات GPS إذا كان ذراع GPS متصلاً.

يسجّل Kismet كل شيء في ملفات قاعدة بيانات `.kismet` في `~/.kismet/` بشكل افتراضي. يمكن تصديرها لاحقاً للتحليل أو الرفع على WiGLE.

## حالة الاستخدام: إعداد Wardriving

Raspberry Pi يعمل بـ Kismet مع محول ALFA وذراع GPS هو طقم wardriving متكامل ومكتفٍ بذاته — أصغر وأرخص من أي جهاز wardriving متخصص.

**المكونات المطلوبة:**
- Raspberry Pi 4 أو Pi 5
- ALFA AWUS036ACH
- ذراع GPS USB (شرائح u-blox تعمل بشكل جيد مع Kismet)
- موزع USB بطاقة كهربائية خارجية
- بطارية USB-C محمولة (65 W+، مع شحن pass-through)

**خطوات الإعداد:**

1. تثبيت Kismet وحزم GPS:

```bash
sudo apt install kismet gpsd gpsd-clients
```

2. ضبط `gpsd` لقراءة ذراع GPS:

```bash
sudo gpsd /dev/ttyUSB0 -F /var/run/gpsd.sock
```

3. تشغيل Kismet مع دعم GPS:

```bash
kismet -c wlan1 --gps=gpsd:host=localhost,port=2947
```

4. ضع Pi والموزع والمحول والبطارية في حقيبة أو حافظة وضعها في مركبتك. ادخل إلى واجهة ويب Kismet من نقطة اتصال هاتفك أو جهاز لوحي متصل بنفس شبكة WiFi الخاصة بـ Pi.

تلتقط سجلات Kismet إحداثيات GPS لكل شبكة تم اكتشافها. صدّر قاعدة بيانات `.kismet` إلى صيغة WiGLE CSV باستخدام `kismetdb_to_wigle` (مضمّن مع Kismet) وارفعه إلى WiGLE للخرائط.

{{< alert "triangle-exclamation" >}}
التزم دائماً بالقوانين المحلية قبل إجراء أي نشاط مسح للشبكات. في كثير من الولايات القضائية، يعد wardriving بالمسح السلبي فحسب قانونياً؛ أما الفحص النشط أو الاتصال بالشبكات دون إذن فلا. تعرّف على اللوائح المحلية في منطقتك.
{{< /alert >}}
