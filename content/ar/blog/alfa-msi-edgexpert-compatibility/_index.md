> 📌 حُدِّث هذا المقال وفق اختبارات GX10 الفعلية في نوفمبر 2026: على ASUS GX10 (Ubuntu 24.04 ARM64، النواة 6.17.0-1014-nvidia) تعمل بطاقات ALFA التسع الحالية جميعها بتعريفات مدمجة في النواة، وتعمل فور توصيلها دون الحاجة إلى DKMS. البيانات الكاملة في [الجدول الشامل لاختبار بطاقات ALFA التسع على ARM64](/ar/blog/alfa-9-cards-arm64-gx10-ubuntu-matrix/). أُجري الاختبار على GX10 فقط، ولم تُختبر طرازات GB10 الأخرى جهازًا جهازًا.

## 1. ملخص المشكلة

يسأل العميل: «هل يمكن استخدام بطاقات الشبكة اللاسلكية USB من سلسلة ALFA على MSI EdgeXpert (منصة NVIDIA GB10 Grace Blackwell)؟»

الخلاصة المختصرة: يستخدم MSI EdgeXpert وNVIDIA DGX Spark شريحة GB10 نفسها وسلسلة أنوية NVIDIA نفسها. اختبرنا فعليًا على ASUS GX10 (Ubuntu 24.04 ARM64، النواة 6.17.0-1014-nvidia) بطاقات ALFA التسع الحالية بواجهة USB (AWUS036ACM / ACHM / ACH / ACS / EACS / AX / AXER / AXM / AXML)، فوجدنا أنها جميعًا تستخدم تعريفات مدمجة في النواة وتعمل فور توصيلها، دون حاجة إلى تجميع (compile) أو DKMS. السلوك المتوقع مطابق، لكن الاختبار أُجري على GX10 فقط، ولم يُختبر MSI EdgeXpert بعينه. الفروق الوظيفية: طرازات MediaTek MT7921 (AWUS036AXM / AXML) يفشل فيها حقن الحزم (packet injection) على النواة القياسية 6.17، بينما تعمل أوضاع monitor وAP وWPA3؛ أما الطرازات السبعة الأخرى فقد ثبت عمليًا أن وضع monitor والحقن يعملان فيها. يختلف أدنى إصدار للنواة دخل فيه تعريف كل بطاقة إلى الفرع الرئيسي (ACM / ACHM: 4.19، AXM / AXML: 5.18، EACS: 6.2، ACH / ACS: 6.13، AX / AXER: 6.17)، ولا تحتاج إلى تعريفات DKMS المجتمعية إلا الأنوية الأقدم من ذلك الإصدار. ملاحظة: منافذ USB الأربعة في EdgeXpert كلها من نوع USB Type-C (20Gbps)، لذا تحتاج بطاقات ALFA (باستثناء AXML) إلى محول من USB-C إلى USB-A.

نطاق التقييم: بطاقات ALFA التسع الحالية بواجهة USB (AWUS036ACM / ACHM / ACS / EACS / ACH / AX / AXER / AXML / AXM).

MSI EdgeXpert إصدار OEM من منصة DGX Spark، والعتاد الأساسي والبرمجيات متطابقان تمامًا:

| العنصر | MSI EdgeXpert | NVIDIA DGX Spark |

### 2.4 الحاجة إلى محول USB Type-C

منافذ USB الأربعة في EdgeXpert كلها من نوع Type-C، بينما بطاقات ALFA كلها بموصل USB Type-A (باستثناء AXML بموصل USB-C)، لذلك يلزم استخدام محول. يُنصح باختيار محول يدعم USB 3.2 Gen 2×2 (20Gbps).

## 7. خطوات الإعداد بالتفصيل خطوة بخطوة

يُتوقع أن تكون خطوات التثبيت على MSI EdgeXpert مطابقة لـ NVIDIA DGX Spark (الخطوات مختبرة على GX10). فيما يلي نسخة مختصرة، والخطوات الكاملة في الفصل السابع من مقال [هل تتوافق بطاقات الشبكة اللاسلكية ALFA مع NVIDIA DGX Spark](/ar/blog/alfa-nvidia-dgx-spark-compatibility/).

### 7.1 طرازات شرائح MediaTek (AWUS036ACM / ACHM / AXM / AXML)

**الخطوة 1: توصيل البطاقة**

استخدم محول USB-C إلى USB-A (يمكن توصيل AXML مباشرة)، ثم أدخل بطاقة ALFA في منفذ USB-C في EdgeXpert.

**الخطوة 2: التحقق من اكتشاف USB**

```bash
lsusb
# مثال على الناتج المتوقع (AWUS036ACM / MT7612U):
# Bus 001 Device 003: ID 0e8d:7612 MediaTek Inc. MT7612U 802.11a/b/g/n/ac Wireless Adapter
```

**الخطوة 3: التحقق من واجهة الشبكة**

```bash
ip link show
# يجب أن تظهر تلقائيًا واجهة يبدأ اسمها بـ wlx (يُحمَّل التعريف المدمج في النواة تلقائيًا)
```

**الخطوة 4: الاتصال بشبكة WiFi**

```bash
nmcli dev wifi connect "SSID" password "كلمة المرور"
```

### 7.2 طرازات شرائح Realtek (AWUS036ACH / ACS / EACS / AX / AXER)

تتضمن النواة 6.17 (الإصدار المختبر على GX10) تعريفات جميع طرازات Realtek، والخطوات مطابقة لطرازات MediaTek دون أي تجميع (أدنى إصدار: EACS: 6.2، ACH / ACS: 6.13، AX / AXER: 6.17):

```bash
# 1. تحقق من إصدار النواة (6.17 فما فوق تتضمن تعريفات جميع طرازات Realtek؛ الإصدار المختبر على GX10 هو 6.17.0-1014-nvidia)
uname -r

# 2. بعد توصيل البطاقة، تحقق من تحميل التعريف تلقائيًا
lsusb
lsmod | grep -E "rtw88|rtw89"
ip link show

# 3. الاتصال بشبكة WiFi
nmcli dev wifi connect "SSID" password "كلمة المرور"
```

الوحدات (modules) التي تُحمَّل تلقائيًا لكل طراز: ACH: `rtw88_8812au`، ACS: `rtw88_8821au`، EACS: `rtw88_8821cu`، AX / AXER: `rtw89_8852bu`. فقط إذا كان ناتج `uname -r` أقدم من أدنى إصدار للبطاقة (نظام قديم) تحتاج إلى تثبيت تعريف DKMS يصونه المجتمع (مثل morrownr/8812au-20210820 لشريحة RTL8812AU).

### 7.3 وضع المراقبة (اختبار الاختراق)

⚠️ لا تُجرِ اختبارات المراقبة والحقن إلا على شبكات تملكها أو حصلت على إذن صريح باختبارها.

```bash
sudo apt install -y aircrack-ng
IF=wlx00c0cafe0000   # استبدله باسم الواجهة الذي يظهر في ip link
sudo ip link set $IF down
sudo iw dev $IF set type monitor
sudo ip link set $IF up
sudo aireplay-ng --test $IF
```

- لا تشغّل `airmon-ng check kill`: فهو يوقف NetworkManager ويقطع اتصال الجهاز بالشبكة الخارجية.
- على AWUS036AXM / AXML يفشل الأمر `aireplay-ng --test` على النواة القياسية 6.17 (Found 0 APs)، فلا يمكن تنفيذ deauth أو التقاط handshake.
- يظهر الخطأ `failed to arm` مع hcxdumptool 8.x على البطاقات التسع كلها عدا EACS على 2.4 GHz (التعريفات لا تدعم active monitor)، لذا استخدم airodump-ng + aireplay-ng بدلًا منه.

## 9. القيود المعروفة

- **الحاجة إلى محول USB Type-C**: باستثناء AXML، تحتاج جميع بطاقات ALFA إلى محول USB-C إلى USB-A.
- **فشل الحقن في طرازات MT7921**: يفشل حقن الحزم في AWUS036AXM / AXML على النواة القياسية 6.17، فلا يمكن تنفيذ deauth أو التقاط handshake؛ بينما تعمل أوضاع monitor وAP وWPA3. السبب الرئيسي تراجع (regression) في mac80211 chanctx منذ النواة 6.16، وما زالت التعريفات المعدّلة من المجتمع محدودة السرعة.
- **نطاق الاختبار**: أُجري الاختبار على ASUS GX10 (النواة 6.17.0-1014-nvidia) فقط؛ ولم يُختبر MSI EdgeXpert بعينه، والسلوك المتوقع مطابق.
- **تعذّر استخدام hcxdumptool**: يظهر الخطأ `failed to arm` على كل البطاقات عدا EACS على 2.4 GHz، لذا استخدم airodump-ng + aireplay-ng.
- **احتمال تعارض Wi-Fi 7 المدمج**: يحتوي EdgeXpert على Wi-Fi 7 + BT 5.4 مدمجين.
- **وضع AP يتطلب إعدادًا يدويًا**: DGX OS مهيأ افتراضيًا كبيئة تطوير.
- **قيود تنظيمية على 6GHz**: يعتمد توفر Wi-Fi 6E على المنطقة التنظيمية.
- **الأنوية القديمة**: لا تحتاج طرازات Realtek إلى تعريفات DKMS المجتمعية إلا على الأنظمة ذات النواة الأقدم من أدنى إصدار للبطاقة (EACS: 6.2، ACH / ACS: 6.13، AX / AXER: 6.17)، وفي هذه الحالة يجب إعادة تجميعها بعد كل تحديث للنواة.
- **فروق الإصدار الصناعي لا تؤثر على التوافق**: مواصفات عتاد الإصدار الصناعي من MSI (MS-C931) مطابقة للإصدار الاستهلاكي، وتوافق USB WiFi واحد في الإصدارين.

شروط النقض: إذا تغيّرت صفحة المواصفات الرسمية من MSI (تعديل مواصفات منافذ USB، أو إصدار نواة أقدم من 6.x)، أو كشف الاختبار الفعلي أن mt76x2u / mt7921u لا تُحمَّل تلقائيًا على DGX OS، فيجب مراجعة مصفوفة التوافق في الفصل السادس؛ وإذا تغيّر سلوك التعريفات المدمجة بعد تحديث نواة NVIDIA، فيجب إعادة الاختبار الفعلي.
