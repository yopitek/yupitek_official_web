> 📌 حُدِّث هذا المقال وفق اختبارات GX10 الفعلية في نوفمبر 2026: على ASUS GX10 (Ubuntu 24.04 ARM64، النواة 6.17.0-1014-nvidia) تعمل بطاقات ALFA التسع الحالية جميعها بتعريفات مدمجة في النواة، وتعمل فور توصيلها دون الحاجة إلى DKMS. البيانات الكاملة في [الجدول الشامل لاختبار بطاقات ALFA التسع على ARM64](/ar/blog/alfa-9-cards-arm64-gx10-ubuntu-matrix/). أُجري الاختبار على GX10 فقط، ولم تُختبر طرازات GB10 الأخرى جهازًا جهازًا.

## 1. ملخص المشكلة

يسأل العميل: «هل يمكن استخدام بطاقات الشبكة اللاسلكية USB من سلسلة ALFA على حاسوب الذكاء الاصطناعي الفائق الشخصي NVIDIA DGX Spark (GB10 Grace Blackwell)؟»

الخلاصة المختصرة: يعمل DGX Spark بنظام NVIDIA DGX OS (مبني على Ubuntu، kernel 6.x). اختبرنا فعليًا على ASUS GX10 المبني على منصة GB10 نفسها (Ubuntu 24.04 ARM64، النواة 6.17.0-1014-nvidia) بطاقات ALFA التسع الحالية بواجهة USB، فوجدنا أنها جميعًا تستخدم تعريفات مدمجة في النواة وتعمل فور توصيلها، دون حاجة إلى تجميع (compile) أو DKMS. يستخدم DGX Spark شريحة GB10 نفسها وسلسلة أنوية NVIDIA نفسها، والسلوك المتوقع مطابق، لكن الاختبار أُجري على GX10 فقط، ولم يُختبر DGX Spark بعينه. الفروق الوظيفية: طرازات MediaTek MT7921 (AWUS036AXM / AXML) يفشل فيها حقن الحزم على النواة القياسية 6.17، بينما تعمل أوضاع monitor وAP وWPA3؛ أما الطرازات السبعة الأخرى فقد ثبت عمليًا أن وضع monitor والحقن يعملان فيها. يختلف أدنى إصدار للنواة دخل فيه تعريف كل بطاقة إلى الفرع الرئيسي (ACM / ACHM: 4.19، AXM / AXML: 5.18، EACS: 6.2، ACH / ACS: 6.13، AX / AXER: 6.17)، ولا تحتاج إلى تعريفات DKMS المجتمعية إلا الأنوية الأقدم من ذلك الإصدار. ملاحظة: جميع منافذ USB في DGX Spark من نوع USB Type-C، بينما بطاقات ALFA بموصل USB Type-A، لذا يلزم محول أو كابل من USB-C إلى USB-A.

نطاق التقييم: بطاقات ALFA التسع الحالية بواجهة USB (AWUS036ACM / ACHM / ACS / EACS / ACH / AX / AXER / AXML / AXM).

### 2.3 الميزات الأساسية: نواة حديثة + ARM64

لبيئة برمجيات DGX Spark تأثيران أساسيان على توافق بطاقات ALFA:

- النواة 6.x (حديثة): تتضمن النواة 6.17 (الإصدار المختبر على GX10) تعريفات البطاقات التسع المذكورة في هذا المقال، ومنها mt76 (MT7612U / MT7610U، 4.19+) وmt7921u (MT7921AUN، 5.18+) وrtw88 (RTL8821CU 6.2+؛ RTL8812AU / RTL8811AU 6.13+) وrtw89 (RTL8832BU، 6.17+). وهذا على النقيض تمامًا من النواة 4.9 في Jetson Nano.
- معمارية ARM64 (aarch64): عند استخدام التعريفات المدمجة في النواة لا حاجة إلى تجميع أي شيء على ARM64؛ ولا تحتاج طرازات Realtek إلى تجميع تعريفات DKMS المجتمعية (مثل سلسلة morrownr، مع التأكد من ضبط CONFIG_PLATFORM_ARM64 = y في Makefile) إلا على الأنظمة القديمة ذات النواة الأقدم من أدنى إصدار للبطاقة.

### 2.4 الحاجة إلى محول USB Type-C

منافذ USB الأربعة في DGX Spark كلها من نوع Type-C، بينما بطاقات ALFA كلها بواجهة USB Type-A (باستثناء AXML بواجهة USB-C):

| الطراز | مواصفة الواجهة | هل يلزم محول؟ |
|---|---|---|
| AWUS036AXML | USB-C / USB 3.2 | ❌ لا يلزم (توصيل مباشر) |
| AWUS036AXM | USB Type-A / USB 3.2 | ✅ يلزم محول USB-C إلى USB-A |
| AWUS036AX | USB Type-A / USB 3.2 | ✅ يلزم |
| AWUS036AXER | USB Type-A / USB 3.2 | ✅ يلزم |
| AWUS036ACH | USB Type-A / USB 3.0 | ✅ يلزم |
| AWUS036ACHM | USB Type-A / USB 2.0 | ✅ يلزم |
| AWUS036ACM | USB Type-A / USB 3.0 | ✅ يلزم |
| AWUS036ACS | USB Type-A / USB 2.0 | ✅ يلزم |
| AWUS036EACS | USB Type-A / USB 2.0 | ✅ يلزم |

التوصية: استخدم محولًا أو كابلًا من USB-C إلى USB-A يدعم USB 3.2 Gen 2×2 (20Gbps) لضمان عمل طرازات USB 3.x مثل AWUS036ACH / ACM / AX بسرعتها الكاملة.

## 7. خطوات الإعداد بالتفصيل خطوة بخطوة

### 7.1 الأعمال التحضيرية

**الخطوة 1: شغّل DGX Spark وسجّل الدخول** (عبر SSH أو بتوصيل لوحة مفاتيح وشاشة مباشرة)

```bash
ssh username@<dgx-spark-ip>
```

**الخطوة 2: تحقق من معمارية النظام وإصدار النواة**

```bash
uname -m
# المتوقع: aarch64
uname -r
# المتوقع: 6.x.x (نواة DGX OS)
```

**الخطوة 3: تحقق من أن إصدار النواة 6.17 فما فوق**

تتضمن النواة 6.17 فما فوق تعريفات البطاقات التسع كلها، فلا حاجة إلى تثبيت أدوات التجميع. يختلف أدنى إصدار من بطاقة لأخرى (ACM / ACHM: 4.19، AXM / AXML: 5.18، EACS: 6.2، ACH / ACS: 6.13، AX / AXER: 6.17)؛ وإذا كانت النواة أقدم من ذلك الإصدار، فعندئذ فقط تحتاج طرازات Realtek إلى تعريفات DKMS المجتمعية (راجع الفقرة الأخيرة من 7.3).

### 7.2 المسار A: طرازات شرائح MediaTek (AWUS036ACM / ACHM / AXML / AXM) — تعمل فور التوصيل

**الخطوة 1: توصيل البطاقة**

استخدم محول USB-C إلى USB-A (يمكن توصيل AXML مباشرة بمنفذ USB-C)، ثم أدخل بطاقة ALFA في منفذ USB في DGX Spark.

**الخطوة 2: تحقق من اكتشاف البطاقة**

```bash
lsusb
# مثال على الناتج المتوقع (AWUS036ACM / MT7612U):
# Bus 001 Device 003: ID 0e8d:7612 MediaTek Inc. MT7612U 802.11a/b/g/n/ac Wireless Adapter
```

**الخطوة 3: تحقق من إنشاء واجهة الشبكة تلقائيًا**

```bash
ip link show
# المتوقع ظهور واجهة يبدأ اسمها بـ wlx (مسماة حسب عنوان MAC، ويُحمَّل التعريف المدمج في النواة تلقائيًا)
```

**الخطوة 4: البحث عن شبكات WiFi** (يُستخدم wlan0 أدناه للتوضيح، استبدله باسم الواجهة الذي يظهر في `ip link show`)

```bash
sudo iw dev wlan0 scan | grep -E "SSID|signal"
```

**الخطوة 5: الاتصال بشبكة WiFi (عبر NetworkManager)**

```bash
nmcli dev wifi list
nmcli dev wifi connect "اسم شبكة WiFi" password "كلمة مرور WiFi"
```

**الخطوة 6: (اختياري) تفعيل وضع المراقبة**

```bash
sudo apt install -y aircrack-ng
sudo ip link set wlan0 down
sudo iw dev wlan0 set type monitor
sudo ip link set wlan0 up
sudo iw dev wlan0 info
```

### 7.3 المسار B: طرازات Realtek Wi-Fi 5 (AWUS036ACH / ACS / EACS) — دون تثبيت على kernel 6.13+ (EACS: 6.2+)

**الخطوة 1: وصّل البطاقة وتحقق من تحميل التعريف تلقائيًا**

```bash
uname -r          # يحتاج ACH / ACS إلى 6.13 فما فوق، وEACS إلى 6.2 فما فوق
lsusb
lsmod | grep rtw88
ip link show
```

الوحدات (modules) التي تُحمَّل تلقائيًا لكل طراز: ACH: `rtw88_8812au`، ACS: `rtw88_8821au`، EACS: `rtw88_8821cu` (يتضمن EACS أيضًا بلوتوث، وقد ثبت عمله فعليًا).

**الخطوة 2: طريقة الاتصال مماثلة للخطوة 5 في 7.2 (عبر nmcli)**

**الخطوة 3: (اختياري) وضع المراقبة والحقن**

⚠️ لا تُجرِ اختبارات المراقبة والحقن إلا على شبكات تملكها أو حصلت على إذن صريح باختبارها.

```bash
sudo apt install -y aircrack-ng
IF=wlx00c0cafe0000   # استبدله باسم الواجهة الذي يظهر في ip link
sudo ip link set $IF down
sudo iw dev $IF set type monitor
sudo ip link set $IF up
sudo aireplay-ng --test $IF
```

- لا تشغّل `airmon-ng check kill`: فهو يوقف NetworkManager ويقطع اتصال الجهاز بالشبكة الخارجية.
- على AWUS036AXM / AXML يفشل الأمر `aireplay-ng --test` على النواة القياسية 6.17 (Found 0 APs)، فلا يمكن تنفيذ deauth أو التقاط handshake.
- يظهر الخطأ `failed to arm` مع hcxdumptool 8.x على البطاقات التسع كلها عدا EACS على 2.4 GHz (التعريفات لا تدعم active monitor)، لذا استخدم airodump-ng + aireplay-ng بدلًا منه.

**خطوات مطلوبة فقط على الأنوية القديمة (ACH / ACS أقدم من 6.13، وEACS أقدم من 6.2)**: بعد تثبيت `build-essential git bc dkms`، جمّع التعريف المجتمعي، مثل morrownr/8812au-20210820 لشريحة RTL8812AU (مع التأكد من `CONFIG_PLATFORM_ARM64 = y` في Makefile). أما إذا كان الإصدار كافيًا فاستخدم التعريف المدمج مباشرة.

### 7.4 المسار C: طرازات Wi-Fi 6 (AWUS036AX / AXER، RTL8832BU) — دون تثبيت على kernel 6.17+

```bash
lsusb                      # المتوقع ظهور 0bda:b832
lsmod | grep rtw89_8852bu
ip link show
```

نتيجة الاختبار على GX10: يُحمَّل التعريف المدمج `rtw89_8852bu` تلقائيًا، والاستقبال في وضع monitor قوي، والحقن يعمل (2.4GHz: AX بنسبة 96%، وAXER بنسبة 73%)، ويدعم AP بعرض 80MHz. لم يدخل rtw89_8852bu الفرع الرئيسي للنواة إلا في الإصدار 6.17، لذا تحتاج الأنظمة ذات النواة 6.16 فما دون إلى تعريف DKMS المجتمعي (morrownr/rtl8852bu-20250826).

## 8. الأخطاء الشائعة وطرق حلها

| العَرَض | السبب المحتمل | الحل |
|---|---|---|
| لا تظهر بطاقة ALFA في lsusb | محول USB-C رديء / اتصال ضعيف | استبدل محول USB-C إلى USB-A؛ تأكد من أن المحول يدعم نقل البيانات (وليس الشحن فقط)؛ جرّب منفذ USB-C آخر |
| لا توجد واجهة wlan بعد توصيل بطاقة MediaTek | لم تُحمَّل وحدة النواة تلقائيًا / البرنامج الثابت (firmware) مفقود | حمّل الوحدة يدويًا: `sudo modprobe mt76x2u`؛ افحص `dmesg \| grep mt76`؛ ثبّت البرنامج الثابت: `sudo apt install linux-firmware` |
| لا تظهر واجهة wlan بعد توصيل بطاقة Realtek | النواة أقدم من أدنى إصدار للبطاقة (EACS: 6.2، ACH / ACS: 6.13، AX / AXER: 6.17) ولا تتضمن التعريف المناسب | تحقق من الإصدار بـ `uname -r`؛ حدّث النواة، أو ثبّت تعريف DKMS المجتمعي على النواة القديمة |
| بعد تثبيت تعريف DKMS على نواة قديمة يُظهر modprobe الرسالة Operation not permitted | Secure Boot / توقيع الوحدات | يجب توقيع الوحدة أو تعطيل Secure Boot (لن تواجه هذا عند استخدام التعريفات المدمجة) |
| لا تُلتقط أي إشارة بعد التبديل المتكرر بين monitor وAP | توقف الاستقبال (RX stall) | افصل البطاقة وأعد توصيلها ليُعاد تعداد USB |
| لا تظهر واجهة wlx بعد إعادة توصيل EACS / AXML | تعلّق التعرّف (probe) على الجهاز المركّب بلوتوث + Wi-Fi | أعد التوصيل في منفذ USB آخر |
| اتصال WiFi غير مستقر / سرعة منخفضة | محول USB-C يدعم USB 2.0 فقط | استبدله بمحول يدعم USB 3.2 Gen 2×2؛ تأكد من أن المحول يحمل علامة «Data» وليس «Charge Only» |
| تعارض بين Wi-Fi 7 المدمج وبطاقة ALFA الخارجية | تعارض التوجيه بين واجهتين لاسلكيتين | عطّل WiFi المدمج: `sudo nmcli radio wifi off` أو من BIOS/UEFI؛ أو اضبط أولوية التوجيه |
| تعذّر استخدام 6GHz (Wi-Fi 6E) | قيود المنطقة التنظيمية (Regulatory Domain) | اضبط المنطقة التنظيمية: `sudo iw reg set US` (نطاق 6GHz مفتوح في الولايات المتحدة)؛ ثبت عمليًا أن AXML يعمل على 6GHz، أما AXM فلم يُختبر |
| فشل تشغيل وضع AP | تعارض NetworkManager مع hostapd | راجع دليل ALFA Soft AP من Yopitek؛ أوقف إدارة NetworkManager لتلك الواجهة ثم اضبط hostapd يدويًا |
| اختفاء البطاقة بعد الاستئناف من السكون | الإيقاف التلقائي لـ USB (autosuspend) | عطّل الإيقاف التلقائي لـ USB: `echo 'options usbcore autosuspend=-1' \| sudo tee /etc/modprobe.d/usb.conf` |

## 9. القيود المعروفة

- **الحاجة إلى محول USB Type-C**: باستثناء AXML، تحتاج جميع بطاقات ALFA إلى محول USB-C إلى USB-A، وتؤثر جودة المحول على الأداء والاستقرار.
- **فشل الحقن في طرازات MT7921**: يفشل حقن الحزم في AWUS036AXM / AXML على النواة القياسية 6.17، فلا يمكن تنفيذ deauth أو التقاط handshake؛ بينما تعمل أوضاع monitor وAP وWPA3. السبب الرئيسي تراجع (regression) في mac80211 chanctx منذ النواة 6.16، وما زالت التعريفات المعدّلة من المجتمع محدودة السرعة.
- **نطاق الاختبار**: أُجري الاختبار على ASUS GX10 (النواة 6.17.0-1014-nvidia) فقط؛ ولم يُختبر DGX Spark بعينه، والسلوك المتوقع مطابق.
- **تعذّر استخدام hcxdumptool**: يظهر الخطأ `failed to arm` على كل البطاقات عدا EACS على 2.4 GHz، لذا استخدم airodump-ng + aireplay-ng.
- **احتمال تعارض Wi-Fi 7 المدمج**: يحتوي DGX Spark على Wi-Fi 7 مدمج، وقد يحدث تعارض في التوجيه أو الموارد عند استخدام WiFi المدمج والخارجي معًا.
- **وضع AP يتطلب إعدادًا يدويًا**: DGX OS مهيأ افتراضيًا كبيئة تطوير، ويتطلب وضع نقطة الاتصال AP تثبيت hostapd / dnsmasq وإعدادهما يدويًا.
- **قيود تنظيمية على 6GHz**: يعتمد توفر نطاق 6GHz لـ Wi-Fi 6E على إعداد المنطقة التنظيمية، ويجب التحقق من أحدث اللوائح بشأن فتح نطاق 6GHz في تايوان.
- **الأنوية القديمة**: لا تحتاج طرازات Realtek إلى تعريفات DKMS المجتمعية (morrownr) إلا على الأنظمة ذات النواة الأقدم من أدنى إصدار للبطاقة (EACS: 6.2، ACH / ACS: 6.13، AX / AXER: 6.17)، وفي هذه الحالة يجب إعادة تجميعها بعد كل تحديث للنواة.
- **فروق قدرات اختبار الاختراق**: في اختبارات GX10 كانت أعلى نسب نجاح الحقن لطرازات Realtek rtw88 (EACS وACH بنسبة 100% على النطاقين)؛ وطرازات MediaTek mt76 (ACM / ACHM) تعمل؛ أما MT7921 (AXM / AXML) فتفشل.
- **وظيفة البلوتوث**: ثبت عمليًا على GX10 عمل البلوتوث في AWUS036AXML وAWUS036EACS؛ ولم يُتحقق من بلوتوث AWUS036AXM بشكل منفصل (يحتوي DGX Spark على BT 5.4 مدمج).
- **RTL8832BU (AWUS036AX / AXER)**: أوصى مطوّر التعريفات morrownr علنًا بتجنب التعريفات الخارجية (out-of-tree) لسلسلة rtl8852/32au (المصدر في الفصل العاشر). أما اختبار GX10 هذا فاستخدم التعريف المدمج في النواة `rtw89_8852bu`، وعملت فيه أوضاع monitor والحقن وAP وWPA3؛ وتنطبق هذه النتيجة فقط على التعريف المدمج في النواة 6.17 فما فوق.
- **RTL8812AU (AWUS036ACH)**: دُمج التعريف المتوافق مع معيار mac80211 داخل النواة `rtw88_8812au` في الفرع الرئيسي في النواة 6.13، وأصبح ناضجًا منذ النواة 6.14 (حسب إعلان morrownr). وفي اختبار GX10 على النواة 6.17 عمل فور التوصيل وبلغت نسبة الحقن 100% على النطاقين. قبل الرد على العميل، يمكن أن يطلب الدعم الفني منه ناتج `uname -r` للتأكد من أن النواة 6.13 فما فوق.

شروط النقض: إذا تغيّر إصدار النواة أو تعريف وحدة تحكم USB بعد تحديث DGX OS بما يغيّر السلوك، أو إذا ظهرت على جهاز DGX Spark فعلي نتائج تختلف عن GX10، فيجب مراجعة مصفوفة التوافق في الفصل السادس؛ وإذا أصلحت النواة مستقبلًا مشكلة الحقن في mt7921u، فيمكن رفع تقييم AWUS036AXM / AXML من «للاتصال / AP فقط».
