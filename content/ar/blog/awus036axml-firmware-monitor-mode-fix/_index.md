**ALFA AWUS036AXML** هو محول WiFi 6E الرائد من ALFA Network، مبني على شريحة MediaTek MT7921AUN ويدعم ثلاثة نطاقات (2.4 / 5 / 6 GHz). إنه أحد المحولات USB القليلة القادرة على المراقبة السلبية في نطاق 6 GHz في عام 2026. يؤدي أداءً ممتازاً في حالات الاستخدام المتعددة كمسح الموقع والتقاط الحزم وجمع PMKID.

{{< tldr >}}
تعريف mt7921u لـ AWUS036AXML يُسبب تعثر البرنامج الثابت عند الحقن النشط للحزم. يشرح هذا المقال السبب الجذري وخطوات التشخيص وحلول التحديث والترقية والتبديل إلى الالتقاط السلبي بـ hcxdumptool.
{{< /tldr >}}


لكن هناك مشكلة معروفة تفاجئ المستخدمين: **أوامر وضع المراقبة النشط تُسبب انهيار الثابتة**. تشغيل أدوات مثل `aireplay-ng` أو `mdk4` يجعل واجهة `wlan0mon` تختفي تماماً، مما يضطرك لفصل المحول وإعادة توصيله للتعافي. هذه ليست عطلاً في الجهاز، بل قيود في دليل Linux `mt7921u` والثابتة الحالية.

يشرح هذا الدليل السبب الجذري ويوفر خطوات التشخيص والإصلاح والحلول البديلة.

---

## المشكلة: انهيار وضع المراقبة النشط

### الأعراض

بعد تفعيل وضع المراقبة وتشغيل أمر نشط مثل `aireplay-ng --test wlan0mon` أو أي عملية إلغاء مصادقة أو حقن، تختفي واجهة `wlan0mon` من مخرجات `ip link` و `iwconfig`. يصبح المحول غير مستجيب ولا يمكن استعادته دون فصله فيزيائياً وإعادة توصيله. في بعض الأحيان يُظهر `dmesg` خطأ ثابتة أو حدث إعادة تشغيل فور الانهيار.

العمليات السلبية (المسح بـ `airodump-ng`، التقاط الإطارات الخام) تعمل بشكل صحيح قبل وبعد الانهيار، طالما لم يُشغَّل أي حقن نشط.

### السبب الجذري

تستخدم **شريحة MT7921AUN** بنية MAC مستندة إلى الثابتة. يعتمد دليل `mt7921u` في نواة Linux على الثابتة المضمنة في الشريحة للتعامل مع عمليات الطبقة الدنيا، بما فيها حقن الإطارات في وضع المراقبة. لا تُنفذ الثابتة والدليل الحاليان بالكامل مسار الأوامر المطلوب للحقن النشط في وضع المراقبة على Linux.

في المقابل، **المراقبة السلبية** (استشعار الإطارات الموجودة في الهواء) لا تتطلب من الثابتة إرسال أي شيء ولا تتسبب في الانهيار. المشكلة محصورة في عمليات مسار الإرسال: إطارات إلغاء المصادقة، طلبات المسح، فيضانات الارتباط، والعمليات النشطة المماثلة.

{{< alert "triangle-exclamation" >}}
**خطأ انهيار ثابتة معروف.** هذه مشكلة مؤكدة في دليل Linux `mt7921u` حتى مطلع 2026، وتؤثر على AWUS036AXML ومحولات USB الأخرى المبنية على MT7921AUN. قد يُعالج في تحديثات النواة أو الثابتة المستقبلية — راجع [دليل تثبيت الدليل](/ar/blog/install-alfa-driver-kali-ubuntu/) للحصول على آخر المستجدات.
{{< /alert >}}

## التشخيص: هل هذه مشكلتك؟

```bash
# التحقق من التعرف على المحول
lsusb | grep -i mediatek

# التحقق من تحميل الدليل
lsmod | grep mt7921u

# التحقق من إصدار النواة (يجب أن يكون >= 5.18)
uname -r

# تشغيل وضع المراقبة
sudo airmon-ng start wlan0

# اختبار الالتقاط السلبي (يجب أن يعمل)
sudo airodump-ng wlan0mon

# اختبار النشط (قد يتسبب في الانهيار)
sudo aireplay-ng --test wlan0mon
```

إذا اختفى المحول من `ip link` بعد `aireplay-ng --test`، فقد أكدت خطأ انهيار الثابتة.

التحقق الإضافي عبر سجلات النواة:

```bash
sudo dmesg | grep -E "mt7921|firmware|reset" | tail -20
```

ابحث عن رسائل مثل `mt7921u: firmware crash` أو `mt7921u: chip reset` أو `usb disconnect` تظهر مباشرة بعد استدعاء aireplay-ng.

{{< alert "circle-info" >}}
**الالتقاط السلبي غير متأثر.** إذا كان `airodump-ng` يعمل لكن `aireplay-ng` يتسبب في الانهيار، فهذا هو خطأ MT7921AUN المعروف تماماً. تابع الإصلاحات أدناه.
{{< /alert >}}

## الإصلاح الأول: تحديث حزمة الثابتة

الخطوة الأولى الأكثر تأثيراً هي التأكد من امتلاكك أحدث ملفات ثابتة MT7921. إصدارات الثابتة القديمة أكثر عرضة للانهيار؛ الثابتة المحدثة تحسن الاستقرار لبعض العمليات النشطة.

```bash
sudo apt update
sudo apt install firmware-misc-nonfree

# أو تثبيت أحدث ثابتة mt7921 يدوياً من مستودع linux-firmware
sudo apt install git
git clone https://git.kernel.org/pub/scm/linux/kernel/git/firmware/linux-firmware.git
sudo cp linux-firmware/mediatek/mt7921* /lib/firmware/mediatek/
sudo modprobe -r mt7921u
sudo modprobe mt7921u
```

بعد تحديث ملفات الثابتة، أعد تحميل الدليل وأعد اختبار الوضع النشط:

```bash
sudo modprobe -r mt7921u && sudo modprobe mt7921u
sudo airmon-ng start wlan0
sudo aireplay-ng --test wlan0mon
```

## الإصلاح الثاني: استخدام أحدث نواة

دليل `mt7921u` يُصان بنشاط في نواة Linux الرئيسية. منذ 5.18، أُدرجت تصحيحات الاستقرار، معالجة أوامر الثابتة، وتحسينات وضع المراقبة في تحديثات النواة. تشغيل نواة أحدث هو أحد أكثر الطرق موثوقية لتحسين السلوك.

تحقق من إصدار النواة الحالي:

```bash
uname -r
```

التحديث إلى أحدث نواة متاحة على Kali Linux:

```bash
sudo apt update && sudo apt full-upgrade -y
sudo reboot
```

الهدف: **النواة 6.1 LTS أو أحدث** للحصول على أكثر تصحيحات دليل `mt7921u` اكتمالاً. النواة 6.6 وما بعدها تتضمن تحسينات إضافية لمكدس دليل MediaTek USB أظهرت نتائج إيجابية.

{{< alert "circle-info" >}}
**تحسين النواة 6.6+.** عدة تقارير من المجتمع تشير إلى أن النواة 6.6 مع الثابتة المحدثة تقلل (لكن لا تزيل دائماً) انهيارات الوضع النشط على MT7921AUN. بعد الترقية، أعد تشغيل تسلسل التشخيص لتقييم مجموعتك المحددة.
{{< /alert >}}

## الحل البديل: استخدام hcxdumptool (التقاط PMKID السلبي)

إذا لم تُعالج الإصلاحات على مستوى الثابتة الانهيار بالكامل، توفر `hcxdumptool` سير عمل بديلاً فعالاً لا يتطلب أي حقن إطارات.

تعمل `hcxdumptool` في **الوضع السلبي** — تلتقط قيم PMKID مباشرة من إطارات البيكون والمسح التي تبثها نقاط الوصول. لا إرسال لإطارات إلغاء المصادقة، لا حقن، لا انهيار ثابتة. يتعامل AWUS036AXML مع هذا سير العمل بشكل مثالي.

```bash
sudo apt install hcxdumptool hcxtools

# التقاط سلبي — بدون إلغاء مصادقة، بدون انهيار ثابتة
sudo hcxdumptool -i wlan0mon -o capture.pcapng --enable_status=1

# التحويل إلى صيغة hashcat
hcxpcapngtool -o hash.hc22000 capture.pcapng

# الاختراق باستخدام hashcat
hashcat -m 22000 hash.hc22000 /usr/share/wordlists/rockyou.txt
```

يلتقط هذا سير العمل قيم PMKID من إطارات البيكون دون إرسال أي شيء — سلبي تماماً من منظور الوسط اللاسلكي.

{{< alert "circle-info" >}}
**التقاط PMKID يعمل على جميع شبكات WPA2/WPA3 الحديثة.** تبث نقاط الوصول قيم PMKID في إطارات البيكون بغض النظر عن ارتباط أي عميل. تحتاج فقط إلى التواجد في نطاق نقطة الوصول — لا يلزم وجود عميل. مثالي للسيناريوهات التي لا يكون فيها إلغاء المصادقة خياراً.
{{< /alert >}}

## الحل البديل: استخدام AWUS036ACH للحقن النشط

للمهام التي تتطلب فعلاً حقن إطارات نشطاً (التقاط مصافحة WPA القسري، تعداد WPS، وما شابه)، **AWUS036ACH** (شريحة RTL8812AU) هو الحل الراسخ مع دعم دليل ناضج ومُختبر جيداً على Kali Linux.

الإعداد المهني الموصى به بمحولين:

- **AWUS036AXML** ← المسح السلبي والالتقاط على نطاق 5 GHz / 6 GHz
- **AWUS036ACH** ← الحقن النشط على نطاق 2.4 GHz / 5 GHz

هذا الجمع يمنحك تغطية كاملة عبر جميع النطاقات مع تولي RTL8812AU للحقن (دعم وضعه النشط على Linux مستقر منذ سنوات)، بينما يتولى AWUS036AXML اكتشاف 6 GHz والالتقاط السلبي عالي الجودة.

راجع [مراجعة AWUS036AXML](/ar/blog/awus036axml-wifi-6e-review/) و[دليل حقن الحزم](/ar/blog/packet-injection-guide/) لتفاصيل الإعداد لكلا المحولين.

## متى يعمل الوضع النشط

تجدر الإشارة إلى أن الوضع النشط لا يفشل في كل الحالات. عدة شروط أبلغ عنها أعضاء المجتمع تُنتج سلوكاً مستقراً أو قريباً من المستقر على MT7921AUN:

- **النواة 6.6 أو أحدث** مع firmware-misc-nonfree 20240610 أو أحدث
- تجنب `aireplay-ng --deauth` في وضع الانفجار (فيضانات إلغاء المصادقة ذات معدل الحزم العالي أكثر عرضة للانهيار من عمليات الإطار الواحد)
- استخدام `--deauth 1` أو `--deauth 3` بدلاً من تدفقات إلغاء المصادقة المستمرة
- ضمان توصيل المحول بمنفذ USB 3.0 (قيود عرض نطاق USB 2.0 تضيف ضغطاً على مسار أوامر الثابتة)
- العمل على 2.4 GHz بدلاً من 5 GHz للحقن (يبدو النطاق الأدنى تردداً أكثر استقراراً في بعض إصدارات الدليل)

{{< alert "triangle-exclamation" >}}
**اختبر قبل عمليات الاختراق الفعلية.** حتى عندما يبدو الوضع النشط يعمل، قد تنهار ثابتة MT7921AUN في منتصف العملية تحت الحمل. احتفظ دائماً بخطة تعافٍ (محول احتياطي أو سير عمل سلبي فقط) عند استخدام AWUS036AXML للعمليات النشطة.
{{< /alert >}}

## التحقق من تحديث الثابتة

```bash
# التحقق من تاريخ ملف الثابتة الحالي
ls -la /lib/firmware/mediatek/mt7921*

# التحقق من إصدار الدليل
modinfo mt7921u | grep -E "version|filename"

# التحقق من رسائل النواة لتحميل الثابتة
sudo dmesg | grep mt7921
```

عند تحميل الثابتة بنجاح، يجب أن يُظهر مخرج `dmesg` شيئاً مثل:

```
mt7921u 1-2.3:1.0: firmware init done
mt7921u 1-2.3:1.0: HW/SW Version: ...
```

## الملخص: أفضل حالات استخدام AWUS036AXML

- ✅ **المسح السلبي لـ WiFi 6E والتقاط PCAP** — يعمل بشكل مثالي
- ✅ **التقاط PMKID بـ hcxdumptool** — بدون حقن، بدون انهيار ثابتة
- ✅ **اكتشاف شبكات 6 GHz** — المسح السلبي بـ airodump-ng على نطاق 6 GHz
- ✅ **مسح الموقع وتحليل التداخل لـ WiFi 6E** — مراقبة سلبية ثلاثية النطاق
- ✅ **التقاط مصافحة WPA2 الأساسية** — التقاط سلبي من حركة المرور الموجودة
- ⚠️ **حقن الإطارات النشط** — استخدم AWUS036ACH حتى تنضج ثابتة MT7921AUN
- ⚠️ **فيضانات إلغاء المصادقة** — خطر الانهيار؛ اختبر بعناية على النواة 6.6+
- ⭐ **أفضل سير عمل: احمل كلاً من AWUS036AXML + AWUS036ACH** لتغطية كاملة لجميع النطاقات والعمليات
