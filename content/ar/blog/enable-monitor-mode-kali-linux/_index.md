## ما هو وضع المراقبة ولماذا يهم في اختبار الاختراق؟

وضع المراقبة هو وضع تشغيل خاص لبطاقات الشبكة اللاسلكية (NICs) يسمح للمحول بالتقاط **جميع** إطارات 802.11 في الهواء — لا تلك الموجهة إلى جهازك فحسب. في الوضع الاعتيادي "الإداري"، يستقبل محولك الحزم المُوجَّهة إلى عنوان MAC الخاص به ويتجاهل كل شيء آخر. يرفع وضع المراقبة هذا المرشح كلياً.

بالنسبة لمختبري الاختراق اللاسلكي، وضع المراقبة هو الأساس. بدونه، لا تستطيع أدوات مثل **airodump-ng** أو **Wireshark** (في وضع الالتقاط اللاسلكي) أو **Kismet** اعتراض حركة الشبكة سلبياً. يُمكّن وضع المراقبة من:

- **الاستطلاع السلبي** — مسح جميع نقاط الوصول والعملاء القريبين دون إرسال أي إطارات.
- **التقاط المصافحات** — الاستماع لمصافحات WPA/WPA2 رباعية الاتجاهات أثناء مصادقة العميل.
- **هجمات إلغاء المصادقة** — إرسال إطارات إدارة 802.11 (يتطلب حقن الحزم إضافةً لوضع المراقبة).
- **الكشف عن نقاط الوصول المارقة** — تحديد نقاط الوصول غير المصرح بها على الشبكة.
- **تحليل البروتوكول** — فحص معمّق لإطارات إدارة 802.11 ومعالجتها وإطارات بياناتها.

لا يدعم كل محول لاسلكي وضع المراقبة. تحدد **الشريحة المعالجة** و**برنامج التشغيل** المُدرَج في النواة هذه القدرة. المحولات الاستهلاكية المباعة للاستخدام المنزلي نادراً ما تكون متوافقة. المحولات المصممة خصيصاً للبحث الأمني — كمجموعة ALFA Network — مبنية بشرائح معالج وبرامج تشغيل تكشف وضع المراقبة بنظافة.

## المتطلبات الأساسية

قبل تفعيل وضع المراقبة، تأكد مما يلي:

1. تشغّل **Kali Linux** (يُوصى بـ 2024.1 أو أحدث) مع نواة متوافقة.
2. محولك اللاسلكي موصول (محولات USB) أو مثبت (PCIe/mini-PCIe).
3. لديك صلاحيات **root أو sudo**.
4. حددت اسم واجهتك: شغّل `ip link` أو `iwconfig` ولاحظ الواجهة اللاسلكية (عادةً `wlan0` أو `wlan1` أو `wlx...`).

```bash
ip link show
```

ابحث عن إدخال يبدأ بـ `wlan` أو له اسم طويل مبني على MAC يبدأ بـ `wlx`.

## الطريقة 1: تفعيل وضع المراقبة بـ airmon-ng

`airmon-ng` هو جزء من مجموعة **aircrack-ng** وهو الأداة الأكثر استخداماً لتبديل وضع المراقبة على Kali Linux. يتعامل تلقائياً مع الحالات الحدية الكثيرة، بما في ذلك إيقاف العمليات التي تتعارض مع تبديل الوضع.

### الخطوة 1 — إيقاف العمليات المتعارضة

يتنافس NetworkManager وwpa_supplicant وdhclient مع وضع المراقبة. أوقفها أولاً:

```bash
sudo airmon-ng check kill
```

الناتج المتوقع:

```
Killing these processes:
  PID Name
  812 wpa_supplicant
  934 NetworkManager
```

> **ملاحظة:** سيُقطع هذا اتصالات الشبكة الحالية. إذا احتجت الإنترنت أثناء الاختبار، استخدم اتصالاً سلكياً أو محول لاسلكي ثانٍ في الوضع الاعتيادي.

### الخطوة 2 — تشغيل وضع المراقبة

```bash
sudo airmon-ng start wlan0
```

الناتج المتوقع:

```
PHY     Interface   Driver      Chipset
phy0    wlan0       rtl8812au   Realtek Semiconductor Corp. RTL8812AU 802.11a/b/g/n/ac

(mac80211 monitor mode vif enabled for [phy0]wlan0 on [phy0]wlan0mon)
(mac80211 station mode vif disabled for [phy0]wlan0)
```

المحول الآن في وضع المراقبة وأُنشئت واجهة افتراضية جديدة — عادةً **wlan0mon**.

### الخطوة 3 — تحديد قناة (اختياري لكن موصى به)

افتراضياً، يتنقل المحول عبر القنوات. قفّله على قناة محددة للالتقاط الموجّه:

```bash
sudo iwconfig wlan0mon channel 6
```

## الطريقة 2: تفعيل وضع المراقبة بـ iw

أمر `iw` هو أداة التهيئة اللاسلكية منخفضة المستوى الحديثة. تمنحك هذه الطريقة تحكماً مباشراً أكثر وتفيد حين لا يكون `airmon-ng` متاحاً أو يتصرف بصورة غير صحيحة.

```bash
# أوقف الواجهة
sudo ip link set wlan0 down

# ضبط وضع المراقبة
sudo iw dev wlan0 set type monitor

# أعد تشغيل الواجهة
sudo ip link set wlan0 up
```

الأوامر الثلاثة مسلسلة:

```bash
sudo ip link set wlan0 down && sudo iw dev wlan0 set type monitor && sudo ip link set wlan0 up
```

يُعدّل هذا واجهة `wlan0` الحالية مباشرةً بدلاً من إنشاء واجهة `wlan0mon` جديدة. تحقق من تطبيق التغيير:

```bash
iw dev wlan0 info
```

ابحث عن `type monitor` في الناتج.

## التحقق من وضع المراقبة

### باستخدام iwconfig

```bash
iwconfig
```

ستُظهر واجهة وضع المراقبة:

```
wlan0mon  IEEE 802.11  Mode:Monitor  Frequency:2.457 GHz  Tx-Power=20 dBm
          Retry short limit:7   RTS thr:off   Fragment thr:off
          Power Management:off
```

الحقل الأساسي هو **Mode:Monitor**.

### باستخدام iw dev

```bash
iw dev
```

ابحث عن `type monitor` تحت إدخال واجهتك. إذا ظهر `type managed`، لم يُطبَّق وضع المراقبة بنجاح.

## الاختبار بـ airodump-ng

حين يكون وضع المراقبة نشطاً، اختبره شاملاً بـ `airodump-ng`:

```bash
sudo airodump-ng wlan0mon
```

يجب أن ترى فوراً قائمة حية بنقاط الوصول القريبة تتدفق على الشاشة، تُظهر BSSID والقناة وقوة الإشارة (PWR) ونوع التشفير وESSID. إذا كانت الشاشة فارغة أو تُظهر خطأ، راجع قسم استكشاف الأخطاء أدناه.

لمسح نطاق 5 GHz فقط:

```bash
sudo airodump-ng --band a wlan0mon
```

لالتقاط شبكة محددة وحفظ الناتج للتحليل لاحقاً:

```bash
sudo airodump-ng -c 6 --bssid AA:BB:CC:DD:EE:FF -w capture wlan0mon
```

## استكشاف الأخطاء وإصلاحها

### "Cannot enable monitor mode" أو تختفي الواجهة

يحدث هذا عادةً حين يستعيد NetworkManager الواجهة. شغّل `airmon-ng check kill` مرة أخرى ثم أعد المحاولة. إذا استمرت المشكلة، أوقف NetworkManager يدوياً:

```bash
sudo systemctl stop NetworkManager
sudo systemctl stop wpa_supplicant
```

### وضع المراقبة يعود إلى الوضع الاعتيادي

تعيد بعض برامج التشغيل التشغيل الوضع الاعتيادي تلقائياً بعد ثوانٍ. هذا يعني عادةً أن wpa_supplicant أُعيد تشغيله في الخلفية. تحقق من العمليات الجارية:

```bash
ps aux | grep -E "wpa_supplicant|NetworkManager"
```

أوقف أي عمليات موجودة بمعرف العملية (PID)، ثم أعد تفعيل وضع المراقبة.

### اسم الواجهة مختلف بعد airmon-ng

على بعض الأنظمة، قد تُسمّى الواجهة الجديدة `wlan0mon` أو `mon0` أو شيئاً آخر كلياً. تحقق دائماً بـ `iwconfig` أو `iw dev` بعد تشغيل `airmon-ng start` لتأكيد الاسم الفعلي للواجهة قبل استخدامها مع airodump-ng.

### خطأ "Fixed channel wlan0mon: -1" في airodump-ng

هذا يعني أن airodump-ng لا يستطيع تغيير القنوات. جرّب:

```bash
sudo iwconfig wlan0mon channel 1
```

إذا فشل ذلك، أوقف أي عمليات wpa_supplicant متبقية وأعد المحاولة.

### مشكلات برنامج تشغيل RTL8812AU على النوى الأحدث

يفتقر أحياناً برنامج تشغيل RTL8812AU المدمج في النوى الحديثة جداً إلى دعم كامل لوضع المراقبة. ثبّت برنامج التشغيل المجتمعي:

```bash
sudo apt install dkms git
git clone https://github.com/aircrack-ng/rtl8812au.git
cd rtl8812au
sudo make dkms_install
```

أعد التشغيل بعد التثبيت.

## تعطيل وضع المراقبة عند الانتهاء

أعد دائماً محولك إلى الوضع الاعتيادي حين تنتهي من الاختبار. البقاء في وضع المراقبة يمنع الاتصال الطبيعي بالشبكة.

### باستخدام airmon-ng:

```bash
sudo airmon-ng stop wlan0mon
sudo systemctl start NetworkManager
```

### باستخدام iw:

```bash
sudo ip link set wlan0 down
sudo iw dev wlan0 set type managed
sudo ip link set wlan0 up
sudo systemctl start NetworkManager
```

تحقق من عودة الواجهة إلى الوضع الاعتيادي بـ `iwconfig` وأعد الاتصال بشبكتك.
