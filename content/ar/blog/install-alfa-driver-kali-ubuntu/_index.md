كثيراً ما يعتمد تشغيل محول USB WiFi على Linux على شيء واحد: برنامج التشغيل. على عكس Windows حيث يبث المصنّعون برامج التشغيل في مثبّتات قابلة للتنفيذ، يعتمد Linux على وحدات النواة — كود مُصرَّف تحمّله نظام التشغيل للتواصل مع الأجهزة. فهم هذا النموذج يجعل استكشاف الأخطاء واضحاً وعملية تثبيت برامج التشغيل متوقعة.

{{< tldr >}}
يعتمد تثبيت تعريف محول ALFA على الشريحة: MT7612U و MT7921AUN مدمجان في النواة ويعملان فور التوصيل، RTL8812AU يحتاج تثبيتاً من GitHub aircrack-ng مع DKMS لضمان الاستمرارية بعد تحديثات النواة.
{{< /tldr >}}


يتناول هذا الدليل تثبيت برامج التشغيل لكل شريحة معالج رئيسية في محولات ALFA Network USB WiFi على كلٍّ من Kali Linux 2024/2025 وUbuntu 24.04 LTS.

## كيف تعمل برامج تشغيل USB WiFi على Linux؟

### وحدات النواة

برنامج تشغيل WiFi على Linux هو **وحدة نواة** — ملف `.ko` يُحمَّل في النواة الجارية عند الإقلاع أو عند الطلب. حين تصل بجهاز USB، تقرأ النواة معرف مورده ومعرف منتجه، تبحث عن وحدة مطابقة في قاعدة بياناتها، وتحملها تلقائياً.

بالنسبة للشرائح الشائعة كـ MediaTek MT7612U، يحدث هذا بشفافية تامة: أدخل المحول، تُحمَّل وحدة، تظهر واجهة. بالنسبة للشرائح الأحدث أو الأقل شيوعاً، لا توجد وحدة في الشجرة الرئيسية وعليك تصريف واحدة من المصدر.

### برامج التشغيل خارج الشجرة

حين لا يُدرج برنامج التشغيل في نواة Linux الرئيسية (يُسمى برنامج تشغيل "خارج الشجرة" أو "خارجي")، يجب عليك:

1. تنزيل كود برنامج التشغيل المصدري
2. تصريفه في مواجهة ترويسات نواتك الجارية
3. تثبيت ملف `.ko` الناتج في مجلد وحدة النواة
4. تحميله بـ `modprobe`

تستلزم خطوة التصريف أن تكون ترويسات نواتك مثبتة وتطابق نواتك الجارية تماماً. هذا هو المصدر الأكثر شيوعاً لإخفاقات تثبيت برامج التشغيل.

### DKMS: نظام دعم الوحدات الديناميكية

تصريف عادي بـ `make install` يُنشئ برنامج التشغيل لنواتك الحالية فحسب. حين تحدّث Kali أو Ubuntu النواة — وهذا يحدث بانتظام — لا تعمل برامج التشغيل القديمة بعد الآن حتى تُعيد التصريف.

يحل **DKMS** هذا بتسجيل كود برنامج التشغيل المصدري مع شيطان نظام يُعيد تصريف الوحدات المسجلة تلقائياً كلما ثُبّتت نواة جديدة. هو النهج الموصى به لأي محول يتطلب برنامج تشغيل خارج الشجرة.

## التعرف على شريحتك المعالجة

برنامج التشغيل الذي تحتاجه يعتمد كلياً على شريحتك المعالجة، لا على الاسم التسويقي للمحول. محولان بالاسم ذاته لكن بإصدارات مختلفة قد يستخدمان شرائح مختلفة.

### جدول مطابقة موديلات ALFA والشرائح المعالجة

| موديل ALFA | الشريحة المعالجة | معرفات USB | برنامج التشغيل |
|---|---|---|---|
| [AWUS036ACH](/ar/products/alfa/awus036ach/) | RTL8812AU | 0bda:8812 | aircrack-ng/rtl8812au |
| [AWUS036ACM](/ar/products/alfa/awus036acm/) | MT7612U | 0e8d:7612 | mt76x2u (في النواة) |
| [AWUS036AX](/ar/products/alfa/awus036ax/) | RTL8832BU | 0e8d:885a | OOK driver (<6.14) |
| [AWUS036AXML](/ar/products/alfa/awus036axml/) | MT7921AUN | 0e8d:7961 | mt7921u (نواة 5.18+) |

### التعرف على محولك بـ lsusb

أدخل محولك وشغّل:

```bash
lsusb
```

مثال على الناتج:

```
Bus 003 Device 002: ID 0bda:8812 Realtek Semiconductor Corp. RTL8812AU 802.11a/b/g/n/ac
Bus 003 Device 003: ID 0e8d:7612 MediaTek Inc. MT7612U 802.11a/bgn/ac
```

قارن قيمة `ID xx:xx` بالجدول أعلاه لتأكيد شريحتك المعالجة.

## تجهيز نظامك

بصرف النظر عن شريحتك المعالجة، ثبّت أولاً متطلبات البناء المشتركة:

**Kali Linux:**

```bash
sudo apt update
sudo apt install -y \
    git \
    dkms \
    build-essential \
    libelf-dev \
    linux-headers-$(uname -r)
```

**Ubuntu 24.04:**

```bash
sudo apt update
sudo apt install -y \
    git \
    dkms \
    build-essential \
    libelf-dev \
    linux-headers-$(uname -r) \
    linux-headers-generic
```

تأكد من تثبيت الترويسات لنواتك الجارية تحديداً:

```bash
uname -r
# مثال: 6.6.9-amd64

ls /lib/modules/$(uname -r)/build
# يجب أن يوجد — إذا لم يكن، الترويسات غير مثبتة
```

## برنامج تشغيل RTL8812AU (AWUS036ACH)

تتطلب RTL8812AU برنامج تشغيل خارج الشجرة. يوجد فرعان يصونهما المجتمع؛ اختر بناءً على نظامك.

### الخيار A: aircrack-ng/rtl8812au (Kali Linux — موصى به)

يصون فريق Aircrack-ng هذا الفرع مع توافق صريح مع Kali ودعم محسّن لحقن الحزم:

```bash
git clone https://github.com/aircrack-ng/rtl8812au
cd rtl8812au
make
sudo make install
sudo modprobe 88XXau
```

تحقق من ظهور الواجهة:

```bash
ip link show | grep wlan
# يجب أن يُظهر wlan0 أو ما شابه
```

### الخيار B: morrownr/8812au-20210708 (Ubuntu 24.04 — موصى به)

فرع morrownr محسّن لـ Ubuntu ويتضمن سكريبت تثبيت مريح مع تكامل DKMS:

```bash
git clone https://github.com/morrownr/8812au-20210708
cd 8812au-20210708
sudo ./install-driver.sh
```

يتولى سكريبت التثبيت تسجيل DKMS تلقائياً. بعد تشغيله:

```bash
# أعد التشغيل لتحميل الوحدة الجديدة
sudo reboot

# بعد إعادة التشغيل، تحقق
lsmod | grep 8812au
```

### التسجيل اليدوي في DKMS (لأي من الفرعين)

إذا كنت تفضل التحكم اليدوي:

```bash
# استنسخ برنامج التشغيل (أي من الفرعين)
git clone https://github.com/aircrack-ng/rtl8812au

# احصل على الإصدار من Makefile
grep "^MODULE_VERSION" rtl8812au/Makefile
# لاحظ الإصدار، مثلاً v5.6.4.2 → استخدم 5.6.4.2

# انسخ المصدر إلى مجلد DKMS
sudo cp -r rtl8812au /usr/src/rtl8812au-5.6.4.2

# سجّل وابنِ وثبّت
sudo dkms add -m rtl8812au -v 5.6.4.2
sudo dkms build -m rtl8812au -v 5.6.4.2
sudo dkms install -m rtl8812au -v 5.6.4.2

# تحقق
dkms status
# المتوقع: rtl8812au/5.6.4.2, 6.x.x-kali-amd64: installed
```

### ناتج lsusb وlsmod المتوقع بعد التثبيت الناجح

```bash
lsusb
# Bus 001 Device 003: ID 0bda:8812 Realtek Semiconductor Corp. RTL8812AU ...

lsmod | grep 88XXau
# 88XXau    3461120  0
```

## برنامج تشغيل MT7612U (AWUS036ACM، AWUS036ACX)

MT7612U هي الشريحة الأسهل في الأربعة من حيث التشغيل لأن برنامج تشغيلها أُدرج في نواة Linux الرئيسية منذ الإصدار **4.19**. على Kali Linux 2022+ وUbuntu 20.04+، لا حاجة لتثبيت أي برنامج تشغيل على الإطلاق.

### تحقق من إصدار النواة

```bash
uname -r
```

إذا كان الناتج 4.19 أو أعلى (وسيكون كذلك على أي Kali أو Ubuntu حديث)، فوحدة `mt76x2u` متاحة.

### تحميل الوحدة

```bash
sudo modprobe mt76x2u
```

تحقق من التحميل:

```bash
lsmod | grep mt76x2u
# mt76x2u    86016  0
# mt76x2_common    61440  1 mt76x2u
# mt76_usb    40960  1 mt76x2u
```

يجب ظهور واجهة لاسلكية فوراً:

```bash
ip link show
# wlan0: ...
```

### جعل الوحدة تُحمَّل عند الإقلاع

في معظم الأنظمة، تُحمَّل الوحدة تلقائياً حين يُكتشف المحول. لضمان تحميلها صراحةً عند الإقلاع:

```bash
echo "mt76x2u" | sudo tee -a /etc/modules
```

### لا حاجة للتصريف

هذه الميزة الكبرى لشريحة MT7612U: صفر تصريف، لا مصدر برنامج تشغيل، لا اعتماد على ترويسات النواة. تعمل على كل توزيعة مدعومة جاهزةً مباشرة. لمن يريد تجنب إدارة برامج التشغيل، يُعدّ [AWUS036ACM](/ar/products/alfa/awus036acm/) أكثر محولات اختبار الاختراق plug-and-play.

## برنامج تشغيل MT7921AUN (AWUS036AXM، AWUS036AXML — Wi-Fi 6E)

MT7921AUN هي شريحة Wi-Fi 6E من MediaTek. اندمج برنامج تشغيلها على Linux، `mt7921u`، في النواة الرئيسية منذ **الإصدار 5.18**.

### تحقق من إصدار النواة

```bash
uname -r
```

**Kali Linux 2022.2 وما بعده** يشحن بنواة 5.18 أو أحدث — مدعوم.
**Ubuntu 22.04 LTS** يشحن بنواة 5.15 — **غير مدعوم** دون ترقية النواة.
**Ubuntu 24.04 LTS** يشحن بنواة 6.8 — مدعوم كلياً.

### تحميل الوحدة (نواة 5.18+)

```bash
sudo modprobe mt7921u
```

تحقق:

```bash
lsmod | grep mt7921u
# mt7921u    57344  0
# mt7921_common    196608  1 mt7921u
```

### Ubuntu 22.04: مسار ترقية النواة

إذا كنت على Ubuntu 22.04 بنواة 5.15، لديك خياران:

**الخيار A: نواة HWE** (موصى به)

```bash
sudo apt install linux-generic-hwe-22.04
sudo reboot
```

نواة HWE (تمكين الأجهزة) لـ Ubuntu 22.04 هي 6.2+، وتدعم mt7921u.

**الخيار B: الترقية إلى Ubuntu 24.04**

يشحن Ubuntu 24.04 LTS بنواة 6.8 ودعم كامل لـ mt7921u. هذا هو الحل الأنظف على المدى البعيد.

### Wi-Fi 6E وحالة وضع المراقبة

حتى عام 2026، يوفر برنامج تشغيل mt7921u دعماً مستقراً للوضع الاعتيادي (الاتصال بالشبكات) على نطاقات 2.4 GHz و5 GHz و6 GHz. وضع المراقبة على 2.4 و5 GHz يعمل. **وضع المراقبة على 6 GHz** لا يزال في طور النضج — تحقق من الحالة الراهنة في متتبع مشكلات برنامج تشغيل `mt76` قبل الاعتماد عليه في تقييمات 6 GHz.

## DKMS: الحفاظ على عمل برامج التشغيل بعد تحديثات النواة

يُحدّث كلٌّ من Kali Linux وUbuntu النواة بانتظام. بدون DKMS، تتوقف برامج التشغيل الخارجية (RTL8812AU) عن العمل بعد تحديث النواة حتى تُعيد التصريف يدوياً.

مع DKMS المُهيَّأ بشكل صحيح، يحدث إعادة التصريف تلقائياً أثناء `apt upgrade`.

### تحقق من أن DKMS يدير برنامج تشغيلك

```bash
dkms status
```

مثال على ناتج يُظهر برامج تشغيل مُدارة بشكل صحيح:

```
rtl8812au/5.6.4.2, 6.6.9-amd64: installed
8814au/5.8.7.4, 6.6.9-amd64: installed
```

### ما يحدث أثناء تحديث النواة

```
apt upgrade
→ تنزيل حزمة النواة الجديدة
→ تفعيل خطاف DKMS
→ إعادة تصريف مصدر rtl8812au للنواة الجديدة
→ تثبيت .ko الجديد
→ إعادة تشغيل النظام على النواة الجديدة
→ تحميل برنامج التشغيل تلقائياً
```

إذا أخفق DKMS أثناء الترقية (يظهر في `dkms status` بحالة "built" لا "installed")، أعد التثبيت يدوياً:

```bash
sudo dkms install rtl8812au/5.6.4.2 -k $(uname -r)
```

## استكشاف الأخطاء وإصلاحها

| الأعراض | السبب المحتمل | الحل |
|---|---|---|
| لا واجهة wlan بعد التوصيل | برنامج التشغيل غير محمّل | `sudo modprobe 88XXau` أو `sudo modprobe mt76x2u` |
| `modprobe: FATAL: Module not found` | برنامج التشغيل غير مُصرَّف للنواة الحالية | أعد تصريف برنامج التشغيل أو شغّل `sudo dkms install` |
| تظهر الواجهة ثم تختفي بعد ثوانٍ | إدارة الطاقة تتدخل | `sudo iwconfig wlan0 power off` |
| فشل `make` بخطأ "linux/module.h not found" | ترويسات النواة غير مثبتة | `sudo apt install linux-headers-$(uname -r)` |
| فشل `make` بعدم تطابق الإصدار | الترويسات لا تطابق النواة الجارية | `uname -r` مقابل `ls /lib/modules` — أعد تثبيت الترويسات المطابقة |
| يظهر الجهاز في lsusb لكن لا واجهة | الوحدة مُحمَّلة لكن لم تُنشَأ واجهة | تحقق من `dmesg \| tail -30` للأخطاء |
| يفشل وضع المراقبة: "Operation not supported" | إصدار برنامج التشغيل لا يدعم وضع المراقبة | استخدم فرع aircrack-ng بدلاً من برنامج التشغيل الموزع مع التوزيعة |
| اختبار الحقن في aireplay-ng: 0% | الواجهة ليست في وضع المراقبة | تحقق بـ `iwconfig`، أعد تشغيل `airmon-ng start` |
| برنامج التشغيل يعمل لكن يتوقف بعد إعادة التشغيل | الوحدة لم تُضف إلى initramfs | `sudo update-initramfs -u` أو استخدم DKMS |
| فشل بناء DKMS بعد تحديث النواة | ترويسات مفقودة للنواة الجديدة | `sudo apt install linux-headers-$(uname -r)` |

### أوامر التشخيص التفصيلية

```bash
# تحقق من جميع وحدات الشبكة اللاسلكية المحملة
lsmod | grep -E "8812|8814|mt76|mt79"

# تحقق من رسائل النواة لأحداث USB والشبكة اللاسلكية
dmesg | grep -iE "rtl|mt76|mt79|usb 802|wlan"

# سرد جميع واجهات الشبكة اللاسلكية
iw dev

# تحقق من برنامج التشغيل الذي تستخدمه واجهة معينة
ethtool -i wlan0 | grep driver

# تحقق من تفاصيل جهاز USB
lsusb -v -d 0bda:8812 2>/dev/null | grep -E "idVendor|idProduct|iProduct"

# تحقق من حالة DKMS لجميع الوحدات المسجلة
dkms status
```

## الملخص

تثبيت برامج تشغيل WiFi على Linux يسير وفق شجرة قرار بسيطة:

1. **حدد شريحتك المعالجة** بـ `lsusb` وجدول المطابقة أعلاه
2. **MT7612U أو MT7921AUN (على نواة 5.18+)؟** ← شغّل فقط `modprobe`، انتهيت
3. **RTL8812AU أ؟** ← استنسخ المستودع المناسب، شغّل `make && sudo make install`، فعّل DKMS للاستمرارية
4. **شيء لا يعمل؟** ← راجع جدول استكشاف الأخطاء، تحقق من تطابق الترويسات مع النواة، راجع `dmesg`

جمال محولات ALFA Network أن الشرائح الرئيسية الأربع جميعها لها حلول برامج تشغيل موثقة جيداً ومُصانة بفعالية. لن تجد نفسك أبداً في منطقة غير مدعومة.
