# ALFA AWUS036AXML 設置ガイド：Kali Linux 上の Wi-Fi 6E アダプターでモニターモードとパケットインジェクションを実測

> TL;DR：ALFA AWUS036AXML は MediaTek MT7921AUN チップセットを搭載しており、Kali Linux（カーネル 5.18 以上）では**内蔵の `mt7921u` ドライバーで動作**し、ドライバーのコンパイルは不要です。安定した active monitor mode（アクティブモニターモード）やパケットインジェクションを行うには、カーネル 6.12 以上と給電付き USB Hub を推奨します。接続後、`lsusb` で `0e8d:7961` が表示されれば、`airmon-ng` または `iw` でモニターモードに切り替えることができます。

## なぜ Wi-Fi 6E アダプターがペネトレーションテストで注目されているのか？

Wi-Fi 6E で新たに追加された **6 GHz バンド**（5925–7125 MHz）は、近年の企業向け無線LANのアップグレードにおける重点分野です。次世代 AP、高密度会議室、工場における IoT 環境などで 6 GHz の導入が進んでいます。セキュリティ監査担当者にとって、監査対象の環境に 6 GHz が導入されている場合、テスト用アダプター**はこの周波数帯をキャッチできなければなりません**。そうでなければ、監査範囲に大きな穴が開いてしまいます。

AWUS036AXML は、ALFA Network が提供する Wi-Fi 6E USB アダプターで、2.4 / 5 / 6 GHz の3周波帯をサポートします。前世代のヒット商品である AWUS036ACH（RTL8812AU、2.4/5 GHz のみ）と比較すると、最大の差異は 6 GHz 帯でのモニター機能に対応した点です。AWUS036ACH の手順にすでに精通している方であれば、本ガイドの手順は非常に親しみやすいものとなるでしょう。

## AWUS036AXML の仕様とバージョン要件

| 項目 | AWUS036AXML | AWUS036ACH（比較） | AWUS036ACM（比較） |
|---|---|---|---|
| チップセット | MediaTek MT7921AUN | Realtek RTL8812AU | MediaTek MT7612U |
| 周波数帯 | 2.4 / 5 / 6 GHz（Wi-Fi 6E） | 2.4 / 5 GHz | 2.4 / 5 GHz |
| Linux ドライバー | `mt7921u`（**カーネル内蔵**） | `88XXau`（コンパイル/DKMS が必要） | `mt76`（カーネル内蔵） |
| 推奨カーネル | ≥ 5.18（6 GHz 対応） | 5.x（旧版でも可） | 5.x |
| active monitor mode | カーネル ≥ 6.12 を推奨 | 標準対応 | 標準対応 |
| USB ID（lsusb） | `0e8d:7961` | `0bda:8812` | `0e8d:7612` |
| 消費電力 | 約 2.7 W（給電付き Hub 推奨） | 低め | 低め |
| パケットインジェクション | 対応（実測推奨） | 対応 | 対応 |

> バージョン要件の説明：`mt7921u` はカーネル 5.18 からメインラインに統合され、6 GHz 帯のサポートはカーネルの更新とともに段階的に追加されています。**active monitor mode（アクティブモニターモード）にはカーネル 6.12 以上を推奨**します。Kali 2026 のデフォルトカーネルは 6.14 系であり、条件をすでに満たしています。

## 事前準備

1. **Kali Linux 2024.x 以上**（最新への更新を推奨：`sudo apt update && sudo apt full-upgrade -y`）。
2. カーネルバージョンの確認：`uname -r`。5.18 未満の場合は、まずシステムをアップグレードしてください。
3. 使用可能な USB 3.0 ポート。ラズベリーパイや USB Hub に接続する場合は、**給電付き Hub を推奨**します（AWUS036AXML の消費電力は約 2.7 W で、給電不足だと「接続しても認識されない」現象が発生します）。
4. 合法なテスト権限：本ガイドのすべてのコマンドは、あなたが所有している、または権限を与えられたネットワーク環境でのみ使用してください。

## ステップ 1：アダプターの接続とシステム認識の確認

アダプターを接続した後、`lsusb` コマンドでデバイスが認識されているか確認します。

```bash
lsusb
```

出力結果に以下が含まれているはずです。

```text
Bus 001 Device 003: ID 0e8d:7961 MediaTek Inc. Wireless_Device
```

`0e8d:7961` が MT7921AUN の USB ID です。表示されない場合は、給電を確認し（USB ポートを変更するか、給電付き Hub を追加）、再度試してください。

ドライバーがロードされているか確認します。

```bash
lsmod | grep mt7921
dmesg | grep -i mt7921 | tail -20
```

Kali 2026 のデフォルトカーネルには `mt7921u` が含まれており、通常は接続するだけでロードされます。**ドライバーのダウンロードやコンパイルは不要**です。これは、AWUS036ACH（RTL8812AU には手動で `88XXau` をインストールする必要がある）との最大の違いです。

## ステップ 2：無線インターフェースの確認

```bash
ip link show
# または
iwconfig
```

新しい無線インターフェースが表示されるはずです。通常は `wlan0` または `wlan1` です（システムの既存インターフェースの数によります）。以下の例では `wlan1` を基準としますが、実際の名称に合わせて置き換えてください。

## ステップ 3：モニターモードの有効化

### 方法 1：airmon-ng（推奨）

```bash
# 干渉する可能性のあるサービスを終了
sudo airmon-ng check kill

# モニターモードを有効化（wlan1 はあなたのインターフェース名に置き換えてください）
sudo airmon-ng start wlan1
```

成功すると、`wlan1mon` という仮想インターフェースが表示されます。

### 方法 2：iw（簡易制御）

```bash
sudo ip link set wlan1 down
sudo iw dev wlan1 set type monitor
sudo ip link set wlan1 up
```

この方法は既存のインターフェースを直接変更するため、`wlan1mon` は作成されません。

## ステップ 4：モニターモードが有効になっていることの確認

```bash
iwconfig
```

重要なフィールドは `Mode:Monitor` であるべきです。

```text
wlan1mon  IEEE 802.11  Mode:Monitor  Frequency:2.412 GHz  Tx-Power=30 dBm
          Power Management:off
```

`iw dev` で `type monitor` が表示されるか確認することもできます。その後、`airodump-ng` でエンドツーエンドのテストを行います。

```bash
sudo airodump-ng wlan1mon
```

周辺の BSSID リスト（チャンネル、信号強度、暗号化タイプを含む）が表示されれば、モニターモードは正常です。**6 GHz 帯のスキャン**：

```bash
sudo airodump-ng --band 6g wlan1mon
```

> 注意：6 GHz 帯のスキャンには、アダプターのドライバー/カーネルがその周波数帯をサポートしている必要があります（カーネル 6.12 以上が安定）。`--band 6g` がサポートされていない場合は、まず 5 GHz 帯（`--band a`）でスキャンして基本機能を確認し、カーネルを更新してから再試行してください。

## ステップ 5：パケットインジェクションテスト

```bash
sudo aireplay-ng --test wlan1mon
```

出力結果の重要な行：

```text
Injection is working!
```

成功率が 80% 以上であれば、動作は信頼できます。50% 未満の場合は、アンテナの方向、USB 給電を確認するか、USB 3.0 直結ポートを使用してください。

## ラズベリーパイ補足：ポータブル Wi-Fi 監査プラットフォーム

AWUS036AXML は Raspberry Pi 3B+ / 4 / 5（公式製品ページに記載）でもサポートされており、ポータブル監査ツールキットの構成に適しています。主な注意点：

- **給電**：Pi の USB 給電は限られているため、給電付き USB Hub を使用し、「時々認識されない」現象を避けてください。
- **システム**：Kali ARM64 公式イメージ（Raspberry Pi 版）で問題ありません。インストール後、同様に内蔵 `mt7921u` が使用されます。
- **検証**：`lsusb` で `0e8d:7961` が表示され、`lsmod | grep mt7921` に出力があれば、プラットフォームの準備は完了です。

## 一般的なトラブルシューティング

**Q：`lsusb` で `0e8d:7961` が表示されない場合は？**
99% の場合、給電不足または接続の緩みです。別の USB 3.0 直結ポートに変更してください。Hub に接続している場合は給電付き Hub に変更し、それでもダメな場合は短い USB ケーブルに変更してください。

**Q：モニターモード有効化後、インターフェースが自動的に managed モードに戻ってしまう？**
通常、NetworkManager や wpa_supplicant がバックグラウンドで制御権を奪っています。`sudo airmon-ng check kill` を再実行するか、手動で `sudo systemctl stop NetworkManager wpa_supplicant` を実行してください。

**Q：`iwconfig` で `Mode:Managed` と表示される、またはインターフェースが消える？**
ドライバーが正しくロードされていないか、カーネルが古すぎます。まず `lsmod | grep mt7921` でモジュールを確認し、`uname -r` でカーネルが 5.18 以上であることを確認してください。

**Q：6 GHz 帯でネットワークが検出されない？**
まず `iw dev wlan1mon info` でサポートされている周波数帯を確認してください。6 GHz 環境自体がまだ少ない（新規導入）こと、および台湾の 6 GHz 許可帯域の開放状況は NCC の公告に従ってください。また、2.4/5 GHz 帯でアダプターの機能が正常であることを先に確認することもできます。

**Q：AWUS036ACH と比較して、どちらを購入すべきか？**
監査対象に 6 GHz 環境がある場合 → AWUS036AXML を選択。2.4/5 GHz のみで予算を優先する場合 → AWUS036ACH も非常に成熟した選択肢です。両方とも Kali で使用可能ですが、差異は周波数帯のカバレッジとドライバーのインストール方法（AXML は内蔵でコンパイル不要）にあります。

## よくある質問（FAQ）

**Q1：AWUS036AXML を Kali Linux で使用する場合、別途ドライバーをインストールする必要がありますか？**
不要です。カーネル内蔵の `mt7921u` ドライバー（カーネル 5.18 以上）を使用するため、接続するだけで利用可能です。AWUS036ACH のように DKMS ドライバーをコンパイルする必要はありません。

**Q2：AWUS036AXML はモニターモードをサポートしていますか？**
サポートしています。`airmon-ng` または `iw` で有効化できます。active monitor mode（deauth 関連テストなど）を行うには、カーネル 6.12 以上を推奨します。

**Q3：台湾で Wi-Fi 6E の 6 GHz 帯を監査に使用できますか？**
6 GHz は規制対象の周波数帯です。使用前に NCC の 6 GHz 帯の開放状況と認可規定を確認し、権限のある環境でのみテストを行ってください。

**Q4：ラズベリーパイに接続してもアダプターが認識されない場合は？**
まず給電を確認してください。AWUS036AXML の消費電力は約 2.7 W であるため、給電付き USB Hub を使用し、品質の良い USB ケーブルを使用することを推奨します。

**Q5：AWUS036AXML と AWUS036ACH の違いは？**
AXML は Wi-Fi 6E（6 GHz 追加）でドライバーがカーネル内蔵です。ACH はデュアルバンド（2.4/5 GHz）で、RTL8812AU には手動でドライバーをインストールする必要があります。どちらも Kali で成熟した監査用アダプターです。

## まとめ

AWUS036AXML のインストールプロセスは、想像以上に簡単です。**カーネル 5.18 以上 → 接続するだけで使用可能（`mt7921u`）→ `0e8d:7961` を確認 → airmon-ng でモニターモードに切り替え → aireplay-ng でインジェクションを検証**。AWUS036ACH との核心的な差異は、6 GHz 帯とコンパイル不要のドライバーにあります。あなたの監査範囲が Wi-Fi 6E 世代に入っている場合、このアダプターは周波数帯のカバレッジを補完する最適な選択です。すべてのテストは合法な権限のある環境でのみ実施してください。
