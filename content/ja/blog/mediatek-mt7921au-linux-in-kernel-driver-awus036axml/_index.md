## はじめに：「システム更新のたびにドライバーを再コンパイル」していた日々

Realtek RTL8812AU 系チップセットの USB アダプター（例えば市販で人気の AWUS036ACH）をお使いの場合、次のような経験をされたことがあるかもしれません：

1. コミュニティ保守のドライバーをインストールし、インターネット接続もモニタリングも正常に動作。
2. ある日 `sudo apt upgrade` を実行すると、Linux カーネルが新しいバージョンに更新。
3. 再起動後、アダプターがシステムから消え、Wi-Fi インターフェース（`wlan0` / `wlan1`）が完全に見えなくなる。
4. 仕方なく**ソースコードを再ダウンロードし、DKMS をインストールし、カーネルモジュールを再コンパイル**して、午後を丸ごと費やす。

問題は製品そのものではなく、ドライバーの存在形態にあります。Realtek の Linux ドライバーの多くは Linux カーネル（mainline）に収録されていません。使うには、外部ソースコードをシステムに「外付け」する必要があります。カーネルが更新されるたびに、この外付け部分を再コンパイルしなければ、新しいカーネルバージョンと合わずに動作しなくなります。

そして今回の主役——MediaTek MT7921AU を採用した ALFA AWUS036AXML——はまったく異なる道を歩んでいます。そのドライバーは**最初から Linux カーネルの中に存在している**のです。

## 一、Linux カーネル更新時に Realtek ドライバーのコンパイルが失敗するよくある痛点

### 1.1 カーネルモジュール（Kernel Module）はカーネルバージョンに固定される

Linux カーネルはデバイスドライバーを「モジュール」として動的に読み込みます。重要なのは、**モジュールは特定のカーネルバージョン向けにコンパイルされる**という点です。カーネルのメジャーアップデート（例：6.8 → 6.9）後、古いモジュールは新しいカーネルで読み込めないことが多く、再コンパイルが必要になります。

### 1.2 DKMS：自動再コンパイルの救世主であり、新たな落とし穴

DKMS（Dynamic Kernel Module Support）はまさに「カーネルが更新されるとモジュールを再コンパイルしなければならない」という痛点を解決するための仕組みです。カーネルが更新されるたびに、**ドライバーを自動的に再コンパイルしてくれます**。聞こえは良いのですが、実際には次のような問題に直面します：

- **ツールチェーンの問題**：コンパイルには `build-essential`、`dkms`、ネイティブのカーネルヘッダー（`linux-headers-$(uname -r)`）が必要です。揃っていないと、DKMS のビルドは即座に失敗します。
- **バージョン非互換**：最も怖いのは、カーネルが更新された後、GitHub 上のドライバーが新しい API 変更に追いついていないケースです。次の `apt upgrade` がいつそのタイミングに当たるかは誰にもわかりません。
- **Secure Boot / カーネルモジュール署名**：システムで Secure Boot が有効な場合、署名されていないカーネルモジュールは読み込みを拒否され、ネットワークインターフェースすら出現しません。セキュリティ機能を無効化して解決するのではなく、MOK（Machine Owner Key）の仕組みで自己署名証明書をインポートするのが正しい方法です。これもひと手間です。
- **コミュニティ版の選択に悩む**：同じチップセットでも GitHub 上には `aircrack-ng/rtl8812au`、`morrownr/8812au-20210820` など複数のブランチがあり、バージョンも対応カーネル範囲も異なります。選び間違えると、コンパイルが無駄になります。

### 1.3 本当のコストはあなたの時間

「インストールした一度だけ」のコンパイルなら問題ありません。しかし**システムが更新され続ける限り、このドライバーは永続的なメンテナンスの負担になります**。ペネトレーションテスターや組み込み開発者にとって、貴重な時間はネットワークアダプターの再コンパイルではなく、ツールやスクリプトの開発に使うべきです。

## 二、MediaTek MT7921AU：なぜ「ネイティブ対応・プラグアンドプレイ」が実現できるのか

### 2.1 ネイティブ対応の仕組み：mt76 と mt7921u

MediaTek の Wi-Fi チップセットドライバーは、長年にわたり Linux カーネルの mt76 ワイヤレスドライバーフレームワークに収録されています。MT7921 シリーズには PCIe 版と USB 版があります：

- MT7921 シリーズは Linux Kernel 5.12（PCIe / M.2 版）から mainline カーネルに登場しました；
- AWUS036AXML が使用するのは USB 版の `mt7921u` ドライバーで、Linux Kernel 5.18 から mainline にネイティブ収録されています。

つまり、**ドライバー本体を GitHub から取得する必要も、DKMS も、自分でのコンパイルも不要**です。ディストリビューションのカーネルが十分に新しければ、アダプターを挿してファームウェアを追加するだけで完了します。インターフェースは `ip link` にきちんと表示されます。

### 2.2 必要なのはファームウェア（Firmware）だけ。ドライバーのソースコードは不要

「コンパイル不要＝何もインストール不要」と思っている方も多いのですが、実際は違います。「ドライバーのコンパイルが不要」ということは「何もインストールしなくてよい」という意味ではありません。MT7921AU に必要なのは**ファームウェアファイル**であり、ドライバーのソースコードではありません。ファームウェアはディストリビューションのパッケージとして一元管理されており、通常は 1 コマンドで完了します：

```bash
sudo apt update
sudo apt install linux-firmware firmware-misc-nonfree   # Debian / Kali 系
sudo reboot
```

Ubuntu では一般的に次のようにします：

```bash
sudo apt update
sudo apt install linux-firmware
sudo reboot
```

ファームウェアは「ディストリビューションに追従する」パッケージであり、カーネル更新で壊れることはありません——これが「DKMS ドライバー」とのメンテナンスコストにおける根本的な違いです。

各ディストリビューションの最低カーネル要件は、次の表で一目瞭然です：

| OS / ディストリビューション | 最低カーネル要件 | ドライバーのコンパイルが必要か |
|---|---|---|
| Kali Linux（Rolling） | 6.x（`mt7921u` 内蔵） | 不要。ファームウェアの追加のみ |
| Debian 12 | 6.1 LTS | 不要 |
| Ubuntu 22.04+ / 24.04 LTS | 5.18 以上（HWE カーネル推奨） | 不要 |
| Raspberry Pi OS（Bookworm） | 6.1 LTS | 不要 |
| 旧型 Linux ディストリビューション | 5.18 未満 | 追加のデプロイが必要。非推奨 |
| Windows 10 / 11 | — | メーカー製ドライバー |
| macOS（Intel / Apple Silicon） | 非対応 | **ドライバーなし。購入しないでください** |

> **⚠️ 購入前に最も重要なサポート情報**：AWUS036AXML は **macOS に非対応**です。Intel でも Apple Silicon でも、現在 MT7921AU 用の macOS ドライバーはありません。メイン環境が macOS の場合、この種の Wi-Fi 6 / 6E USB アダプターは使えないものと考えてください——購入後に気づく前に、候補から外してください。

### 2.3 「ネイティブ対応」が Kali 開発者にとって特に重要な理由

Kali Linux ではカーネルの更新が非常に頻繁です（Rolling リリース）。RTL8812AU ユーザーはローリング更新のたびにハラハラします。一方 `mt7921u` はカーネルと一緒にメンテナンスされ、一緒にテストされます——**カーネルがどれだけ新しくなっても、ドライバーは追従します**。ALFA はこの製品をセキュリティテスト向けに位置づけており、モニターモード（Monitor Mode）とパケットインジェクション（Packet Injection）は開封後すぐに使える標準機能です。

## 三、Kali Linux での AWUS036AXML：プラグアンドプレイとモニターモードの実測

### 3.1 挿す、確認する、作業開始：3 ステップで完了

アダプターを USB-C ポートに挿したら（付属の 2-in-1 USB-C/USB-A ケーブルを使用）、次のコマンドを実行します：

```bash
lsusb                 # 0e8d:7961 の MediaTek デバイスが表示されるはず
ip link               # wlanX インターフェースが表示されるはず
sudo apt install linux-firmware firmware-misc-nonfree
sudo reboot
```

再起動後にインターフェースを確認します：

```bash
iwconfig              # wlanX が Managed モードと表示されるはず
ip addr show wlanX    # アドレスが正常に取得される
```

デフォルトの接続でも、一般的なディストリビューション（Kali を含む）の NetworkManager は直接認識します——**GitHub のソースコードサイトは一切不要**です。

私が初めて Kali で AXML を挿したとき、`lsusb` で `0e8d:7961` を確認できただけで安心しました——clone もコンパイルも不要で、再起動後にはインターフェースが自動的に現れました。

### 3.2 モニターモードとパケットインジェクションのテスト

インターフェースが `wlan1` の場合を想定します：

```bash
sudo ip link set wlan1 down
sudo iw dev wlan1 set type monitor
sudo ip link set wlan1 up
iw dev wlan1 info     # type が monitor と表示されることを確認
```

これで `wlan1` は 802.11 フレームをパッシブにモニタリングする状態になり、Wireshark や aircrack-ng スイートに接続して作業を続けられます。

次にパケットインジェクションをテストします：

```bash
sudo aireplay-ng --test wlan1
```

`Injection is working!`（または同等の出力）が表示されれば、インジェクション機能は正常です。この機能はネイティブの `mt7921u` ドライバーでは標準搭載の機能であり、追加の Hacks は不要です。

### 3.3 フュージョンモード（VIF / Fusion）：管理とモニタリングを同時に

多くのペネトレーションシナリオでは「クライアントとしてインターネットに接続しながら、同時にモニタリングする」ことが求められます。ネイティブドライバーは Virtual Interface でこれをサポートしています：

```bash
sudo iw dev wlan1 interface add mon0 type monitor
sudo ip link set mon0 up
```

このとき `wlan1` は managed モード（インターネット用）を維持し、`mon0` がモニタリングを担当します。RTL8812AU ドライバーでこれを安定して実現するには、通常多くの設定ファイルを変更する必要があります——ネイティブドライバーはこの機能をそのまま提供してくれます。

> **⚠️ 合法的な使用のレッドライン**：モニターモード、パケットインジェクション、Evil Twin などの機能のテスト対象は、**あなたが所有しているか、明確に許可を得たネットワーク環境のみ**です（自前のラボ、会社が許可したテストセグメントなど）。許可のないネットワーク偵察や侵入行為は現地の法律に違反する可能性があります。法的な境界線を守ってください。本記事は学術およびエンジニアリング開発用途の技術説明です。

## 四、購入前の評価ワークシート：「ネイティブでコンパイル不要」か「DKMS アダプター」か

購入後のサポートコストを抑えるため、AWUS036AXML と AWUS036ACH のどちらを買うか決める前に、この簡単な評価を行ってください。

### 4.1 2 つのアダプターの簡単な比較

| 評価項目 | AWUS036AXML（MT7921AU） | AWUS036ACH（RTL8812AU） |
|---|---|---|
| ワイヤレス仕様 | Wi-Fi 6E トライバンド（2.4/5/6 GHz） | AC1200 デュアルバンド（2.4/5 GHz） |
| USB インターフェース | USB-C（USB 3.2 Gen 1） | USB 3.0 Type-A |
| Linux ドライバー | `mt7921u` **カーネル 5.18+ にネイティブ搭載** | DKMS での外部コンパイルが必要 |
| インストールの難易度 | ファームウェアの追加のみ | ツールチェーン＋コンパイル＋（Secure Boot 時）署名 |
| カーネル更新の影響 | 影響なし | 更新のたびに再コンパイルが必要 |
| モニターモード | ネイティブ対応 | 対応 |
| パケットインジェクション | ネイティブ対応 | 対応 |
| macOS | 非対応 | 非対応 |
| 対象ユーザー | 現代の Linux / Kali / 組み込み | 旧システム、または 2.4/5 GHz が必要な環境 |

### 4.2 30 秒でできる判断チェックリスト

下の項目にチェックが多ければ多いほど、**AWUS036AXML を直接選ぶのが適しています**：

- [ ] メインシステムは **Kali Linux / Ubuntu / Debian** で、カーネルバージョンは 5.18 以上です。
- [ ] **挿すだけで使える**ことを重視しており、`dkms`、`github clone`、コンパイルツールチェーンには触れたくありません。
- [ ] `mt76` 系のネイティブ対応が必要で、カーネル更新がアダプターに影響しないことが条件です。
- [ ] **6 GHz 帯**（Wi-Fi 6E ルーター環境）が必要です。
- [ ] 主な用途：モニタリング、パケットインジェクション、Soft AP、フュージョンモード（VIF）です。
- [ ] 付属の USB-C / USB-A 2-in-1 ケーブルを使ってノートパソコンやシングルボードコンピューターに接続します。

逆に、6 GHz のニーズがなく、システムが 5.18 未満の旧カーネルで、DKMS のメンテナンス手順に慣れているなら、AWUS036ACH にも役割があります。ただし心の準備は必要です：カーネルが更新されるたびに、ドライバーを再コンパイルしなければなりません。

## 五、まとめ

現代の Linux と Kali 開発者にとって、時間こそが最大のコストです。**MediaTek MT7921AU（AWUS036AXML）は「ドライバーメンテナンス」という終わりのない負担をあなたから取り除きます**。ドライバーはカーネルの中にあり、ファームウェアは 1 パッケージで完了、モニタリングとインジェクションは開封後すぐに使えます——カーネルがローリング更新されても心配はありません。

購入前に確認すべきことは 2 つだけです：**システムカーネル ≥ 5.18**、そして **macOS ではないこと**。あとはネイティブドライバーに任せればよいのです。

## 付録：クイックトラブルシューティング Intake（サポートとユーザー向け）

アダプターを挿してもインターフェースが表示されない場合は、順番に確認してください：

1. `lsusb` に `0e8d:7961`（MediaTek）デバイスがあるか → ない場合は USB ポートを変えるか、給電を確認してください。
2. `sudo apt install linux-firmware firmware-misc-nonfree` を実行して再起動 → ファームウェア未インストールが最大の原因です。
3. `ip link` に `wlanX` が表示されるか → 表示されない場合は、カーネルバージョン（`uname -r`）が 5.18 以上か確認してください。
4. **まず OS が macOS でないことを確認**——この製品には macOS ドライバーがありません。この理由での修理依頼はご遠慮ください。
5. 上記がすべて正常なのにモニタリングできない場合は、managed モードを誤って使用していないか確認してください（`iw dev wlanX info` で type を確認）。
