# Sierra Wireless ファームウェア更新とブランドロック切替ガイド：文鎮化を防ぐ正しい手順

**一言でまとめると、Sierra モジュールのファームウェア更新は「キャリアによる空中配信（FOTA）」か「USB を使った自分での書き込み」のどちらかで行います。多くの人が気にするブランドロック（Dell 版や Lenovo 版と汎用版の違い）も、正しいファームウェアパッケージを使えば切り替えることができます。書き込む前に `AT+GMR` でバージョンを必ず確認し、途中で電源を切らないこと。万一失敗しても慌てる必要はありません。モジュールには公式の SED 復旧モードが内蔵されているからです。**

中古市場で Sierra Wireless のモジュールを購入し、自分のノートPC やルーターに取り付けたものの、動作しないというケースがよくあります。原因はたいてい「ブランドロック（OEM ロック）」です。本記事では、公式仕様書に記載されている確かな情報と、コミュニティの実践的なノウハウを組み合わせて、安全にファームウェアを書き込む方法を解説します。

> 技術資料の出典：Sierra Wireless 公式仕様書（EM7455、EM7565、MC7455）。ブランドロックの切り替えとサードパーティ製ツールについては、コミュニティでの実践に基づいています。本記事は榆閤科技（Yupitek）が編集しました。

## 30 秒でわかる書き込みの重要ポイント

書き込み自体は危険ではありません。危険なのは「バックアップを取らない」「間違ったファイルを入手する」「書き込み中に電源を抜く」ことです。

| 知っておきたいこと | 公式仕様書に記載？ | 簡単な説明 |
|---|---|---|
| **FOTA（空中更新）** | ✅ あり | キャリアが更新を直接配信しますが、キャリアが対応している必要があります。 |
| **USB 書き込み（純正ツール）** | ✅ あり | USB ケーブルで PC に接続し、ツールを使ってファームウェアを書き込みます。最も確実な方法です。 |
| **ファームウェア版数確認（AT+GMR）** | ✅ あり | この AT コマンドで現在のファームウェアバージョンを確認できます。書き込み前の必須手順です！ |
| **ブランドロック（Dell/Lenovo）** | ⚠️ 直接の記載なし | 仕様書にあるのは「OEM ラベル対応」のみ。実際のロック機構はノートPC メーカー独自のホワイトリストです。 |
| **qmi-firmware-update** | ⚠️ 記載なし | Linux オープンソースコミュニティで広く使われている書き込みツールです。 |

## ブランドロック（OEM ロック）とは？

Dell や Lenovo などの大手メーカーは Sierra Wireless からモジュールを購入する際、モジュールに「自社のロゴと専用ファームウェアを入れる」よう求め、さらにノートPC の BIOS に「ホワイトリスト」を組み込みます。

Dell 版のモジュールを Lenovo のノートPC に挿すと、起動時にエラーで止まってしまうことがあります。
Generic（汎用版）のモジュールを、厳しいホワイトリストを持つノートPC に挿しても同様に動作しません。

**だからこそ「ブランドロックの切り替え」が必要になるのです。** 実際には、対応ブランド（または汎用版）のファームウェアをダウンロードし、USB 書き込みツールで強制的に書き込むことで、モジュールを別のブランド版として「見せかける」という操作になります。

> ⚠️ **注意**：ブランドを間違えたファームウェアの書き込みには一定のリスクがあります。作業を始める前に、お使いのマザーボードがどのバージョンを必要としているかを必ず確認してください。

## 書き込み前の必須手順：この 3 ステップで文鎮化を防ぐ

ファイルを入手したからといって、すぐに書き込まないでください。公式仕様書の要求に従い、次の 3 ステップをきちんと行いましょう。

### 1. 現在のファームウェアバージョンを確認する
ターミナル（minicom や putty など）を開いてモジュールの AT port に接続し、次のように入力します。
```text
AT+GMR
```
画面に表示されたバージョン番号をスクリーンショットで保存してください。万一書き込みに失敗したときに、どのバージョンのファイルを書き戻せばよいかがわかります。

### 2. 設定をバックアップする
仕様書にはバックアップ手順の記載はありませんが、実践上は現在の APN 設定と PRI パラメータをメモしておくことをおすすめします。

### 3. 「安全な電源オフ」を理解する
書き込み後、あるいはモジュールを取り外す際に、直接電源を切るのは厳禁です。仕様書でも、直接電源を切るとモジュールのファイルシステムが破損する可能性があると警告されています。
- **EM7455 / EM7565**：`Full_Card_Power_Off#` ピンを Low にして、約 20〜25 秒待ってから電源を切ります。
- **MC7455**：まず `AT!PCOFFEN=0` コマンドを実行し、その後 `W_DISABLE_N` を Low にして、数十秒待ってから電源を抜きます。

## 書き込みの実践：USB での手順

Linux コミュニティで愛用されている `qmi-firmware-update` を使う場合、おおよその手順は次のとおりです（ツールの公式説明を最優先にしてください）。

1. **正しいファイルを入手する**：公式サイトまたはサプライヤーから、対応する型番のファームウェアパッケージを入手します。EM7455 と EM7565 はチップがまったく異なるため、ファイルを混ぜて書き込むのは絶対にやめてください！
2. **モジュールを接続する**：`lsusb` でデバイスが認識されていることを確認します。
3. **干渉するサービスを停止する**：`ModemManager` などのネットワークサービスを先に停止し、USB を占有されないようにします。
4. **書き込みツールを実行する**：ツールにファイルを読み込ませて実行します。
5. **キーボードから手を離す**：書き込み中、モジュールは「不安定な状態」にあります。**絶対に電源を切ったりケーブルを抜いたりしないでください！** 文鎮化が最も多く発生するのはこの瞬間です。
6. **再起動して確認する**：書き込み後、安全に電源をオフにしてから再起動し、`AT+GMR` でバージョン番号が変わったか確認します。

## 万一文鎮化したら？（SED 復旧メカニズム）

書き込み後にモジュールが延々と再起動を繰り返し、システムに入れない場合は、すぐに捨てないでください。

Sierra モジュールには **SED（Smart Error Detection）** と呼ばれる頼りになる復旧機構が内蔵されています。
仕様書には明確に記載されています。**モジュールが起動時に 6 回連続でクラッシュして再起動すると、抵抗をやめて「boot-and-hold」モードに入ります。**
このモードは、ファームウェアを再インストールするために開かれた扉のようなものです。

**復旧手順：**
1. 再起動を繰り返させ、6 回目が終わるとモジュールは静かに停止します（boot-and-hold モード）。
2. そのタイミングで USB を再接続します。
3. 書き込みツールを開き、問題のないファームウェアパッケージを選んで、もう一度書き込みます。
4. 通常これでモジュールは復活します。

> USB にも接続できない場合は、ハードウェアリセット（RESET#）の実行を試してください。モジュールごとに秒数が異なります。EM7455 は約 3〜5.5 秒、EM7565 は 0.2〜2.5 秒です。時間を過ぎると再びループするため、タイミングを合わせる必要があります。

## まとめ

Sierra Wireless モジュールへのファームウェア書き込みやブランドロックの切り替えは、スマートフォンの書き込みと同じようなものです。**標準的な手順と復旧メカニズムがあり、無茶をしなければ問題は起こりません。**

最大の落とし穴は次の 3 つです。
1. 型番を間違えたファームウェアファイルを入手してしまう。
2. 書き込み中に電源ケーブルを蹴ってしまう。
3. 標準手順に従った安全な電源オフを忘れてしまう。

書き込み前にバージョンを確認（`AT+GMR`）し、正しいファイルを用意し、安定した電源を供給すれば、あなたの通信カードにも新しいファームウェアを安心して入れることができます。
