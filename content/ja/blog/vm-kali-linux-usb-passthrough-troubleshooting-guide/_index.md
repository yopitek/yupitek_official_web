{{< tldr >}}

Kali ユーザーの多くは、アダプターをホストに挿しているのに、仮想マシン内でワイヤレスインターフェースが見えないという状況に遭遇します。**このようなケースの多くは、次の 3 つの非常によくある原因によるもので、アダプター自体の故障である可能性は低いです。**

1. **VirtualBox に拡張パック（Extension Pack）がインストールされていない**：これがないと、Guest は USB 2.0/3.0 コントローラーすら利用できません（USB 1.1 の転送速度は最大 12 Mbps で、アダプターにはまったく不十分です）。
2. **USB パススルー設定が行われていない**：ホストは既定ですべての USB デバイスを「占有」します。Guest 側で手動でマウントするか、「USB フィルター（VM USB Filter）」を設定してアダプターを自動的に引き継ぐ必要があります。
3. **Guest 内のドライバーが読み込まれていない**：USB 層は通過しています（`lsusb` では認識されます）が、Linux に対応するドライバーがないため、`ip link` に `wlan` インターフェースが表示されません。

排障の順序は、まずホスト側のハードウェア、次に Guest 側のパススルー、最後にドライバー層です。完全な診断の手順は 1.3 をご覧ください。

## 1. なぜ仮想マシンは既定でホストのワイヤレスアダプターを使えないのか？

### 1.1 USB アダプターは「同時に」1 つの OS にしか属さない

USB は**シングルホスト（single host）**アーキテクチャで動作します。1 つの USB デバイスは、同時に 1 つの「USB ホストコントローラー（Host Controller）」にしか制御されません。アダプターをホストに挿すと、デバイスはまず**ホスト OS（Host OS）**に列挙（enumerate）されて引き継がれます。ホストのドライバーがそれを認識し、制御します。

仮想マシン（Guest VM）は USB バスに挿された物理デバイスではなく、ホスト内でハイパーバイザー（Hypervisor）が演じる「仮想ハードウェア」にすぎません。そのため Guest が USB アダプターを使うには、**ホストがデバイスを Guest に積極的に「引き渡す」必要があります**——この仕組みを **USB パススルー（USB Pass-through / USB Redirection）** と呼びます。

### 1.2 USB パススルーは何を通過させるのか？

VirtualBox を例にすると、パススルーの流れは次のとおりです：

```
物理 USB アダプター（AWUS036ACH / AWUS036AXML）
       │  ホストの物理 USB ポートに挿す
       ▼
ホスト OS（Host OS）の USB ホストコントローラー
       │  Hypervisor（VirtualBox）がインターセプトしてリダイレクト
       ▼
仮想 USB ホストコントローラー（エミュレートされた EHCI / xHCI）
       │  Guest（Kali）には「自分に挿さっている」ように見える
       ▼
Kali の USB ドライバー → ワイヤレスドライバー → wlan インターフェース
```

パススルーが成功すると、このデバイスの**ホスト側の制御権は Guest に移り**、ホストからは「抜かれた」ように見えて使用できなくなります。代わりに Guest 内では新しい USB デバイスとして認識されます。**これは正常な動作であり、バグではありません。** ホストの 1 つの USB デバイスを両方で同時に使うことはできません。

### 1.3 「認識されない」には実は 3 つの層がある

| 層 | 確認ツール | 症状 | 意味 |
|----|-----------|------|------|
| **USB パススルー層** | Guest 内の `lsusb` | `lsusb` でアダプターの VID:PID がまったく見えない | パススルー失敗（Extension Pack / コントローラー / フィルターの問題） |
| **ドライバー層** | Guest 内の `dmesg` | `lsusb` では見えるが、`dmesg` にエラーがある（ファームウェア不足、`Required key not available` など） | Guest 内にドライバーがない、またはモジュールの読み込みに失敗 |
| **ワイヤレスインターフェース層** | Guest 内の `iwconfig` / `ip link` | `lsusb` と `dmesg` は正常なのに `wlan` インターフェースがない | ドライバーは読み込まれたがインターフェースが登録されていない、またはモード／設定の問題 |

> **判断の手順**：まず `lsusb` で「デバイスが Guest にパススルーされたか」を確認し、次に `ip link` で「ドライバーが認識しているか」を確認します。**最初からアダプターの故障を疑わないでください。**

## 2. VirtualBox：まず Extension Pack をインストールし、次に USB 3.0 コントローラーを設定する

### 2.1 拡張パック（Extension Pack）は必須です

VirtualBox の基本パッケージは**USB 1.1（OHCI）コントローラーのエミュレーションのみ**を内蔵しており、USB 1.1 の転送速度ではアダプターにまったく不十分です。**USB 2.0（EHCI）と USB 3.0（xHCI）コントローラーは、Oracle 公式の「拡張パック（Extension Pack）」がなければ利用できません。**

Extension Pack がない場合の症状は典型的です：Guest の設定で USB 2.0 / USB 3.0 コントローラーを選択できない、またはアダプターをマウントすると「仮想マシンへのデバイス接続に失敗しました（error code E_FAIL / VERR_PDM_NO_USB_PORTS）」と表示されます。

### 2.2 バージョンは「完全に」一致させる必要があります

Extension Pack のバージョンは**VirtualBox 本体のバージョンと完全に一致させる必要があります**（例：VirtualBox 7.0.20 には 7.0.20 の Extension Pack が必要です）。マイナーバージョンが 1 つでも違うと、インストールや読み込みに失敗する可能性があります。

```bash
# 現在の VirtualBox バージョンを確認
vboxmanage --version
```

Oracle 公式ダウンロードページ（https://www.virtualbox.org/wiki/Downloads）から対応バージョンの
`Oracle_VM_VirtualBox_Extension_Pack-<バージョン>.vbox-extpack` をダウンロードし、次の手順を実行します：

```bash
# 方法 1：GUI インストール（VirtualBox 本体 → ファイル → ツール → Extension Pack Manager → インストール）
# 方法 2：コマンドラインでインストール
sudo VBoxManage extpack install Oracle_VM_VirtualBox_Extension_Pack-*.vbox-extpack

# インストール済みか確認
VBoxManage list extpacks
```

> インストール時には Oracle のライセンス（Personal Use and Evaluation License）が表示されます。個人利用は無料ですが、商用環境ではライセンスの内容に従ってください。

### 2.3 Linux ホスト：vboxusers グループに自分を追加する

Linux ホストでは、VirtualBox が USB デバイスにアクセスするために、**ユーザーが `vboxusers` グループに属している必要があります**。拡張パックをインストールしても失敗する多くのケースは、この権限が原因です。

```bash
# グループに追加（<user> は自分のユーザー名に置き換えてください）
sudo usermod -aG vboxusers $USER

# ログアウトして再ログイン（または再起動）してグループを有効化；確認する
id $USER
```

### 2.4 USB 3.0（xHCI）コントローラーを設定する

1. Kali 仮想マシンを選択 → **設定（Settings）→ ポート（Ports）→ USB**。
2. 「Enable USB Controller」にチェックを入れ、**USB 3.0 (xHCI) Controller** を選択します。
   - AWUS036AXML は USB 3.2 Gen 1（USB-C）仕様です。**必ず USB 3.0 (xHCI) を選択してください**。USB 2.0 を選ぶと転送速度が制限されます。
   - AWUS036ACH は USB Type-A インターフェースで、USB 2.0 と USB 3.0 のどちらのコントローラーでも使用できます。より良い転送速度を得るには、こちらも USB 3.0 (xHCI) を選択してください。
3. コントローラーを変更したら、**シャットダウンしてから起動**してください（Guest 内で reboot を実行するのではありません）。変更を反映するために必要です。

### 2.5 手動マウントと VMware との対比

Kali 仮想マシンを起動したら、ウィンドウ**右下の USB アイコン**（USB プラグの形）に注目してください：

1. USB アイコンをクリックすると、現在ホストに挿されている USB デバイスの一覧が表示されます。
2. アダプターは `Realtek 802.11ac NIC`（ACH）や `ALFA AWUS036AXML` / MediaTek（AXML）のように表示されるはずです。
3. クリックすると、デバイスが Kali に「引き渡され」ます。

一覧が空の場合は、パススルー層に問題があります。2.2 / 2.3 / 2.4 に戻って確認するか（USB コントローラーが有効になっていない場合も含む）、第 6 章の排障ワークシートを実行してください。

**VMware との対比**：VMware Workstation / Fusion は**追加の拡張パックなしで** USB パススルー機能を利用できますが、よくある確認ポイントが 2 つあります：

1. **ホスト側サービス**：Linux ホストでは `vmware-usbarbitrator`（USB アービトレーションサービス）が動作しているか確認してください：
   ```bash
   sudo systemctl status vmware-usbarbitrator
   # 動作していない場合は起動し、起動時に自動実行するよう設定
   sudo systemctl enable --now vmware-usbarbitrator
   ```
2. **仮想マシン設定**：仮想マシン設定 → USB Controller → **USB 3.1（または USB 3.0）** にチェックを入れます。
3. **手動接続**：VMware ウィンドウのメニュー → **リムーバブルデバイス（Removable Devices）→ アダプター → 接続（Connect）**。

> **対比のポイント**：VirtualBox は「拡張パック未インストール」で詰まります。VMware は「アービトレーションサービスが動作していない」または「USB 3.0 コントローラーがオフ」で詰まります。まずどちらを使っているか確認してから、該当する項目をチェックしてください。

## 3. 診断ツールの 3 ステップ：lsusb → iwconfig → dmesg

パススルー設定が完了したら、3 つのコマンドで問題を「パススルー層」か「ドライバー層」かに切り分けます。

### ステップ 0：まずホスト側でハードウェアを確認する（アダプターのせいにしない）

**ホスト OS** でターミナルを開いて実行します：

```bash
lsusb
```

期待される出力（モデルによる）：

```
# AWUS036ACH（Realtek RTL8812AU）
Bus ... ID 0bda:8812 Realtek Semiconductor Corp. RTL8812AU 802.11a/b/g/n/ac 2T2R DB WLAN Adapter
# または AWUS036AXML（MediaTek MT7921AU）
Bus ... ID 0e8d:7961 MediaTek Inc. Wireless_Device
```

- ホストで認識される → ハードウェアとケーブルは正常です。問題はパススルーか Guest のドライバーにあります。
- ホストでも認識されない → **まずホスト側を確認**（USB ポートを変える、ケーブルを変える、別のマシンでクロステスト）してから、技術サポートのチケットを検討してください。

### ステップ 1：Guest 側の lsusb——パススルーは成功したか？

**Kali 仮想マシン内**で実行します：

```bash
lsusb
```

- 同じ VID:PID が見える → **パススルー成功**です。ステップ 2 へ進みます。
- 見えない → **パススルー失敗**です。第 2 章（Extension Pack / コントローラー / vboxusers グループ）に戻って確認するか、アダプターがホストの他のソフトウェアに占有されていないか確認してください。

### ステップ 2：iwconfig / ip link——ワイヤレスインターフェースは現れたか？

```bash
iwconfig
# または（新しいバージョン）
iw dev
ip link
```

- `wlan0` / `wlx...` インターフェースが現れる → **すべて接続完了**です。使用を開始できます。
- ワイヤレスインターフェースがないが `lsusb` では見える → 問題は **Guest のドライバー層**にあります。ステップ 3 へ進みます。

### ステップ 3：dmesg——ドライバー層はなぜ失敗したのか？

```bash
# カーネルの直近のメッセージを確認
sudo dmesg | tail -30
# USB とワイヤレス関連のメッセージをフィルタリング
sudo dmesg | grep -iE "usb|wlan|8812|mt7921|rtl" | tail -30
```

よくある `dmesg` の結果と対比：

| `dmesg` メッセージ | 原因 | 対処方法 |
|-------------------|------|---------|
| `usb 3-1: new high-speed USB device ...` の後に続きがない | デバイスの列挙は完了したが、利用可能なドライバーがない | Guest 内に対応するドライバーをインストール（FAQ Q4 参照） |
| `Direct firmware load failed` / `firmware_loading` | ファームウェア（firmware）ファイルがない | `apt install firmware-realtek` を実行してからモジュールを再読み込み |
| `Required key not available` | Secure Boot が有効で、モジュールが署名されていない | MOK キーで署名（Secure Boot は無効にしないでください） |
| `disagrees about version of symbol` | ドライバーのバージョンがカーネルと一致しない | DKMS で再コンパイルしてインストール |

> **重要な理解**：`lsusb` で見えるのは「USB パススルーは成功した」ことの証明にすぎず、**ドライバーが読み込まれたことを意味しません**。「パススルーは成功したのに wlan がない」というよくあるケースは、まさに Guest 内に対応するドライバーがないことが原因です。

## 4. USB VM Filter：挿すだけで自動マウント + 切断トラブル

### 4.1 なぜ USB フィルター（USB Filter）を設定するのか？

手動マウント（第 2 章 2.5）の問題は、**Kali 仮想マシンを再起動するたびに再度クリックしなければならない**ことです。「USB フィルター」を設定すると、アダプターを挿した瞬間（または仮想マシンの起動時）に、VirtualBox が**条件に一致するデバイスを自動的に Guest へ転送**します。

設定方法（VirtualBox）：

1. 仮想マシン設定 → USB → 右側の **「＋」でフィルターを追加 → アダプターを選択**。
2. VirtualBox がフィルタールールを自動入力します（ベンダー ID / プロダクト ID / シリアル番号などのフィールド）：
   - **名前（Name）**：例 `ALFA AWUS036AXML` または `AWUS036ACH`
   - **ベンダー ID（Vendor ID）**：AWUS036ACH は `0bda`、AWUS036AXML は `0e8d`
   - **プロダクト ID（Product ID）**：AWUS036ACH は `8812`、AWUS036AXML は `7961`
3. 同じモデルのアダプターを複数持っている場合は、「シリアル番号（Serial Number）」フィールドも入力して、別のアダプターに誤ってフィルターがかからないようにします。

> ヒント：フィルターを右クリック → **フィルターの編集**で、Vendor ID と Product ID だけを残す（緩いマッチ）か、シリアル番号を追加する（正確なマッチ）かを選べます。

### 4.2 頻繁な切断：多くは給電またはコントローラーの問題

高電力アダプター（AWUS036ACH はモニターモード／インジェクション時に瞬間電流が高く、AWUS036AXML は USB 3 仕様）は、仮想マシン内で「使用中にデバイスが落ちる／切断される」ことがあります。典型的な原因と対策は次のとおりです：

| 現象 | 原因 | 対策 |
|------|------|------|
| パススルー後に給電不足で落ち続ける | 仮想 USB コントローラーのエミュレートする給電能力が控えめ、またはホストのポートの給電が不足 | ホスト側で**マザーボード背面の USB ポート**または独立給電の USB Hub を使用 |
| アダプターが現れたり消えたりする | ホストの **USB 省電力（autosuspend）** がデバイスをスリープさせた | ホスト設定で「そのデバイス」の USB 自動スリープを無効化（システム全体のセキュリティ保護は無効にしないでください） |
| マウントすると即失敗、error code の羅列 | コントローラーの選択ミス（USB 1.1/2.0 では USB 3 デバイスを支えられない） | 「USB 3.0 (xHCI) Controller」に変更してシャットダウン後に再起動 |
| ホストのスリープ（sleep）から復帰後にアダプターが使えない | ホストのスリープ中に Hypervisor の USB リダイレクトが切断された | 使用中はホストのスリープを避ける；または復帰後に一度マウントし直す |

### 4.3 セキュリティ上の注意

デバイスが落ちるのを減らすために、**単一の USB デバイス**の自動スリープを無効化することはできますが、これは「そのデバイス」レベルに限られます。手間を省くためにシステムレベルのセキュリティ保護（ファイアウォール、Secure Boot）を無効化するのは**やめてください**。釣り合わない代償を払うことになります。

## 5. macOS ホストの制限とプラットフォームの境界線

### 5.1 macOS ホストの USB パススルーには先天的な制限がある

macOS ホストから仮想マシンを実行して USB パススルーを行うのは、**最も詰まりやすい組み合わせ**です。まず自分の状況を確認してください：

| macOS ホスト | VirtualBox | VMware Fusion |
|-------------|-----------|---------------|
| **Apple Silicon（M1/M2/M3/M4）** | ⚠️ **USB パススルーのサポートが制限／不完全**です。公式に公表されている既知の制限の 1 つで、アダプターのドライバーが正常でも、パススルー層がそもそも使えない可能性があります | ⚠️ サポートはより完全ですが、まず「ホストに直接挿して」macOS 側でアダプターが正常か確認することをお勧めします |
| **Intel（Intel Mac）** | ✅ 使用可能ですが、まず**カーネルエクステンション（Kernel Extension）の承認**フロー（システム設定 → プライバシーとセキュリティ → Oracle 関連のカーネルエクステンションを許可）を完了し、バージョンが完全に一致する Extension Pack をインストールする必要があります | ✅ 使用可能 |

**推奨**：ホストが macOS の場合は、「ホストに直接挿す → `system_profiler SPUSBDataType` → ホスト側でアダプターが正常か確認」をすべての排障の第一関門にしてください。**macOS 側でサポートされていないモデルを仮想マシンの排障リストに持ち込まないでください**。多くの時間を無駄にします。

### 5.2 プラットフォームの境界線（Support Boundary）

| プラットフォーム | サポート状況 | 説明 |
|----------------|-------------|------|
| Windows ホスト + VirtualBox / VMware + Kali Guest | ✅ サポート | 本章のすべての手順が適用されます |
| Linux ホスト + VirtualBox / VMware + Kali Guest | ✅ サポート | vboxusers グループ（VB）と vmware-usbarbitrator サービス（VMware）を忘れずに |
| **macOS（Apple Silicon）** + VirtualBox | ⚠️ **USB パススルー制限あり** | VMware Fusion への変更、または Linux／Windows ホストの使用を推奨 |
| macOS（Intel）+ VirtualBox | ✅ サポート | カーネルエクステンションの承認 + バージョン一致の Extension Pack が必要 |
| **Guest が macOS** | ❌ 非推奨 | 本記事は Kali / Debian / Ubuntu などの Linux Guest を前提としています |

> **サポート境界**：排障の際は必ず「ホスト側でアダプターが正常か」を先に確認してから、仮想マシン設定の問題を検討してください。ホスト側自体がアダプターを認識できない場合、どの仮想マシン設定でも復旧できません——その場合の次のステップはホスト側のドライバー問題です（当サイトの他のドライバー排障記事を参照してください）。

## 7. よくある質問（FAQ）

**Q1：USB ポートを変えたら `lsusb` で表示されなくなりました。アダプターの故障でしょうか？**
故障とは限りません。まず「充電専用」ポートに挿していないか、ホストが省電力のためにデバイスをスリープさせていないかを確認してください。マザーボード背面の通常の USB ポートに挿し直すか、一度抜いて挿し直せば、多くの場合は復旧します。

**Q2：VM ウィンドウ右下の USB アイコンが空です。どうすればよいですか？**
次の順に確認してください：① Extension Pack のバージョンが VirtualBox と完全に一致しているか；② Linux ホストで `vboxusers` グループに所属しているか（再ログインが必要です）；③ ホスト側の `lsusb` でアダプターがまだ認識されているか；④ 他のソフトウェア（ホスト側のドライバーツールなど）がデバイスを占有していないか。

**Q3：USB フィルターを設定したら、ホスト側でアダプターが使えなくなりました。正常ですか？**
正常です。Guest にパススルーすると、デバイスの制御権は Guest 側に移り、ホスト側では同時に使用できません。ホストで他の作業に使いたい場合は、VM ウィンドウの USB アイコンから「リリース（release）」してホストに戻してください。

**Q4：Guest 内の `lsusb` では認識されるのに wlan インターフェースがありません。どのドライバーを入れればよいですか？**
チップセットによります：
- **AWUS036AXML（MediaTek MT7921AU）**：カーネル内蔵の `mt7921u` ドライバーを使用し、Kernel 5.18+ ならプラグアンドプレイで動作します。まず `apt install linux-firmware` が更新されているか確認してください。
- **AWUS036ACH（Realtek RTL8812AU）**：カーネル外（out-of-tree）ドライバーのため、コミュニティ保守の `aircrack-ng/rtl8812au` をインストールし、DKMS でコンパイルする必要があります（Secure Boot の MOK 署名にも対応してください。Secure Boot は無効にしないでください）。

**Q5：USB 3.0 コントローラーを選んだら、Guest が起動できなくなりました。なぜですか？**
一部の古い Guest カーネルは xHCI のサポートが不十分です。Kali が古いバージョンの場合は、「シャットダウン → USB 2.0 (EHCI) Controller に戻す → 起動 → カーネルをアップグレード → USB 3.0 に戻す」の順でお試しください。Kali はできるだけ最新版を維持してください。xHCI のサポートがより完全になります。

**Q6：アダプターは実機では速いのに、仮想マシン内では遅くなります。正常ですか？**
正常です。仮想マシン内のアダプター性能は「USB エミュレーション層を経由した転送」とほぼ同等で、実機に直接挿した場合より多少のオーバーヘッドが加わります。正しい USB 3.0 (xHCI) コントローラーと新しい Hypervisor を使えば、そのオーバーヘッドを最小限に抑えられます。性能が著しく低下する場合は、まずコントローラーが USB 1.1 のままになっていないか確認してください。

## 8. 結論とハードウェアの推奨

「仮想マシンが外付けアダプターを認識しない」ケースの 9 割以上は、**パススルー設定**または**Guest のドライバー**が原因で、ハードウェアの故障はむしろまれです。本記事の手順を順番に実行してください：

1. **ホスト側の `lsusb` でまずハードウェアに問題がないか確認します。**
2. **VirtualBox には必ずバージョン一致の Extension Pack をインストール**し、Linux ホストでは `vboxusers` グループに参加します。VMware では `vmware-usbarbitrator` サービスが動作しているか確認します。
3. **USB コントローラーを USB 3.0 (xHCI) に設定**し、USB フィルターでアダプターを自動マウントさせます。
4. **Guest 内で `lsusb → iwconfig / ip link → dmesg` の順に層を特定**し、ドライバーが不足していれば補います。アダプターの故障を推測するのはやめましょう。

**推奨ハードウェア**：ALFA AWUS036AXML（MediaTek MT7921AU）は、新しいカーネルの Kali では**カーネル内蔵ドライバーでプラグアンドプレイ**動作し、仮想マシンでのパススルー後に最も手間がかかりません。ALFA AWUS036ACH（Realtek RTL8812AU）も同様に使えますが、Guest 内で DKMS によりコミュニティドライバーをコンパイルし、Secure Boot の署名を処理することを忘れないでください（当サイトの RTL8812AU DKMS 排障記事を参照できます）。どちらも、ホスト側で独立給電の USB ポート／Hub を使用し、「デバイスが落ちる」という変数を一度に排除することをお勧めします。

**次のステップ**：第 6 章の排障ワークシートを Kali 仮想マシンのデスクトップに保存しておきましょう。「アダプターを認識しない」たびに、まず一通り実行してから技術サポートのチケットを開くかどうか決めてください——表に従って進めれば、データがすべてを解決します。
