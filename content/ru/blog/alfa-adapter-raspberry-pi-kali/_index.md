Ноутбук с Kali Linux — стандартная рабочая станция для пентестинга, но далеко не единственный вариант. Raspberry Pi 4 или Pi 5 в сочетании с адаптером ALFA USB WiFi даёт компактную, бесшумную платформу с пассивным охлаждением: помещается в карман куртки, работает от USB-C повербанка и может оставаться без присмотра в целевой среде часами. Образы Kali Linux ARM64 поставляются непосредственно от Offensive Security и работают на Pi 4 и Pi 5 без эмуляции — с полным набором инструментов: Aircrack-ng, Kismet, Wireshark, Bettercap и остальными стандартными мета-пакетами Kali.

Главная проблема — драйвер. Чипсет RTL8812AU в AWUS036ACH и AWUS036ACM не входит в основное ядро, поэтому нельзя просто подключить адаптер и ожидать его работы. Необходимо скомпилировать драйвер под работающее ARM64-ядро — причём флаги компиляции отличаются от x86-64. Это руководство проведёт вас через каждый шаг.

## Рекомендуемое оборудование

Не каждая комбинация модели Pi, адаптера и блока питания работает надёжно. В таблице ниже отражено то, что проверено в работе, и ожидаемые компромиссы.

| Компонент | Рекомендуется | Примечания |
|---|---|---|
| Одноплатный компьютер | Raspberry Pi 5 (4 ГБ или 8 ГБ) | Pi 4 (4 ГБ+) работает хорошо; Pi 3B+ слишком медленный для захвата в реальном времени |
| Основной адаптер | ALFA AWUS036ACH | Чипсет RTL8812AU; лучшая поддержка ARM-драйвера; двухдиапазонный AC1200 |
| Альтернативный адаптер | ALFA AWUS036ACM | Вариант RTL8812AU; аналогичная поддержка; чуть меньшее энергопотребление |
| Адаптер WiFi 6 | ALFA AWUS036AXM или AXML | Чипсет MT7921U; в ядре с версии 5.18; требует firmware-misc-nonfree |
| USB-хаб | Питаемый USB 3.0 хаб | AWUS036ACH потребляет ~500 мВт; без хаба возможна просадка напряжения на Pi |
| Хранилище | MicroSD 32 ГБ+ (Class 10 / A2) | Карты A2 заметно быстрее при загрузке и операциях apt |
| Блок питания | Официальный USB-C БП для Pi (≥ 3 А) | Сторонние адаптеры — частая причина проблем со стабильностью |

{{< alert "triangle-exclamation" >}}
AWUS036ACH — устройство USB с высоким током потребления. Прямое подключение к Raspberry Pi 4 или Pi 5 без питаемого USB-хаба может привести к троттлингу или перезапуску Pi под нагрузкой. Всегда используйте питаемый хаб при работе AWUS036ACH совместно с другими USB-периферийными устройствами.
{{< /alert >}}

## Установка Kali Linux ARM64 на Raspberry Pi

### Загрузка ARM-образа

Kali Linux поддерживает официальные ARM64-образы для Raspberry Pi по адресу [https://www.kali.org/get-kali/#kali-arm](https://www.kali.org/get-kali/#kali-arm). Загрузите образ с пометкой **Raspberry Pi 4 (64-bit)** или **Raspberry Pi 5 (64-bit)**. Не используйте 32-битный образ — для шагов компиляции драйвера в этом руководстве необходимо ядро ARM64.

### Запись на MicroSD

Можно записать с помощью GUI-инструмента Raspberry Pi Imager или `dd` из командной строки:

```bash
# Замените /dev/sdX на фактическое устройство SD-карты (проверьте с lsblk)
sudo dd if=kali-linux-2025.1-raspberry-pi-arm64.img of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

В Raspberry Pi Imager: выберите **Использовать пользовательский образ** → выберите файл Kali `.img.xz` → выберите SD-карту → запись.

### Первый запуск и начальная настройка

Вставьте SD-карту, подключите монитор и клавиатуру (или сначала настройте headless-доступ) и включите питание. Учётные данные по умолчанию:

- **Имя пользователя:** `kali`
- **Пароль:** `kali`

После входа запустите `kali-tweaks` и следуйте подсказкам для усиления конфигурации по умолчанию. Затем полностью обновите систему перед работой с драйверами:

```bash
sudo apt update && sudo apt full-upgrade -y
sudo reboot
```

{{< alert "circle-info" >}}
Если планируете подключаться к Pi по SSH, включите SSH до первой загрузки, поместив пустой файл с именем `ssh` в раздел `/boot` SD-карты. Это тот же механизм, что используется в стандартной Raspberry Pi OS.
{{< /alert >}}

## Установка драйвера RTL8812AU на Kali ARM64 (AWUS036ACH / ACM)

Драйвер RTL8812AU не включён в основное ядро Linux. На ARM64 необходимо либо компилировать из исходников, либо установить версию DKMS, упакованную Kali. Оба пути описаны ниже — начните с пакетного подхода и переходите к ручной сборке только при несовместимости версий ядра.

### Вариант 1: Пакет Kali (рекомендуемый отправной пункт)

Kali Linux поставляет DKMS-упакованную версию драйвера RTL8812AU, которая автоматически перекомпилируется при обновлении ядра.

```bash
sudo apt install realtek-rtl88xxau-dkms
```

После установки перезагрузитесь и убедитесь, что модуль загружен:

```bash
sudo modprobe 88XXau
ip link show
```

Если вы видите интерфейс `wlan1` (при условии, что `wlan0` — встроенный адаптер Pi), драйвер работает. Этот пакет может отставать от версии на GitHub на несколько недель, но это наиболее простой стартовый вариант.

{{< alert "circle-info" >}}
Пакет Kali обычно достаточен для большинства ARM64-конфигураций. Переходите к ручной сборке ниже только если пакет DKMS не компилируется под вашу текущую версию ядра, которую можно проверить командой `uname -r`.
{{< /alert >}}

### Вариант 2: Ручная сборка из исходников (ARM64)

Если пакет DKMS не работает — чаще всего потому, что ядро новее последней протестированной версии пакета — соберите напрямую из форка Aircrack-ng на GitHub. Это официальный источник поддержки ARM64.

```bash
sudo apt update
sudo apt install -y build-essential dkms git linux-headers-$(uname -r)

git clone https://github.com/aircrack-ng/rtl8812au.git
cd rtl8812au

# Переключить флаги платформы с x86 на ARM64
sed -i 's/CONFIG_PLATFORM_I386_PC = y/CONFIG_PLATFORM_I386_PC = n/' Makefile
sed -i 's/CONFIG_PLATFORM_ARM64_RPI = n/CONFIG_PLATFORM_ARM64_RPI = y/' Makefile

sudo make dkms_install
```

Команды `sed` — ключевое отличие от сборки на x86-64. Без них Makefile по умолчанию использует пути платформы x86, и собранный модуль не загрузится на ARM64.

После успешной сборки загрузите модуль и проверьте:

```bash
sudo modprobe 88XXau
ip link show
```

Вы должны увидеть новый интерфейс — обычно `wlan1`. Если `ip link show` отображает интерфейс, драйвер работает корректно.

## MT7921U на Raspberry Pi (AWUS036AXM / AXML)

Чипсет MediaTek MT7921U в адаптерах AWUS036AXM и AXML включён в основное ядро начиная с версии 5.18. Образы Kali Linux ARM64 поставляются с ядром значительно выше этого порога, поэтому драйвер загружается автоматически при подключении адаптера — компиляция не требуется.

Единственный дополнительный шаг — установка проприетарной прошивки, которую требует MT7921U:

```bash
sudo apt install firmware-misc-nonfree
sudo reboot
```

После перезагрузки убедитесь, что адаптер обнаружен и интерфейс активен:

```bash
lsusb
sudo modprobe mt7921u
ip link show
```

Если `lsusb` показывает устройство MediaTek, а `ip link show` отображает новый беспроводной интерфейс, адаптер готов к работе. Поддержка режима мониторинга на MT7921U значительно улучшилась начиная с ядра 5.18, однако в некоторых тестах инъекции пакетов она может быть менее надёжной, чем у адаптеров на RTL8812AU. Для максимальной совместимости с традиционными рабочими процессами пентестинга AWUS036ACH остаётся более предпочтительным выбором.

## Включение режима мониторинга на Raspberry Pi

Raspberry Pi имеет встроенный WiFi-интерфейс (`wlan0`). Оставьте его подключённым к сети для доступа по SSH. Используйте адаптер ALFA (`wlan1`) исключительно для режима мониторинга и захвата пакетов. Никогда не переводите `wlan0` в режим мониторинга на headless-Pi — вы потеряете SSH-соединение.

```bash
# Остановить процессы, мешающие режиму мониторинга (NetworkManager, wpa_supplicant)
sudo airmon-ng check kill

# Включить режим мониторинга на интерфейсе адаптера ALFA
sudo airmon-ng start wlan1

# Убедиться, что режим мониторинга активен
sudo iwconfig wlan1mon

# Начать захват на всех каналах
sudo airodump-ng wlan1mon
```

{{< alert "circle-info" >}}
`airmon-ng start wlan1` создаёт новый интерфейс с именем `wlan1mon`. Всегда запускайте последующие инструменты против `wlan1mon`, а не `wlan1`. Имя интерфейса можно подтвердить командами `iwconfig` или `ip link show`.
{{< /alert >}}

{{< alert "triangle-exclamation" >}}
Выполнение `airmon-ng check kill` останавливает NetworkManager и wpa_supplicant. Если вы подключены по SSH через `wlan0`, это также прервёт SSH-сессию. На headless-устройствах перед выполнением этих команд подключитесь через Ethernet или второй проводной интерфейс, или используйте `tmux`, чтобы сессия сохранялась после разрыва соединения.
{{< /alert >}}

Для отключения режима мониторинга и восстановления управляемого режима:

```bash
sudo airmon-ng stop wlan1mon
sudo systemctl start NetworkManager
```

## Советы по настройке портативного пентестинга

Заставить железо работать — лишь половина дела. Следующие практические рекомендации определяют разницу между стабильным полевым комплектом и грудой бесполезных кабелей.

**Сетевая архитектура:** Используйте `wlan0` (встроенный WiFi Pi) для поддержания управляющего соединения — подключайтесь к Pi по SSH с ноутбука в той же локальной сети или точке доступа. Полностью посвятите `wlan1` (адаптер ALFA) активностям пентестинга. Никогда не смешивайте эти роли.

**Headless-работа:** Избегайте подключения клавиатуры, мыши и монитора в поле. Настройте SSH при первой загрузке и работайте со всем через терминальный эмулятор на ноутбуке. Сессии `tmux` сохраняются при переподключении, что незаменимо при нестабильной сети.

**Питание:** Используйте официальный USB-C блок питания Raspberry Pi мощностью не менее 3 А. Для AWUS036ACH добавьте питаемый USB-хаб на 2,5 А или больше. Качественный USB-C повербанк (65 Вт+) может одновременно питать Pi, хаб и адаптер в течение 4–6 часов в зависимости от нагрузки.

**Хранилище:** Записывайте логи Kismet и файлы захвата на USB SSD, а не на MicroSD-карту. MicroSD-карты имеют ограниченное число циклов записи и быстро деградируют при продолжительной записи. USB 3.0 SSD, подключённый к питаемому хабу, быстрее и долговечнее.

**Корпус:** Выбирайте корпус для Pi с открытыми USB-портами или прорезями для питаемого хаба. Алюминиевые корпуса с пассивными рёбрами охлаждения помогают управлять тепловым режимом при длительном захвате.

## Запуск Kismet на Raspberry Pi

Kismet — пассивный WiFi-сканер, работающий как фоновый сервер и предоставляющий веб-интерфейс на основе браузера. Отлично подходит для headless-развёртывания Pi: оставьте его работать и проверяйте веб-интерфейс с любого устройства в той же сети.

```bash
sudo apt install kismet

# Запустить Kismet с использованием адаптера ALFA в режиме мониторинга
kismet -c wlan1
```

{{< alert "circle-info" >}}
При передаче имени интерфейса напрямую Kismet сам переведёт его в режим мониторинга. Не нужно запускать `airmon-ng start` перед запуском Kismet. Kismet управляет жизненным циклом интерфейса самостоятельно.
{{< /alert >}}

После запуска откройте веб-интерфейс Kismet в браузере на любом устройстве в сети:

```
http://raspberrypi.local:2501
```

При первом запуске Kismet предложит создать имя пользователя и пароль администратора. После входа можно просматривать обнаруженные сети, связанных клиентов, историю уровня сигнала и GPS-данные, если подключён GPS-донгл.

По умолчанию Kismet записывает всё в файлы баз данных `.kismet` в `~/.kismet/`. Их можно экспортировать позднее для анализа или загрузки в WiGLE.

## Практический пример: Варварожинг (Wardriving)

Raspberry Pi с Kismet, адаптером ALFA и GPS-донглом — это полный автономный комплект для варварожинга, меньше и дешевле любого специализированного устройства.

**Необходимые компоненты:**
- Raspberry Pi 4 или Pi 5
- ALFA AWUS036ACH (или AWUS036ACM)
- USB GPS-донгл (чипсеты u-blox хорошо работают с Kismet)
- Питаемый USB-хаб
- USB-C повербанк (65 Вт+, с сквозной зарядкой)

**Шаги настройки:**

1. Установить Kismet и пакеты GPS:

```bash
sudo apt install kismet gpsd gpsd-clients
```

2. Настроить `gpsd` для чтения с GPS-донгла:

```bash
sudo gpsd /dev/ttyUSB0 -F /var/run/gpsd.sock
```

3. Запустить Kismet с поддержкой GPS:

```bash
kismet -c wlan1 --gps=gpsd:host=localhost,port=2947
```

4. Разместите Pi, хаб, адаптер и повербанк в сумке или корпусе и установите в автомобиль. Откройте веб-интерфейс Kismet с горячей точки телефона или планшета, подключённого к той же сети WiFi, что и Pi.

Логи Kismet фиксируют GPS-координаты для каждой обнаруженной сети. Экспортируйте базу данных `.kismet` в формат WiGLE CSV с помощью `kismetdb_to_wigle` (входит в состав Kismet) и загрузите в WiGLE для картографирования.

{{< alert "triangle-exclamation" >}}
Всегда соблюдайте местное законодательство перед проведением любой деятельности по сканированию сетей. Во многих юрисдикциях пассивное сканирование при варварожинге законно; активное зондирование или подключение к сетям без разрешения — нет. Изучите местные нормативные акты.
{{< /alert >}}
