Запустить адаптер ALFA WiFi внутри виртуальной машины не так просто, как подключить его и ждать, пока гостевая ОС обнаружит устройство. В отличие от общих папок или сетевого моста, режим мониторинга и инъекция пакетов требуют **полного управления USB** — ВМ должна эксклюзивно владеть USB-устройством, а не совместно использовать его через сетевой стек хоста. Это называется USB passthrough, и правильная настройка — самая распространённая причина сбоев для пентестеров и игроков CTF, работающих в ВМ.

Это руководство охватывает полную настройку passthrough для **VirtualBox 7.x** и **VMware Workstation 17+ / VMware Fusion 13+** с Kali Linux в качестве гостевой ОС. Рассматриваются как AWUS036ACH (чипсет RTL8812AU), так и более новый AWUS036AXML (чипсет MT7921AUN), с заметками для каждого адаптера там, где поведение различается.

По завершении ваш адаптер ALFA будет отображаться внутри Kali через `lsusb`, правильный драйвер будет загружен, и `airmon-ng` подтвердит работу режима мониторинга.

## Предварительные требования

Перед началом убедитесь, что ваша среда соответствует следующим требованиям. Отсутствие любого элемента — особенно Extension Pack для VirtualBox — является основной причиной большинства сбоев passthrough.

| Требование | Подробности |
|---|---|
| **Гипервизор** | VirtualBox 7.x + Extension Pack **или** VMware Workstation 17+ / Fusion 13+ |
| **Гостевая ОС** | Kali Linux 2024.x или новее (протестировано на 2024.1–2025.1) |
| **Адаптер ALFA** | AWUS036ACH, AWUS036AXML, AWUS036ACM или любое устройство RTL8812AU / MT7921AUN |
| **USB-порт хоста** | Рекомендуется USB 3.0 (особенно для AWUS036AXML) |
| **ОС хоста** | Windows 10/11, Linux или macOS (Fusion) |
| **Доступ Sudo** | Требуется внутри ВМ Kali |

{{< alert "circle-info" >}}
Если вы ещё не установили драйвер внутри Kali, сначала выполните шаги USB passthrough из этого руководства. Как только адаптер станет виден внутри ВМ, следуйте [Руководству по установке драйвера ALFA](/ru/blog/install-alfa-driver-kali-ubuntu/) для компиляции и загрузки правильного драйвера.
{{< /alert >}}

## USB Passthrough в VirtualBox — Пошагово

VirtualBox требует дополнительный компонент — **Extension Pack** — для поддержки USB 2.0 и USB 3.0 passthrough. Без него доступен только USB 1.1 (OHCI), что недостаточно для современных адаптеров ALFA.

### Установка VirtualBox Extension Pack

1. Откройте [virtualbox.org/wiki/Downloads](https://www.virtualbox.org/wiki/Downloads).
2. В разделе **VirtualBox Extension Pack** нажмите **All supported platforms** для загрузки файла `.vbox-extpack`. Версия должна точно совпадать с установленной версией VirtualBox.
3. Откройте VirtualBox, перейдите в **Файл → Настройки → Расширения** (на macOS: **VirtualBox → Настройки → Расширения**).
4. Нажмите значок **+**, перейдите к скачанному `.vbox-extpack` и установите. Примите лицензию при запросе.

Для проверки активности Extension Pack через командную строку:

```bash
VBoxManage list extpacks
```

Ожидаемый вывод:

```
Extension Packs: 1
Pack no. 0:   Oracle VirtualBox Extension Pack
Version:      7.0.x
...
Usable:       true
```

{{< alert "triangle-exclamation" >}}
Если поле **Usable** показывает `false`, версия Extension Pack не совпадает с версией VirtualBox. Удалите и переустановите правильную версию.
{{< /alert >}}

### Добавление пользователя в группу vboxusers (только для хостов Linux)

На хостах Linux учётная запись пользователя должна быть членом группы `vboxusers` для доступа к USB-устройствам.

```bash
sudo usermod -aG vboxusers $USER && newgrp vboxusers
```

После выполнения команды **выйдите из системы и войдите снова** (или перезагрузитесь), чтобы изменения группы вступили в силу. Проверить можно командой:

```bash
groups $USER
```

В выводе должна присутствовать `vboxusers`.

### Включение USB-контроллера в настройках ВМ

1. Выключите ВМ Kali, если она запущена.
2. Выберите ВМ, нажмите **Настройки → USB**.
3. Установите флажок **Включить USB-контроллер**.
4. Выберите **Контроллер USB 3.0 (xHCI)** из переключателей.

{{< alert "circle-info" >}}
USB 3.0 (xHCI) необходим для AWUS036AXML. Для AWUS036ACH технически достаточно USB 2.0 (EHCI), поскольку сам адаптер является USB 2.0, но использование xHCI не создаёт проблем и обеспечивает единообразие конфигурации.
{{< /alert >}}

### Добавление фильтра USB-устройства

1. В той же панели **Настройки → USB** нажмите значок **+** (Добавить фильтр USB с устройства).
2. Подключите адаптер ALFA сейчас, если он ещё не подключён. VirtualBox отобразит его в выпадающем списке.
3. Выберите устройство. Обычно оно отображается как **"Realtek 802.11ac NIC"** (AWUS036ACH) или **"MediaTek Corp. 802.11 b/g/n"** (AWUS036AXML).
4. Нажмите **ОК** для сохранения.

### Запуск ВМ и проверка через lsusb

Запустите ВМ Kali. После загрузки рабочего стола откройте терминал и выполните:

```bash
lsusb
```

Вы должны увидеть строку вида:

```
Bus 001 Device 003: ID 0bda:8812 Realtek Semiconductor Corp. RTL8812AU 802.11a/b/g/n/ac 2T2R DB WLAN Adapter
```

или для AWUS036AXML:

```
Bus 002 Device 002: ID 0e8d:7961 MediaTek Inc. Wireless_Device
```

### Загрузка драйвера

**AWUS036ACH (RTL8812AU):**

```bash
sudo modprobe 88XXau
```

При неудаче (модуль не найден) сначала установите пакет DKMS:

```bash
sudo apt update && sudo apt install -y realtek-rtl88xxau-dkms
sudo modprobe 88XXau
```

**AWUS036AXML (MT7921AUN):**

```bash
sudo modprobe mt7921u
```

### Проверка режима мониторинга

```bash
sudo airmon-ng start wlan1
sudo iwconfig wlan1mon
```

Поле **Mode** должно отображать `Monitor`.

### Распространённые ошибки VirtualBox

| Ошибка | Причина | Решение |
|---|---|---|
| «Нет доступных USB-устройств» в настройках USB | Extension Pack не установлен или версия не совпадает | Установить подходящую версию Extension Pack |
| Адаптер не захвачен / не виден в lsusb | Пользователь не в группе `vboxusers` (хост Linux) | `sudo usermod -aG vboxusers $USER`, затем выйти/войти |
| «USB-устройство занято предыдущим запросом» | Другой процесс на хосте использует устройство | Отключить и подключить адаптер заново перед запуском ВМ |
| Устройство постоянно отключается внутри ВМ | USB 3.0 контроллер отключён; ВМ использует OHCI | Переключиться на USB 3.0 (xHCI) в Настройки ВМ → USB |
| Фильтр добавлен, но устройство не захватывается автоматически | Фильтр создан до установки Extension Pack | Удалить фильтр, установить Extension Pack, добавить фильтр снова |

## USB Passthrough в VMware Workstation / VMware Fusion

VMware обрабатывает USB passthrough иначе, чем VirtualBox. Отдельное расширение устанавливать не нужно — поддержка USB 2.0 и 3.0 встроена в VMware Workstation 17+ и Fusion 13+. Основной механизм — **служба USB Arbitrator**, которая отслеживает USB-события хоста и направляет устройства в ВМ.

### Подключение адаптера через меню устройств

При подключении адаптера ALFA во время работы ВМ VMware обычно показывает всплывающее окно с запросом, какая ВМ должна владеть устройством. Если вы пропустили окно:

1. При запущенной ВМ Kali перейдите в **ВМ → Съёмные устройства** в строке меню.
2. Разверните список, найдите адаптер ALFA (например, **Realtek 802.11ac NIC**).
3. Нажмите **Подключить (Отключить от хоста)**.

### VMware Fusion (macOS)

1. Перейдите в **Виртуальная машина → USB и Bluetooth**.
2. Найдите адаптер ALFA в списке.
3. Переключите подключение на **Подключить к Linux** (или имя вашей ВМ Kali).

### Проверка и загрузка драйвера

После подключения проверьте внутри Kali:

```bash
lsusb
```

Затем загрузите подходящий драйвер, как описано в разделе VirtualBox выше.

### Проверка службы USB Arbitrator VMware

Если адаптер ALFA не отображается в меню **Съёмные устройства**, служба USB arbitrator может не работать. На хостах Linux:

```bash
sudo systemctl status vmware-usbarbitrator
```

Если остановлена:

```bash
sudo systemctl start vmware-usbarbitrator
sudo systemctl enable vmware-usbarbitrator
```

### Включение USB 3.0 в VMware

Откройте файл `.vmx` вашей ВМ Kali и подтвердите или добавьте:

```
usb_xhci.present = "TRUE"
```

{{< alert "triangle-exclamation" >}}
Для поддержки USB 3.0 (xHCI) требуется аппаратная версия VMware 14 или выше. Если ВМ была создана с более старой версией оборудования, обновите её через **ВМ → Управление → Изменить совместимость оборудования**.
{{< /alert >}}

### Распространённые ошибки VMware

| Ошибка | Причина | Решение |
|---|---|---|
| Адаптер не в меню съёмных устройств | USB arbitrator не запущен | Запустить службу `vmware-usbarbitrator` |
| Устройство подключается и сразу отключается | Драйвер ОС хоста забирает устройство обратно | Отключить драйвер WiFi адаптера на хосте или переподключить быстрее |
| «Устройство уже используется хостом» | ОС хоста захватила устройство | Отключить от хоста перед подключением в ВМ |
| Нет скорости USB 3.0 внутри ВМ | Версия оборудования ВМ < 14 или xHCI не включён | Обновить версию оборудования, добавить `usb_xhci.present = "TRUE"` в .vmx |
| Режим мониторинга не работает даже после passthrough | Неправильный или отсутствующий драйвер в Kali | Следовать [Руководству по установке драйвера](/ru/blog/install-alfa-driver-kali-ubuntu/) |

## Заметки для конкретных адаптеров

### AWUS036ACH (RTL8812AU)

AWUS036ACH — устройство **USB 2.0**, одно из наиболее протестированных в среде ВМ. Оба гипервизора — VirtualBox и VMware — надёжно работают с ним. Пакет драйвера: `realtek-rtl88xxau-dkms`. Имя модуля: `88XXau`.

### AWUS036AXML (MT7921AUN)

AWUS036AXML — устройство **USB 3.0** с поддержкой WiFi 6E, имеющее некоторые особенности в среде ВМ. **Необходимо** использовать USB 3.0 (xHCI) контроллер. Пакет прошивки: `firmware-misc-nonfree`. Ранние модели могут периодически зависать при арбитраже USB 3.0 в VirtualBox. VMware Workstation, как правило, надёжнее работает с AWUS036AXML для USB 3.0 passthrough.

Полный обзор: [Обзор AWUS036AXML WiFi 6E](/ru/blog/awus036axml-wifi-6e-review/).

### AWUS036ACM (RTL8812AU, одна антенна)

Ведёт себя идентично AWUS036ACH с точки зрения драйвера и passthrough. Используйте тот же модуль `88XXau` и те же настройки VirtualBox/VMware.

## Советы по производительности

**Отключить автоприостановку USB на хосте:**

```bash
echo -1 | sudo tee /sys/module/usbcore/parameters/autosuspend
```

**Выделить достаточно ресурсов ВМ:**
- **Минимум 2 ядра CPU** (рекомендуется 4)
- **2 ГБ ОЗУ** (4 ГБ для полного рабочего стола Kali)

**Сделать снимок ВМ перед пентест-работами.**

{{< alert "circle-info" >}}
Для сессий захвата пакетов длительностью более 30 минут рассмотрите использование USB-хаба с внешним питанием между адаптером и хостом. Это обеспечивает стабильное питание и предотвращает отключение адаптера из-за падения напряжения во время критических захватов.
{{< /alert >}}

## Честное сравнение: физическая машина vs ВМ

| Возможность | Kali на физическом железе | VirtualBox + Kali | VMware + Kali |
|---|---|---|---|
| **Поддержка драйверов** | Полная, прямая | Хорошая (с Extension Pack) | Хорошая (встроенный USB) |
| **Стабильность режима мониторинга** | Отличная | Хорошая | Хорошая–Отличная |
| **Надёжность инъекции пакетов** | Отличная | Хорошая (редкие потери кадров) | Хорошая–Отличная |
| **Время настройки** | Высокое (выделенное оборудование) | Низкое–Среднее | Низкое–Среднее |
| **Портативность** | Низкая | Высокая (снимки, мобильность) | Высокая |
| **CTF / лабораторное использование** | Избыточно | Идеально | Идеально |
| **Профессиональный пентест** | Рекомендуется | Приемлемо | Приемлемо |

## Краткий справочник по устранению неполадок

| Симптом | Наиболее вероятная причина | Решение |
|---|---|---|
| `lsusb` ничего не показывает внутри Kali | USB passthrough не настроен | Добавить USB-фильтр (VBox) или подключить через съёмные устройства (VMware) |
| «Нет USB-устройств» в настройках VirtualBox | Extension Pack отсутствует или версия не совпадает | Установить подходящий Extension Pack |
| Адаптер виден в `lsusb`, но нет интерфейса `wlan` | Драйвер не загружен | `sudo modprobe 88XXau` или `sudo modprobe mt7921u` |
| `modprobe: FATAL: Module 88XXau not found` | Пакет DKMS не установлен | `sudo apt install realtek-rtl88xxau-dkms` |
| Интерфейс появляется и исчезает | Автоприостановка USB или арбитраж VBox xHCI | Отключить автоприостановку; попробовать USB 2.0 контроллер для ACH |
| `airmon-ng` запускается, но режим мониторинга тихо не работает | Неправильный драйвер или конфликт с network manager | `sudo airmon-ng check kill`, затем повторить |
| Фильтр USB в VirtualBox не захватывает при загрузке | Фильтр добавлен до установки Extension Pack | Удалить фильтр, установить Extension Pack, добавить снова |
| VMware теряет устройство во время длительных сессий | Служба USB arbitrator VMware останавливается | Повторно включить и настроить автозапуск |
