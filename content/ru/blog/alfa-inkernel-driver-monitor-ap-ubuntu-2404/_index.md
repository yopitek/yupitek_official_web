> Это стандартное руководство по настройке сети в Linux, показывающее, как на новых версиях ядра включить режимы Monitor (мониторинг) и AP (точка доступа) на беспроводных картах ALFA через **встроенные (in-kernel) драйверы**.
> Тестовая платформа: ASUS GX10 / Ubuntu 24.04 LTS / ARM64 / kernel `6.17.0-1014-nvidia`. Все данные — это выдержки из натурной проверки совместимости продукта, выполненной Yupitek на собственном оборудовании и в собственной офисной сети Wi-Fi (SSID `YUPITEK`).
> ⚠️ **Правомерное использование**: режим Monitor допустим только для прослушивания собственных или авторизованных сетей; в режиме AP соблюдайте местные радиорегламенты. Статья не касается никаких атакующих операций против сторонних сетей.

## Коротко о главном (TL;DR)

На ASUS GX10 (ARM64 / Ubuntu 24.04 / kernel 6.17) все 9 USB Wi-Fi-адаптеров ALFA, протестированных Yupitek (тайваньский дистрибьютор ALFA Network), работают на in-kernel драйверах (`rtw88` / `rtw89` / `mt76`) без установки драйвера, включают режимы Monitor и AP по одной и той же процедуре, а iPhone 7 Plus / 15 Pro нормально подключаются к AP в 2.4G и 5G; минимальное ядро — от 4.19 до 6.17 в зависимости от карты.

- **На свежих ядрах драйверы ставить не нужно**: Realtek `rtw88` / `rtw89` и MediaTek `mt76` уже включили эти USB-чипы ALFA во встроенную поддержку; на kernel 6.17 (проверено на GX10) все 9 карт встроены, хотя минимальная версия у каждой карты своя, подключил и пользуешься — без компиляции, без DKMS.
- **Процедуры Monitor и AP одинаковы у всех трёх семейств**: вернуть интерфейс от NetworkManager → переключить в monitor через `iw` / поднять AP через `hostapd`.
- **Две ловушки совместимости**: при подъёме AP лучше отключить 802.11n (`ieee80211n=0`), а для WPA3-SAE использовать `sae_pwe=0`, иначе старые iPhone не подключатся.
- **Градация продвинутых режимов**: mesh только у `mt76`; IBSS на одном устройстве умеют `mt76` и `rtw88` (ACH), у `rtw89` не заявлен.
- **Железное правило платформы**: никогда не выполнять `airmon-ng check kill` (оборвёт сеть на GX10), работать только с внешними интерфейсами `wlx*`.

## 1. Почему «без установки драйверов» — главная тема этого поколения

Раньше при использовании USB-адаптеров Wi-Fi вроде ALFA в Linux самым частым барьером был именно драйвер. Чипы RTL8812AU, MT7610U в прежние годы не входили в mainline-ядро, и пользователю приходилось тянуть out-of-tree проекты с GitHub (например, `morrownr/USB-WiFi`, `aircrack-ng/rtl8812au`), а затем через DKMS привязывать и компилировать их под текущую версию ядра. При каждом обновлении ядра DKMS пересобирался заново; стоило компиляции провалиться — и карта попросту исчезала. Для среды дистрибьюторской проверки или обучения, где нужна стабильная эксплуатация, это была давняя головная боль.

В свежих mainline-ядрах ситуация переломилась: три больших семейства драйверов — Realtek `rtw88`, `rtw89` и MediaTek `mt76` — постепенно официально включили эти USB-чипы во встроенную поддержку. Минимальная версия ядра у каждой карты своя (см. столбец "Мин. ядро" ниже); на ядре 6.17 (проверено на GX10) встроены все девять карт из этой статьи, **распознаёт сразу при подключении — без компиляции, без DKMS**. Что ещё важнее, два самых популярных прежде out-of-tree проекта (rtl8812au от morrownr и от aircrack-ng) теперь оба перенаправляют на этот встроенный драйвер, и репорты об ошибках тоже сведены в один `lwfinger/rtw88`. Иными словами, шаг ручной компиляции драйвера на новых ядрах уже можно просто пропустить.

Сообщество `lwfinger/rtw88` по-прежнему активно поддерживает проект, непрерывно отправляя правки в upstream, и стабильность встроенного драйвера растёт вместе с ядром — пользователям больше не нужно поддерживать собственные ветки и каждый раз при обновлении упираться в провал компиляции DKMS. Для среды дистрибьюторской проверки и обучения один и тот же набор шагов можно повторно использовать на разных картах и при разных обновлениях ядра, а затраты на сопровождение заметно падают — именно поэтому статья делает акцент на «без установки драйверов».

Чипы, охваченные тестом, и соответствующие встроенные модули драйверов:

| Семейство чипов | Модель чипа | Встроенный модуль драйвера | Мин. ядро | Поколение / потоки | Представитель |
|---|---|---|---|---|---|
| **MediaTek mt76** | MT7612U | `mt76x2u` | 4.19 | Wi-Fi 5 / 2T2R | AWUS036ACM |
| **MediaTek mt76** | MT7610U | `mt76x0u` | 4.19 | Wi-Fi 5 / 1T1R | AWUS036ACHM |
| **MediaTek mt76** | MT7921AU | `mt7921u` | 5.18 | Wi-Fi 6 / 2x2 | AWUS036AXM / AXML |
| **Realtek rtw88** | RTL8812AU | `rtw88_8812au` | 6.13 | Wi-Fi 5 / 2T2R | AWUS036ACH |
| **Realtek rtw88** | RTL8811AU | `rtw88_8821au` | 6.13 | Wi-Fi 5 / 1x1 | AWUS036ACS |
| **Realtek rtw88** | RTL8821CU | `rtw88_8821cu` | 6.2 | Wi-Fi 5 / 1x1 (+BT) | AWUS036EACS |
| **Realtek rtw89** | RTL8832BU | `rtw89_8852bu` | 6.17 | Wi-Fi 6 / 2x2 | AWUS036AX / AXER |

> Если ядро вашей системы ниже минимальной версии для вашей карты (см. таблицу выше), придётся идти старым путём: установить out-of-tree драйвер через DKMS (для карт rtw88 — `lwfinger/rtw88`). Например, в Ubuntu 24.04: GA-ядро 6.8 уже содержит драйверы для ACM, ACHM, AXM, AXML и EACS; HWE 6.14 добавляет ACH и ACS. Для AX и AXER нужно ядро 6.17 и выше (например, HWE из 24.04.4). Эта статья исходит из ядра 6.17 на GX10.

## 2. Проверяем, что драйвер загружен и привязан

Прежде чем переключать любой режим, убедитесь, что карта корректно распознана, драйвер привязан, а имя интерфейса создано. На примере Realtek AWUS036ACH (`rtw88_8812au`) — четыре шага проверки.

**Шаг первый: убеждаемся, что USB-устройство перечислено.** Через `lsusb` находим USB ID (Realtek чаще `0bda:xxxx`, MediaTek чаще `0e8d:xxxx`):

```bash
lsusb | grep 0bda:8812
# Bus 004 Device 002: ID 0bda:8812 Realtek Semiconductor Corp. RTL8812AU 802.11a/b/g/n/ac 2T2R DB WLAN Adapter
```

**Шаг второй: проверяем привязку драйвера и скорость USB.** `lsusb -t` одновременно показывает привязанный driver и скорость соединения (`5000M` означает USB 3.0):

```bash
lsusb -t | grep rtw88_8812au
# |__ Port 001: Dev 002, If 0, Class=Vendor Specific Class, Driver=rtw88_8812au, 5000M
```

Для карт MediaTek можно вместо этого наблюдать сообщения инициализации драйвера через `dmesg` и заодно подтвердить переименование интерфейса:

```bash
sudo dmesg | grep mt76x0u | tail -3
# mt76x0u 3-1:1.0: ASIC revision: 76100002 MAC revision: 76502000
# mt76x0u 3-1:1.0 wlx00c0cababcd2: renamed from wlan0
```

**Шаг третий: получаем имя интерфейса.** Ubuntu использует предсказуемые имена (predictable naming), и внешние карты ALFA всегда получают `wlx` плюс MAC-адрес. Это имя определяется MAC-адресом и **не меняется после переподключения**, что удобно для скриптов. Встроенная сетевая карта для выхода в интернет носит другое имя (на GX10 это `wlP9s9`), их обязательно нужно различать:

```bash
IF=$(ls /sys/class/net | grep '^wlx' | head -1); echo $IF
# wlx00c0cabca7f5
```

**Шаг четвёртый: запрашиваем режимы интерфейса, заявленные чипом.** Этот шаг определяет, какие режимы будут доступны дальше:

```bash
iw phy $(cat /sys/class/net/$IF/phy80211/name) info | sed -n '/Supported interface modes/,/Band 1/p'
```

Realtek rtw88 (ACH) перечислит `IBSS / managed / AP / AP/VLAN / monitor`, но **без** mesh и P2P; MediaTek mt76 (ACHM) дополнительно перечислит `mesh point / P2P-client / P2P-GO`. Этот список — первоисточник различий в возможностях семейств, подробнее в разделе 5.

## 3. Включаем режим Monitor (2.4 GHz / 5 GHz)

Режим Monitor (мониторинг) позволяет карте не ассоциироваться ни с одной AP и напрямую принимать 802.11-фреймы из эфира; часто используется для диагностики пакетов в собственной сети, обхода спектра и оценки покрытия сигнала. Процедура включения одинакова у всех трёх семейств, разница лишь в нюансах стабильности отдельных семейств (см. разделы 5, 6).

**Общие шаги включения:**

```bash
IF=$(ls /sys/class/net | grep '^wlx' | head -1)
sudo nmcli dev set $IF managed no      # передаём под наш контроль, чтобы NetworkManager не вмешивался
sudo ip link set $IF down
sudo iw dev $IF set type monitor
sudo ip link set $IF up
iw dev $IF info | grep type
# type monitor
```

Если видите `type monitor` — переключение прошло успешно. Дальше указываем канал для мониторинга. Для **2.4 GHz** используем `set channel`:

```bash
sudo iw dev $IF set channel 6
sudo timeout 8 tcpdump -i $IF -c 300 -w /tmp/mon-ch6.pcap
tcpdump -r /tmp/mon-ch6.pcap | wc -l
```

Для **5 GHz** задание частотой менее подвержено ошибкам (ch36 = 5180 MHz):

```bash
sudo iw dev $IF set freq 5180
sudo timeout 8 tcpdump -i $IF -c 300 -w /tmp/mon-ch36.pcap
tcpdump -r /tmp/mon-ch36.pcap | wc -l
```

**Ожидаемый результат (выдержка из тестов):** AWUS036ACH на ch1 / ch6 / ch11 поймала соответственно 92 / 214 / 71 фрейм; на 5 GHz ch36 / ch149 / ch157 — соответственно 260 / 137 / 127 фреймов, то есть мониторинг и в 2.4G, и в 5G работает нормально. MediaTek ACHM при сканировании со сменой частот через `airodump-ng --band abg` в течение 120 секунд нашла в полосе ch1/5/6/36/149/157 19 базовых станций и 14 клиентов. Если на каком-то канале поймано 0 пакетов — обычно это просто значит, что в данный момент на этом канале нет AP, а не поломка карты.

После переключения в monitor стандартные диагностические инструменты работают прямо на интерфейсе `wlx*`: `airmon-ng` показывает карты и статус драйверов, `kismet` можно использовать как источник данных для перехвата в реальном времени с генерацией лога `.kismet`, `Wireshark` и `tshark` разбирают захваченные пакеты, а `bettercap` обходит каналы. Все эти инструменты протестированы и работают на всех трёх семействах — ими удобно инвентаризировать загрузку каналов и покрытие сигнала в собственном беспроводном окружении. Единственное, на что обратить внимание: `hcxdumptool` 8.x на этой платформе даёт `failed to arm` на всех трёх семействах, кроме EACS в 2.4 ГГц (встроенные драйверы не предоставляют active-monitor), и если нужна похожая функциональность — переходите на `airodump-ng` вместе с пакетом aircrack-ng.

> **Замечание по 5 GHz:** в regdomain по умолчанию (`country 00`) многие каналы 5 GHz помечены как passive/no-IR — слушать можно, но активная передача ограничена. Если дальше нужно вести тестирование на 5 GHz в рамках авторизации, сначала разблокируйте через `sudo iw reg set US`, а по окончании верните `sudo iw reg set TW`. У Realtek `rtw88_8812au` есть известный эффект 5G RX-stuck (после многократного переключения режимов 5G перестаёт принимать пакеты) — при его появлении один раз физически переподключите карту и в первую очередь выполняйте работу по 5G.

## 4. Включаем режим AP / точки доступа (2.4 GHz / 5 GHz)

Режим AP (точка доступа) превращает карту в Wi-Fi-базу через `hostapd`. Процедура одинакова у всех трёх семейств: сначала передаём интерфейс от NetworkManager, затем запускаем его с одним конфигом `hostapd`. Ниже — универсальная минимальная конфигурация.

**4-1. 2.4 GHz (чистый 802.11g)**

Создаём конфиг `/tmp/ap24.conf`:

```ini
interface=wlx00c0cabca7f5
driver=nl80211
ssid=ALFA-AP-24G
hw_mode=g
channel=6
country_code=TW
auth_algs=1
ieee80211n=0
wpa=2
wpa_key_mgmt=WPA-PSK
rsn_pairwise=CCMP
wpa_passphrase=<ваш пароль, минимум 8 символов>
```

Запуск:

```bash
sudo nmcli dev set $IF managed no
sudo hostapd /tmp/ap24.conf
```

Когда клиент подключается, `hostapd` последовательно выводит `authenticated` → `associated` → `AP-STA-CONNECTED` → `EAPOL-4WAY-HS-COMPLETED`; последняя строка означает, что четырёхстороннее рукопожатие завершено и подключение успешно.

**4-2. 5 GHz (чистый 802.11a, ch36)**

Меняем конфиг выше на 5 GHz:

```ini
ssid=ALFA-AP-5G
hw_mode=a
channel=36
```

Карты 2x2 (например, rtw89 AX/AXER, mt76 ACM/AXM) можно дополнить настройкой VHT80 и выйти на полосу 80 MHz; при одной антенне или когда важна совместимость, оставьте чистый 20 MHz a.

**4-3. Две ключевые настройки совместимости**

1. **При подъёме AP лучше отключить 802.11n** (`ieee80211n=0`, работать на чистом g / чистом a). На практике старый клиент (iPhone 7 Plus) при сохранённом `ieee80211n=1` проваливает ассоциацию и показывает ошибочное сообщение «неверный пароль», хотя на деле это `handle_assoc_cb: STA not found`; стоит убрать 802.11n — и он подключается с первого раза.
2. **Для WPA3-SAE используйте `sae_pwe=0`** (hunting-and-pecking). При `sae_pwe=2` (принудительный H2E) рукопожатие ключей со старыми устройствами проваливается. Пример секции WPA3:

```ini
wpa_key_mgmt=SAE
rsn_pairwise=CCMP
ieee80211w=2
sae_pwe=0
```

Обе эти ловушки одинаково встречаются и на картах Realtek, и на MediaTek — это вопрос совместимости клиента, а не различий драйверов. Девять карт из этой статьи в режиме AP на 2.4G и 5G все позволяли iPhone 7 Plus / 15 Pro нормально подключиться.

**4-4. Одновременно в интернете и в роли точки доступа (STA + AP)**

Семейство mt76 поддерживает на одной карте одновременно подключаться к существующему Wi-Fi и поднимать дополнительный AP VIF в роли ретранслятора. На практике ACHM, оставаясь подключённой к YUPITEK через главный интерфейс, одновременно поднимала точку 5 GHz, к которой подключался iPhone: загрузка всё равно держалась на 198 Mbit/s, средний ping — 3.2 ms. Для этой комбинации нужно выполнить три условия: AP VIF должен использовать другой MAC, имя интерфейса сохранять формат `wlx`, и все VIF находиться на одном канале. На картах Realtek эта комбинация не гарантируется phy (у rtw88 managed + monitor работает, но STA + AP нестабильна), поэтому для ретранслирующей точки лучше выбирать семейство mt76.

## 5. Различия и ограничения трёх семейств чипов

Базовые режимы managed / monitor / AP поддерживают и ведут себя одинаково все три семейства. Различия — в **продвинутых режимах интерфейса** (mesh, IBSS, active monitor, P2P): это полностью зависит от того, что заявляет драйвер, и не связано с числом антенн у карты. Ниже — сводка по тестам.

| Продвинутый режим | MediaTek mt76 | Realtek rtw88 | Realtek rtw89 |
|---|---|---|---|
| Monitor (2.4G/5G) | ✅ | ✅ | ✅ |
| AP (hostapd) | ✅ | ✅ | ✅ |
| Ad-hoc / IBSS (одно устройство) | 🟡 поднимается на одном устройстве | 🟡 поднимается на одном устройстве | ❌ не заявлено драйвером |
| Mesh (802.11s, одно устройство) | 🟡 поднимается на одном устройстве | ❌ `-95` не поддерживается | ❌ не заявлено драйвером |
| Active monitor | 🟡 настраивается | ❌ `-95` не поддерживается | N/A |
| Wi-Fi Direct (P2P) | нужно второе устройство | ❌ `-95` не поддерживается | N/A |

**MediaTek mt76 (ACM / ACHM / AXM / AXML)** — семейство с самой полной поддержкой продвинутых режимов. Уже `iw phy info` заявляет `mesh point`, `IBSS`, `P2P-client/GO`. На практике даже на одном устройстве удаётся `Joined IBSS`, `type mesh point` и отправка соответствующих beacon (peer link со вторым устройством не проверялся из-за отсутствия второй карты). Если ваша задача — эксперименты с mesh или IBSS на одном устройстве, семейство mt76 — первый выбор. Отдельно отметим: Wi-Fi 6 MT7921 (AXM/AXML), хоть и имеет полный набор режимов и стабильный AP, на этой платформе не способен к frame injection (основная причина — регрессия mac80211 chanctx в stock kernel 6.16+, а не врождённое свойство чипа; сообщество на тех же моделях переходит на git/patched-драйверы, и они работают, но прошивка фиксирует скорость — см. morrownr/USB-WiFi #387, morrownr/mt76 #18), и для продвинутых тестов, требующих инъекции, не подходит.

**Realtek rtw88 (ACH / ACS / EACS)** поддерживает `IBSS / managed / AP / AP/VLAN / monitor`. IBSS поднимается на одном устройстве (`Joined IBSS`, по данным теста на ACH; у EACS iftype указан, но на практике join не срабатывает), однако **mesh (802.11s), active monitor и Wi-Fi Direct все три на практике отдают `Operation not supported (-95)`**. Ещё одна особенность именно rtw88 — VIF: хотя флаги `iw phy` пишут «interface combinations are not supported», на практике у ACH два интерфейса managed + monitor поднимаются одновременно, monitor VIF поймал 100 фреймов — «быть в интернете и параллельно перехватывать» возможно; но phy эту комбинацию не гарантирует, и для долгой работы под высокой нагрузкой всё же лучше брать семейство mt76.

**Realtek rtw89 (AX / AXER)** — самое новое семейство Wi-Fi 6 в этой статье, monitor и AP (включая VHT80) показывают себя хорошо, чувствительность приёма высокая. Но в продвинутых режимах active monitor / mesh / IBSS / P2P не заявлены уже на уровне драйвера (N/A), поэтому такие эксперименты на одном устройстве проводите на картах mt76. Позиционирование rtw89 — это стабильный мониторинг и точка доступа Wi-Fi 6, а не платформа для экспериментов с продвинутыми режимами интерфейса.

> Выбор одной фразой: **нужен mesh / IBSS на одном устройстве → mt76 (ACM / ACHM); нужна точка Wi-Fi 6 и сильный приём → rtw89 (AX / AXER); нужна двухдиапазонная универсальность и VIF → rtw88 (ACH).**

## 6. Безопасность платформы (GX10 + Ubuntu ARM64)

На машинах типа GX10, где «встроенная карта отвечает за выход в интернет, а внешняя ALFA используется для тестов», следующие пункты — железные правила эксплуатации, следуя которым вы не оборвёте себе сеть.

1. **Никогда не выполняйте `airmon-ng check kill`.** Эта команда отключит NetworkManager и заодно оборвёт выход GX10 в интернет. Вся статья использует только `iw` и `nmcli dev set <интерфейс> managed no`, не трогая `check kill`.
2. **Работайте только с `wlx*`, никогда не трогайте встроенный `wlP9s9`.** `wlP9s9` — это магистраль выхода GX10 в интернет, любые действия down / смены режима допустимы только над интерфейсом ALFA `wlx*`; перед командой обязательно подтвердите цель через `echo $IF`.
3. **RX stall лечится переподключением.** Если после многократного переключения monitor / AP ничего не сканируется, чаще всего это зависший приём драйвера (особенно часто у Realtek на 5G). Программно обычно не восстановить — просто **один раз физически переподключите** карту, USB переинициализируется, а имя интерфейса сохранится, так как MAC не меняется.
4. **Комбо-карты BT+WiFi — в другой USB-порт.** У комбо-устройств с Bluetooth и Wi-Fi вроде EACS, AXML при переподключении иногда зависает WiFi probe и не создаётся интерфейс `wlx`; смена USB-порта обычно всё исправляет.
5. **Перед передачей на 5 GHz задайте regdomain.** В `country 00` по умолчанию 5 GHz в основном no-IR, активная передача запрещена. Перед тестом в рамках авторизации разблокируйте через `sudo iw reg set US`, по окончании верните `sudo iw reg set TW`.
6. **Нюансы пакетов на ARM64.** GX10 — это aarch64, у `aircrack-ng` часто нет prebuilt wheel/package, его нужно собирать из исходников; для `wifite` рекомендуется версия с GitHub, чтобы обойти конфликт зависимостей apt. Кроме того, `hcxdumptool` 8.x на этой платформе даёт `failed to arm` на всех трёх семействах, кроме EACS в 2.4 ГГц (встроенные драйверы не поддерживают active-monitor), для перехвата при мониторинге переходите на `airodump-ng` вместе с пакетом aircrack-ng.

**После завершения тестов возвращаем обычный режим:**

```bash
sudo pkill hostapd 2>/dev/null
sudo ip link set $IF down
sudo iw dev $IF set type managed
sudo ip link set $IF up
sudo nmcli dev set $IF managed yes
iw dev $IF info | grep type      # ожидается type managed
```

## Часто задаваемые вопросы (FAQ)

**Q: Как в Ubuntu 24.04 перевести карту ALFA в режим monitor?**
A: На kernel 6.17 и выше достаточно передать интерфейс из-под управления NetworkManager и переключить его в режим monitor — ставить сторонний драйвер не нужно; у всех трёх семейств драйверов из статьи (rtw88 / rtw89 / mt76) процедура одинакова, подробные команды — в шагах по тексту.

**Q: Почему в Ubuntu для карты ALFA не нужно ставить отдельный драйвер?**
A: Потому что Realtek `rtw88`/`rtw89` и MediaTek `mt76` постепенно включили эти USB-чипы во встроенную поддержку mainline-ядра (минимальная версия у каждой карты своя, от 4.19 до 6.17; в Ubuntu 24.04 для AX и AXER нужно ядро 6.17 и выше, например HWE из 24.04.4); на ядре 6.17 (проверено на GX10) встроены все 9 карт из статьи — распознаёт сразу при подключении, без компиляции и без DKMS.

**Q: Поднял точку WPA3 на карте ALFA, а старый iPhone не подключается — что делать?**
A: На практике выявлены две частые причины: первая — в hostapd `sae_pwe` нужно задать равным 0, а не 2, чтобы обеспечить совместимость со старыми iPhone; вторая — сохранённая настройка 802.11n может ломать ассоциацию старых устройств, поэтому при приоритете совместимости рекомендуется отключить 802.11n.

**Q: Какое семейство драйверов — `rtw88`, `rtw89` или `mt76` — поддерживает mesh или IBSS?**
A: В тестах семейство `mt76` (например, AWUS036ACM / ACHM) может на одном устройстве поднять mesh (802.11s) и IBSS; Realtek `rtw88` может на одном устройстве выполнить join IBSS (по данным теста на ACH), но mesh не поддерживает, а у `rtw89` даже IBSS не заявлен.
