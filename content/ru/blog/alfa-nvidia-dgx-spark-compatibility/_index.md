> 📌 Статья обновлена по результатам тестов на GX10 в ноябре 2026 года: на ASUS GX10 (Ubuntu 24.04 ARM64, ядро 6.17.0-1014-nvidia) все 9 актуальных Wi-Fi-адаптеров ALFA работают на драйверах, встроенных в ядро, — достаточно подключить адаптер, DKMS не нужен. Полные данные — в [сводной таблице тестов 9 адаптеров ALFA на ARM64](/ru/blog/alfa-9-cards-arm64-gx10-ubuntu-matrix/). Тестирование проводилось только на GX10; другие модели на GB10 по отдельности не проверялись.

## 1. Краткое описание вопроса

Вопрос клиента: «Можно ли использовать USB Wi-Fi-адаптеры серии ALFA на персональном ИИ-суперкомпьютере NVIDIA DGX Spark (GB10 Grace Blackwell)?»

Краткий вывод: DGX Spark работает под управлением NVIDIA DGX OS (на базе Ubuntu, ядро 6.x). Мы протестировали все 9 актуальных USB Wi-Fi-адаптеров ALFA на ASUS GX10 — машине на той же платформе GB10 (Ubuntu 24.04 ARM64, ядро 6.17.0-1014-nvidia): все они работают на встроенных в ядро драйверах, достаточно подключить адаптер — ни компиляция, ни DKMS не нужны. DGX Spark использует тот же GB10 и ту же линейку ядер NVIDIA, поэтому ожидается такое же поведение, но тесты проводились только на GX10 — DGX Spark отдельно не проверялся. Различия в функциях: у моделей на MediaTek MT7921 (AWUS036AXM / AXML) на стоковом ядре 6.17 не работает инъекция пакетов, при этом monitor, AP и WPA3 доступны; у остальных 7 моделей monitor и инъекция подтверждены тестами. Минимальная версия ядра, с которой драйвер каждого адаптера входит в основную ветку, различается (ACM / ACHM 4.19, AXM / AXML 5.18, EACS 6.2, ACH / ACS 6.13, AX / AXER 6.17); драйверы DKMS от сообщества нужны только на старых ядрах ниже этой версии. Примечание: все порты USB у DGX Spark — USB Type-C, а адаптеры ALFA имеют разъем USB Type-A, поэтому нужен переходник или кабель USB-C на USB-A.

Объект оценки: 9 актуальных моделей USB Wi-Fi-адаптеров ALFA (AWUS036ACM / ACHM / ACS / EACS / ACH / AX / AXER / AXML / AXM).

### 2.3 Ключевые особенности: современное ядро + ARM64

Программная среда DGX Spark влияет на совместимость с адаптерами ALFA в двух ключевых аспектах:

- Ядро 6.x (современное): ядро 6.17 (версия, на которой проводились тесты на GX10) уже содержит драйверы всех 9 адаптеров из этой статьи, включая mt76 (MT7612U / MT7610U, 4.19+), mt7921u (MT7921AUN, 5.18+), rtw88 (RTL8821CU 6.2+; RTL8812AU / RTL8811AU 6.13+) и rtw89 (RTL8832BU, 6.17+). Это резко контрастирует с ядром 4.9 на Jetson Nano.
- Архитектура ARM64 (aarch64): при использовании встроенных в ядро драйверов ничего компилировать на ARM64 не нужно; только на старых системах, где ядро ниже минимальной версии для данного адаптера, для моделей Realtek нужно компилировать драйверы DKMS от сообщества (например, серию morrownr; в Makefile должно быть задано CONFIG_PLATFORM_ARM64 = y).

Рекомендация: используйте переходник или кабель USB-C на USB-A с поддержкой USB 3.2 Gen 2×2 (20 Гбит/с), чтобы адаптеры с USB 3.x, такие как AWUS036ACH / ACM / AX, работали на полной скорости.

## 7. Подробная пошаговая настройка

### 7.1 Подготовка

**Шаг 1: включите DGX Spark и войдите в систему** (по SSH или с подключенными клавиатурой и монитором)

```bash
ssh username@<dgx-spark-ip>
```

**Шаг 2: проверьте архитектуру системы и версию ядра**

```bash
uname -m
# Ожидается: aarch64
uname -r
# Ожидается: 6.x.x (ядро DGX OS)
```

**Шаг 3: убедитесь, что версия ядра — 6.17 или выше**

Ядро 6.17 и новее уже содержит драйверы всех 9 адаптеров, инструменты компиляции устанавливать не нужно. Минимальная версия у каждого адаптера своя (ACM / ACHM 4.19, AXM / AXML 5.18, EACS 6.2, ACH / ACS 6.13, AX / AXER 6.17); только если ядро ниже этой версии, для моделей Realtek понадобятся драйверы DKMS от сообщества (см. последний абзац раздела 7.3).

### 7.2 Путь A: модели на чипах MediaTek (AWUS036ACM / ACHM / AXML / AXM) — работают сразу

**Шаг 1: подключите адаптер**

Через переходник USB-C на USB-A (AXML можно подключить напрямую в порт USB-C) вставьте адаптер ALFA в порт USB на DGX Spark.

**Шаг 2: убедитесь, что адаптер обнаружен**

```bash
lsusb
# Пример ожидаемого вывода (AWUS036ACM / MT7612U):
# Bus 001 Device 003: ID 0e8d:7612 MediaTek Inc. MT7612U 802.11a/b/g/n/ac Wireless Adapter
```

**Шаг 3: убедитесь, что сетевой интерфейс создан автоматически**

```bash
ip link show
# Ожидается интерфейс с именем на wlx (имя по MAC-адресу, встроенный драйвер загружается автоматически)
```

**Шаг 4: просканируйте сети Wi-Fi** (ниже для примера используется wlan0 — замените его на имя интерфейса из вывода `ip link show`)

```bash
sudo iw dev wlan0 scan | grep -E "SSID|signal"
```

**Шаг 5: подключитесь к Wi-Fi (через NetworkManager)**

```bash
nmcli dev wifi list
nmcli dev wifi connect "имя_вашей_сети" password "пароль_вашей_сети"
```

**Шаг 6: (необязательно) включите режим мониторинга**

```bash
sudo apt install -y aircrack-ng
sudo ip link set wlan0 down
sudo iw dev wlan0 set type monitor
sudo ip link set wlan0 up
sudo iw dev wlan0 info
```

### 7.3 Путь B: модели Realtek Wi-Fi 5 (AWUS036ACH / ACS / EACS) — на ядре 6.13+ установка не нужна (EACS — 6.2+)

**Шаг 1: подключите адаптер и убедитесь, что драйвер загрузился автоматически**

```bash
uname -r          # ACH / ACS — нужно 6.13 или выше, EACS — 6.2 или выше
lsusb
lsmod | grep rtw88
ip link show
```

Модули, которые загружаются автоматически: ACH → `rtw88_8812au`, ACS → `rtw88_8821au`, EACS → `rtw88_8821cu` (у EACS также есть Bluetooth, работа подтверждена тестами).

**Шаг 2: подключение — так же, как в шаге 5 раздела 7.2 (через nmcli)**

**Шаг 3: (необязательно) режим мониторинга и инъекция**

⚠️ Мониторинг и инъекцию проводите только в собственных сетях или в сетях, на тестирование которых получено разрешение.

```bash
sudo apt install -y aircrack-ng
IF=wlx00c0cafe0000   # замените на имя интерфейса из вывода ip link
sudo ip link set $IF down
sudo iw dev $IF set type monitor
sudo ip link set $IF up
sudo aireplay-ng --test $IF
```

- Не запускайте `airmon-ng check kill`: эта команда останавливает NetworkManager, и хост теряет внешнее подключение.
- На AWUS036AXM / AXML со стоковым ядром 6.17 команда `aireplay-ng --test` завершается неудачей (Found 0 APs), deauth и перехват handshake невозможны.
- hcxdumptool 8.x на всех 9 адаптерах, кроме EACS в 2.4 ГГц, выдает `failed to arm` (драйвер не поддерживает active monitor); используйте airodump-ng + aireplay-ng.

**Шаги, нужные только на старых ядрах (ACH / ACS — ниже 6.13, EACS — ниже 6.2)**: установите `build-essential git bc dkms` и скомпилируйте драйвер от сообщества, например morrownr/8812au-20210820 для RTL8812AU (в Makefile должно быть задано `CONFIG_PLATFORM_ARM64 = y`). Если версия ядра достаточна, используйте встроенные драйверы.

### 7.4 Путь C: модели Wi-Fi 6 (AWUS036AX / AXER, RTL8832BU) — на ядре 6.17+ установка не нужна

```bash
lsusb                      # ожидается 0bda:b832
lsmod | grep rtw89_8852bu
ip link show
```

Тесты на GX10: встроенный в ядро `rtw89_8852bu` загружается автоматически, прием в monitor сильный, инъекция работает (2,4 ГГц: AX 96%, AXER 73%), AP поддерживает 80 МГц. rtw89_8852bu входит в основную ветку ядра только начиная с 6.17, поэтому на системах с ядром 6.16 и ниже нужен драйвер DKMS от сообщества (morrownr/rtl8852bu-20250826).

## 8. Частые ошибки и их устранение

| Симптом | Возможная причина | Решение |
|---|---|---|
| lsusb не видит адаптер ALFA | Неисправный переходник USB-C / плохой контакт | Замените переходник USB-C на USB-A; убедитесь, что он поддерживает передачу данных (а не только зарядку); попробуйте другой порт USB-C |
| После подключения адаптера MediaTek нет интерфейса wlan | Модуль ядра не загрузился автоматически / отсутствует firmware | Загрузите вручную: `sudo modprobe mt76x2u`; проверьте `dmesg \| grep mt76`; установите firmware: `sudo apt install linux-firmware` |
| После подключения адаптера Realtek нет интерфейса wlan | Ядро ниже минимальной версии для данного адаптера (EACS 6.2, ACH / ACS 6.13, AX / AXER 6.17), соответствующий драйвер не встроен | Проверьте версию через `uname -r`; обновите ядро или на старом ядре установите драйвер DKMS от сообщества |
| На старом ядре после установки драйвера DKMS modprobe выдает Operation not permitted | Secure Boot / подпись модулей | Подпишите модуль или отключите Secure Boot (со встроенными драйверами эта проблема не возникает) |
| После многократного переключения monitor / AP не видно ни одного сигнала | Зависание приема (RX stall) | Отключите и снова подключите адаптер, чтобы USB-устройство заново перечислилось |
| После переподключения EACS / AXML нет интерфейса wlx | Зависание probe составного устройства Bluetooth + Wi-Fi | Подключите адаптер к другому порту USB |
| Нестабильное подключение Wi-Fi / низкая скорость | Переходник USB-C поддерживает только USB 2.0 | Замените на переходник с поддержкой USB 3.2 Gen 2×2; убедитесь, что на нем указано «Data», а не «Charge Only» |
| Конфликт встроенного Wi-Fi 7 и внешнего адаптера ALFA | Конфликт маршрутов между двумя беспроводными интерфейсами | Отключите встроенный Wi-Fi: `sudo nmcli radio wifi off` или в BIOS/UEFI; либо настройте приоритет маршрутов |
| Диапазон 6 ГГц (Wi-Fi 6E) недоступен | Ограничения регуляторного домена (Regulatory Domain) | Задайте регуляторный домен: `sudo iw reg set US` (в США диапазон 6 ГГц открыт); работа AXML на 6 ГГц подтверждена тестами, AXM не тестировался |
| Не удается запустить режим AP | Конфликт NetworkManager и hostapd | См. руководство Yopitek ALFA Soft AP; исключите интерфейс из управления NetworkManager и настройте hostapd вручную |
| Адаптер пропадает после выхода из сна | Автоматическая приостановка USB (autosuspend) | Отключите autosuspend USB: `echo 'options usbcore autosuspend=-1' \| sudo tee /etc/modprobe.d/usb.conf` |

## 9. Известные ограничения

- Нужен переходник для USB Type-C: всем адаптерам ALFA, кроме AXML, требуется переходник USB-C на USB-A, и его качество влияет на производительность и стабильность
- У моделей на MT7921 не работает инъекция: на AWUS036AXM / AXML со стоковым ядром 6.17 инъекция пакетов не работает, deauth и перехват handshake невозможны; monitor, AP и WPA3 доступны. Основная причина — регрессия mac80211 chanctx в ядрах после 6.16; исправленные драйверы от сообщества по-прежнему ограничены по скорости
- Объем тестирования: тесты проводились только на ASUS GX10 (ядро 6.17.0-1014-nvidia); DGX Spark отдельно не проверялся, ожидается такое же поведение
- hcxdumptool не работает: на всех адаптерах, кроме EACS в 2.4 ГГц, выдает `failed to arm`; используйте airodump-ng + aireplay-ng
- Возможен конфликт со встроенным Wi-Fi 7: в DGX Spark уже есть Wi-Fi 7, и при одновременном использовании встроенного и внешнего Wi-Fi возможны конфликты маршрутов или ресурсов
- Режим AP настраивается вручную: DGX OS по умолчанию настроена как среда разработки, для точки доступа нужно вручную установить и настроить hostapd / dnsmasq
- Регуляторные ограничения диапазона 6 ГГц: доступность диапазона 6 ГГц для Wi-Fi 6E зависит от настроек регуляторного домена; статус открытия 6 ГГц на Тайване уточняйте по актуальным нормам
- Старые ядра: только на системах с ядром ниже минимальной версии для данного адаптера (EACS 6.2, ACH / ACS 6.13, AX / AXER 6.17) моделям Realtek нужны драйверы DKMS от сообщества (morrownr), и после каждого обновления ядра их нужно компилировать заново
- Различия в возможностях для тестирования на проникновение: в тестах на GX10 самая высокая успешность инъекции у моделей Realtek на rtw88 (EACS и ACH — 100% в обоих диапазонах); модели MediaTek на mt76 (ACM / ACHM) работают; у MT7921 (AXM / AXML) инъекция не работает
- Bluetooth: Bluetooth у AWUS036AXML и AWUS036EACS на GX10 работает (подтверждено тестами); Bluetooth у AWUS036AXM отдельно не проверялся (в DGX Spark уже встроен BT 5.4)
- RTL8832BU (AWUS036AX / AXER): мейнтейнер драйверов morrownr ранее публично рекомендовал избегать внешних (out-of-tree) драйверов серии rtl8852/32au (источник см. в разделе 10). В этих тестах на GX10 использовался встроенный в ядро `rtw89_8852bu`: monitor, инъекция, AP и WPA3 работают; этот вывод относится только к встроенному драйверу на ядре 6.17 и новее
- RTL8812AU (AWUS036ACH): встроенный драйвер стандарта mac80211 `rtw88_8812au` включен в основную ветку ядра в версии 6.13 и стабилен начиная с 6.14 (по объявлению morrownr). В тестах на GX10 с ядром 6.17 адаптер работает сразу после подключения, инъекция — 100% в обоих диапазонах. Перед ответом клиенту служба поддержки может попросить его прислать вывод `uname -r`, чтобы убедиться, что версия ядра — 6.13 или выше

Условия опровержения: если после обновления DGX OS изменится версия ядра или драйвер USB-контроллера и поведение станет другим либо реальные тесты на DGX Spark дадут результаты, отличные от GX10, матрицу совместимости в разделе 6 нужно пересмотреть; если в будущем в ядре исправят проблему инъекции в mt7921u, оценку AWUS036AXM / AXML можно будет повысить с «Только подключение / AP».
