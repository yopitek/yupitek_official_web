## 1. Краткое резюме проблемы

Клиент спрашивает: «Могут ли USB-карты беспроводной сети серии ALFA использоваться на платформе разработки NVIDIA Jetson Nano?»

Краткий вывод: Jetson Nano может использовать большинство карт ALFA, но ключевые ограничения связаны с тем, что Linux kernel версии 4.9 в JetPack 4.x слишком стар (оценка на основе текущих 9 моделей USB-карт ALFA, из которых 3 модели готовы к использованию, 2 модели требуют дополнительной компиляции, 2 модели не проверены, 2 модели недоступны). Модели с чипами Realtek (AWUS036ACH / ACS / EACS) могут быть напрямую скомпилированы с драйверами out-of-tree, что делает их полезным выбором для Jetson Nano; модели MediaTek MT7612U / MT7610U требуют backport или самостоятельной компиляции драйвера mt76; модель MT7921AUN с Wi-Fi 6E (AWUS036AXML / AXM) не может быть использована на Jetson Nano из-за необходимости ядра 5.19+. В условиях тестирования на проникновение предпочтительнее использовать AWUS036ACH (RTL8812AU), а в условиях обычного интернет-серфинга предпочтительнее использовать AWUS036ACH (стабильный) или AWUS036ACM (требует компиляции mt76).

### 2.2 Сoftware Environment: JetPack 4.x

| Параметр | Содержание |
|---|---|
| Операционная система | Linux for Tegra (L4T), основанная на Ubuntu 18.04 LTS |
| Версия ядра | Linux 4.9 (L4T R32.x / JetPack 4.6.x) |

### 2.3 Ключевые ограничения: Kernel 4.9

Ядро 4.9 Jetson Nano является ключевым фактором для определения совместимости:

| Драйвер | Версия ядра, вошедшая в основную ветку | Возможность использования в Jetson Nano (kernel 4.9) |
|---|---|---|
| mt76x2u (MT7612U) | 4.19 | ❌ Требуется backport / самостоятельная компиляция |
| mt76x0u (MT7610U) | 4.19 | ❌ Требуется backport / самостоятельная компиляция |
| mt7921u (MT7921AUN) | 5.19 | ❌ Некорректно (разница слишком велика) |
| rtl8812au (RTL8812AU) | Never вошла в основную ветку | ✅ Можно компилировать драйвер out-of-tree |
| rtl8821cu (RTL8811CU) | Never вошла в основную ветку | ✅ Можно компилировать драйвер out-of-tree |
| rtw89 (RTL8832BU) | 5.16 (PCIe) / USB постепенно включается | ❌ Требуется самостоятельная компиляция, совместимость не известна |

### 2.4 Ограничения по питанию USB

Четыре порта USB 3.0 Type-A на платформе Jetson Nano делят между собой бюджет питания:

- При использовании DC питания (5V/4A), общее выходное напряжение портов USB составляет около 1.5A (5V)
- При использовании питания через micro-USB (5V/2A), общее выходное напряжение портов USB составляет всего около 0.5A
- ALFA высокомощная сетевая карта (AWUS036ACH) достигает пикового значения 800mA-1A
- Рекомендуется: использовать DC питание + USB 3.0 Hub с питанием, чтобы избежать недостатка питания, который может привести к разрыву соединения или перезагрузке системы

## 4. Применимые модели и чипсеты

### 4.1 Рекомендации по уровню предпочтительности

| Рекомендация по уровню | Модель (чипсет) | Объяснение |

| ⭐ Категорически рекомендуется (пробивка сетей) | AWUS036ACH (RTL8812AU) | Драйверы зрелые, поддержка Monitor Mode + Packet Injection, наиболее часто используемая ALFA сетевая карта на Jetson Nano |
| ✅ Рекомендуется (обычное интернет-соединение) | AWUS036ACH (RTL8812AU) | Двухдиапазонный AC1200, простая установка драйверов, стабильность |

### 4.2 Рекомендации по сценариям использования

| Сценарий использования | Рекомендуемая модель | Объяснение |

| Радиоконтроль / управление беспилотными летательными аппаратами | AWUS036ACH или AWUS036EACS | Стабильное соединение, низкая задержка |

## 7. Подробные шаги по настройке

### 7.1 Предварительные работы: обновление системы и среда компиляции

**Шаг 1: Запуск системы и вход через SSH в Jetson Nano**

```bash
ssh username@<jetson-nano-ip>
```

**Шаг 2: Обновление системных пакетов**

```bash
sudo apt update
sudo apt upgrade -y
```

**Шаг 3: Установка инструментов компиляции и зависимостей**

```bash
sudo apt install -y build-essential git bc libssl-dev flex bison dkms
```

**Шаг 4: Проверка версии ядра**

```bash
uname -r
# Ожидаемый вывод: 4.9.337-tegra (или类似 4.9.x-tegra)
```

### 7.2 Путь A: Модели чипов Realtek (AWUS036ACH / ACS / EACS) — рекомендуется

Пример с AWUS036ACH (RTL8812AU):

**Шаг 1: Загрузка исходного кода драйвера**

```bash
git clone https://github.com/morrownr/8812au-20210820.git
cd 8812au-20210820
```

**Шаг 2: (Дополнительное) Настройка параметров компиляции для ARM64**

Редактировать Makefile, убедитесь, что следующие настройки установлены:

```
CONFIG_PLATFORM_ARM64 = y
```

(В большинстве новых версий Makefile автоматически определяет aarch64)

**Шаг 3: Компиляция и установка**

```bash
make
sudo make install
```

**Шаг 4: Загрузка драйвера модуля**

```bash
sudo modprobe 8812au
# Или перезагрузите систему
sudo reboot
```

**Шаг 5: Вставьте сетевую карту ALFA и проверьте сетевой интерфейс**

```bash
ip link show
# Ожидаемый вывод: wlan0 интерфейс
# Если нет, проверьте dmesg
dmesg | grep -i "8812au\|rtl8812\|usb"
```

**Шаг 6: Сканирование Wi-Fi сетей (проверка функциональности)**

```bash
sudo iw dev wlan0 scan | grep -E "SSID|signal"
```

**Шаг 7: Подключение к Wi-Fi сети (используя NetworkManager / nmcli)**

```bash
# Jetson Nano по умолчанию устанавливает NetworkManager
nmcli dev wifi list
nmcli dev wifi connect "имя_вашей_wifi" password "пароль_вашей_wifi"
```

**Шаг 8: (Дополнительное) Настройка в режиме AP (для тестирования渗透ации)**

```bash
# Установите hostapd и dnsmasq
sudo apt install -y hostapd dnsmasq
# С参照ением к руководству ALFA Soft AP
# https://yupitek.com/zh-tw/blog/alfa-soft-ap-wifi-hotspot-linux-guide/
```

**Шаг 9: Включение режима мониторинга (для тестирования渗透ации)**

```bash
sudo apt install -y aircrack-ng
sudo ip link set wlan0 down
sudo iw dev wlan0 set type monitor
sudo ip link set wlan0 up
# Проверка
sudo iw dev wlan0 info
# type должен показать monitor
# Тестирование инъекции пакетов
sudo aireplay-ng --test wlan0
```

### 7.3 Путь B: Модели чипов MediaTek (AWUS036ACM / ACHM) — продвинутый

Пример с AWUS036ACM (MT7612U), необходимо backport mt76 драйвера:

**Шаг 1: Загрузка исходного кода ядра Jetson Nano**

```bash
# Загрузите исходный код ядра в зависимости от версии L4T
# Например, для L4T R32.7.4:
wget https://developer.nvidia.com/embedded/l4t/r32_release_v7.4/sources/public_sources.tbz2
tar -xjf public_sources.tbz2
cd Linux_for_Tegra/source/public
tar -xjf kernel_src.tbz2
```

**Шаг 2: Подготовка среды компиляции ядра**

```bash
cd kernel/kernel-4.9
# Создайте настройки по умолчанию
make tegra_defconfig
# Включите соответствующие параметры (menuconfig)
make menuconfig
# Перейдите к: Device Drivers > Network device support > Wireless LAN
# Выберите: <M> MediaTek MT76x2U USB support
# Выберите: <M> MediaTek MT76x0U USB support
```

**Шаг 3: Компиляция модулей ядра**

```bash
make modules_prepare
make M=drivers/net/wireless/mediatek/mt76 modules
```

**Шаг 4: Установка модулей**

```bash
sudo make M=drivers/net/wireless/mediatek/mt76 modules_install
sudo depmod -a
```

**Шаг 5: Загрузка драйвера**

```bash
sudo modprobe mt76x2u
# Вставьте AWUS036ACM
dmesg | grep mt76
ip link show
```

⚠️ Внимание: backport mt76 в ядро 4.9 может встретить ошибки компиляции, которые необходимо исправить вручную. Это продвинутая операция, рекомендуется только пользователям с опытом в компиляции ядра. Если возникают проблемы, рекомендуется использовать AWUS036ACH (RTL8812AU).

### 7.4 Путь C: Модели Wi-Fi 6 / 6E (AWUS036AX / AXER / AXML / AXM)

- AWUS036AXML / AXM (MT7921AUN): Недоступны. Ядро Jetson Nano 4.9 не может быть обновлено до 5.19+, драйвер mt7921u не может быть backport (разница слишком велика, зависит от современных ядерных инфраструктур).
- AWUS036AX / AXER (RTL8832BU): Не рекомендуется. Теоретически можно попробовать скомпилировать драйвер morrownr/rtl8852bu, но совместимость ядра 4.9 не проверена сообществом, и функции Wi-Fi 6 могут не работать корректно. Если необходимо Wi-Fi 6, рекомендуется использовать Jetson Orin Nano (JetPack 5.x, ядро 5.10+) или x86 компьютер.

## 8. Частые ошибки и методы их устранения

| Симптомы | Возможные причины | Методы устранения |
|---|---|---|
| После вставки сетевой карты dmesg не отображает никакой реакции | Недостаточное питание USB / Плохой контакт | Использование DC питания (5V/4A)；замена порта USB；использование USB Hub с питанием |
| Ошибка при компиляции 8812au с помощью make: gcc: ошибка: не распознанный параметр командной строки | Версия GCC слишком старая | Установка GCC 8: `sudo apt install gcc-8 g++-8` и указание в Makefile `CC = gcc-8` |
| modprobe 8812au сообщает о том, что необходимый ключ недоступен | Включен Secure Boot (на Jetson Nano обычно нет этой проблемы) | Проверка, что Jetson Nano не имеет включенного Secure Boot; повторная подпись модуля или отключение Secure Boot |
| Интерфейс wlan0 появился, но не удается сканировать AP | Не установлена Регуляторная зона / Отсутствует драйвера | Установка Регуляторной зоны: `sudo iw reg set TW` и проверка dmesg на наличие ошибок загрузки firmware |
| При высоком уровне мощности системы перезагружается или网卡 разрывается | Недостаточное питание USB | Использование DC питания + USB Hub с питанием; снижение уровня TX Power: `sudo iw dev wlan0 set txpower fixed 2000` |
| В режиме мониторинга aireplay-ng --test показывает "Injection is working!", но реальный атака неэффективна | Ограниченные функции драйвера для инъекций / Конфликт каналов | RTL8812AU функции инъекции доступны; проверка, что NetworkManager остановлен с помощью `airmon-ng check kill`; попытка использования другого канала |
| Фailure при компиляции mt76 backport | Разница между ядром 4.9 и современным исходным кодом mt76 слишком велика | Попробуйте использовать более старую версию mt76 (соответствующую коммиту для ядра 4.19); или используйте AWUS036ACH |
| Сетевая карта исчезает после пробуждения системы | Настройки энергосбережения USB | Отключение автоматического приостановки USB: `echo 'options usbcore autosuspend=-1' | sudo tee /etc/modprobe.d/usb.conf` |
| 5GHz от AWUS036ACH не работает | Ограничения Регуляторной зоны / Отсутствие таблицы каналов драйвера | Установка `sudo iw reg set US` (в США открыто больше каналов 5GHz); проверка, что используемый канал разрешен местными регуляциями |

## 9. Известные ограничения

- Версия ядра зафиксирована на 4.9: Jetson Nano не поддерживает JetPack 5.x, обновление ядра невозможно, что является根源所有 проблем совместимости
- MT7921AUN (Wi-Fi 6E) полностью не доступен: требует ядра 5.19+, не может быть backport в 4.9
- Чип MediaTek mt76 требует ручного backport: пользователи AWUS036ACM / ACHM должны сами компилировать модуль ядра, технический порог высок
- ⚠️ **Владельцы драйверов Wi-Fi 6 (RTL8832BU)公开建议避免使用**: владелец драйвера morrownr в своем официальном公告е明确指出, что серии rtl8852/32au «являются очень плохими драйверами, подозревается, что у чипа есть проблемы», и рекомендует пользователям Linux в текущий момент избегать использования этого чипа (источник см. в разделе 10). Это серьезнее, чем просто «несоответствие совместимости ядра 4.9 не проверено», оценка AWUS036AX / AXER в данном документе и других связанных документах должна пониматься как «не рекомендуется»而非 «можно попробовать, но это сложнее»
- Ограничения по питанию USB: 4 порта USB совместно используют около 1.5A (DC питание), высокопотенциальные сетевые адаптеры требуют использования hubs с питанием
- Производительность AP-режима: ограниченная производительность CPU Jetson Nano, при использовании USB WiFi в режиме AP, объем трафика может быть ниже ожидаемого
- Различия в функциях мониторинга / инъекции: RTL8812AU поддерживает наилучшие результаты; функции инъекции чипа MediaTek после backport в ядро 4.9 могут быть нестабильными
- Долгосрочное обслуживание: JetPack 4.x уже перешел в режим обслуживания, в будущем не будет новых функций или обновлений драйверов
- Функция Bluetooth: функция Bluetooth 5.2 AWUS036AXM на Jetson Nano не проверена (требуется поддержка BlueZ)
- Охлаждение: при длительном использовании USB WiFi с высокими мощностными параметрами, общая температура Jetson Nano может повыситься, рекомендуется установить вентилятор

Обратные условия: вышеуказанные оценки основаны на JetPack 4.6.x (ядро 4.9). Если NVIDIA в будущем выпустит поддержку JetPack 5.x для Jetson Nano (в настоящее время официально не поддерживается), или в сообществе появится стабильный backport ядра 5.x, оценка недоступности в разделе 4 должна быть пересмотрена.
