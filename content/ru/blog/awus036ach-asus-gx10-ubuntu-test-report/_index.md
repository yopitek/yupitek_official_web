## Кратко (TL;DR)

По замерам на ASUS GX10 / Ubuntu 24.04 ARM64 (kernel 6.17), AWUS036ACH работает в режиме monitor в обоих диапазонах, даёт направленную инъекцию пакетов по каждой AP 30/30 = 100% в обоих диапазонах и поднимает AP-точку доступа в обоих диапазонах (чистый 802.11g / чистый 802.11a).

- Начиная с ядра 6.13 DKMS не нужен (в этот раз Ubuntu 24.04 / ядро 6.17): rtw88_8812au встроен, адаптер определяется сразу при подключении.
- Двухдиапазонный режим мониторинга (monitor mode) доступен, направленная инъекция по точкам в обоих диапазонах даёт 30/30 = 100%.
- Сквозной WPA handshake подтверждён на практике: 19.11.2026 в дополнительном тесте на собственном iPhone 15 Pro, в 5G на ch36 перехвачен полный 4-way, экспортировано 47 hashline .22000.
- Приём в 5 ГГц может зависнуть — помогает только физическое переподключение или перезагрузка.
- На одном узле поднимается IBSS, но mesh 802.11s, active monitor и Wi-Fi Direct (P2P) не поддерживаются.

## 1. Эта карта и тестовая платформа

AWUS036ACH — USB-карта ALFA Network, позиционируемая как «двухантенная с высоким усилением»: чип Realtek RTL8812AU, характеристики — Wi-Fi 5 (802.11ac), 2T2R, двухдиапазонный AC1200. По сравнению с одноантенной AWUS036ACHM той же серии (MediaTek MT7610U, AC600) ACH за счёт двух внешних антенн с высоким усилением даёт лучший приём и более стабильную инъекцию, и это частый кандидат, когда клиенты спрашивают про «дальний monitor» и «инъекцию в обоих диапазонах».

Тестовая платформа и условия:

- Вычислительная платформа: ASUS GX10 (ARM64 / aarch64)
- Операционная система: Ubuntu 24.04 LTS
- Версия ядра: kernel 6.17.0-1014-nvidia
- Тестовое устройство: Apple iPhone 7 Plus (2.4G / 5G / WPA3 — всё измерялось на этом аппарате)
- Тестовая среда: собственная офисная сеть Wi-Fi, SSID `YUPITEK` (2.4GHz ch5 / 5GHz ch36, ch157)
- Дата теста: измерения на оборудовании 2026-11-18

На протяжении всего теста мы работаем только с интерфейсом `wlx*`, соответствующим карте ALFA, не касаемся встроенной сетевой карты GX10 для выхода в интернет и не запускаем `airmon-ng check kill` (эта команда отключает NetworkManager и оставляет хост без связи).

## 2. Железо и драйвер (чип / USB ID / in-kernel, без установки)

| Параметр | Характеристика |
|---|---|
| Модель | AWUS036ACH |
| Чип | Realtek RTL8812AU |
| USB ID | `0bda:8812` |
| Драйвер | `rtw88_8812au` (встроен в ядро, mainline ≥ 6.13) |
| Прошивка | `rtw88/rtw8812a_fw.bin` (поставляется с системой) |
| Поколение / потоки | Wi-Fi 5 (802.11ac) / 2T2R |
| Класс полосы | Двухдиапазонный AC1200 |
| Антенны | Две антенны с высоким усилением (внешние) |
| USB-интерфейс | USB 3.0 (при тесте перечисляется как 5000M) |

На ядре 6.17 GX10 ACH — это по-настоящему plug-and-play: `lsusb` опознаёт `0bda:8812`, драйвер `rtw88_8812au` привязывается автоматически, прошивка `rtw8812a_fw.bin` поставляется с системой, без компиляции и без DKMS. Для среды ARM64 это особенно важно. Многие старые out-of-tree драйверы Realtek на aarch64 приходится собирать из исходников, а два старых проекта — morrownr/USB-WiFi и aircrack-ng/rtl8812au — теперь оба перенаправляют на этот встроенный драйвер, и отчёты об ошибках сосредоточены в lwfinger/rtw88. Поэтому пользователям ядра ≥ 6.13 (включая 6.17 у GX10) больше не нужно трогать сторонний DKMS; только на старом ядре (< 6.13) потребуется отдельно ставить `lwfinger/rtw88` через DKMS. Этот upstream-проект до сих пор активно поддерживается (последний commit 2026-10-24, в нём есть исправление Bluetooth 1T1R для 8812A), а значит поддержка этого чипа в mainline продолжает обновляться — это не заброшенный старый драйвер.

Есть один нюанс подключения железа: ACH — это штекер USB-A, поэтому используйте переходник USB-C→A и подключайте напрямую в порт USB-C на GX10, по USB 3.0 (перечисление показывает 5000M). Если же подключить её после USB 2.0 хаба для клавиатуры и мыши, скорость будет ограничена и поведение USB3 не измерить.

Что касается режимов интерфейса, `iw phy` сообщает о поддержке IBSS / managed / AP / AP-VLAN / monitor, но без mesh, P2P и active-monitor — эта граница напрямую определяет часть ограничений из раздела 4.

## 3. Результаты тестов: Monitor / Injection / AP / WPA3

| Функция | 2.4 ГГц | 5 ГГц | Измеренные данные |
|---|---|---|---|
| Monitor | ✅ | ✅ | 2.4G ch1/6/11 = 92/214/71 frames; 5G ch36/149/157 = 260/137/127 frames |
| Injection (широковещательный probe) | ✅ | ✅ | `aireplay-ng --test` broadcast probe в обоих диапазонах возвращает Injection is working |
| Injection (направленная по точкам) | ✅ 30/30 = 100% | ✅ 30/30 = 100% | 2.4G по 4 точкам (включая YUPITEK); 5G по YUPITEK ch36 |
| AP (iPhone 7 Plus) | ✅ чистый 802.11g | ✅ чистый 802.11a (ch36) | 4-way handshake завершён, подключение с первого раза |
| WPA3-SAE AP | ✅ (`sae_pwe=0`) | Не тестировалось | С `ieee80211w=2`, iPhone 7 Plus подключился (проверено только в 2.4 ГГц) |

**Monitor**: в 2.4 ГГц на ch1 / ch6 / ch11 перехвачено соответственно 92 / 214 / 71 фрейм; в 5 ГГц на ch36 / ch149 / ch157 — 260 / 137 / 127 фреймов. Monitor в обоих диапазонах работает нормально, причём объём приёма в 5 ГГц даже выше, чем в 2.4 ГГц (на ch36 перехвачено 260 фреймов), что соответствует позиционированию с двумя антеннами высокого усиления.

**Injection**: это сильная сторона ACH. В 2.4 ГГц `aireplay-ng --test` сначала выполняет broadcast probe (сообщает Injection is working, Found 4 APs), затем идёт направленно по точкам, и по 4 точкам доступа, включая YUPITEK, процент ответов везде 30/30 = 100%, min/avg/max RTT около 4.9 / 39.2 / 99.0 ms, Power около -47. Инъекция в 2.4G у двухантенной ACH заметно стабильнее, чем у одноантенной ACHM. На практике не забудьте добавить `--ignore-negative-one`: это известное поведение lwfinger/rtw88 #453 — при открытом STA-интерфейсе monitor channel может сообщать `-1`, и без этого флага это ошибочно трактуется как сбой инъекции. Кроме того, по записям upstream, при инъекции под высокой нагрузкой встроенный driver иногда делает USB reset, но в этом тесте за ~90 секунд измерений такого не наблюдалось. В 5 ГГц направленная инъекция по YUPITEK (ch36) по каждой точке тоже 30/30 = 100%, средний RTT 13.6 ms, Power -69.1. Этот результат получен при условии «свежеподключённая карта + regdomain, выставленный на разрешающий TX» (детали — в замечаниях по 5G в разделе 4).

**AP**: при поднятии точки через hostapd, 2.4 ГГц на чистом 802.11g (`ieee80211n=0`), 5 ГГц на чистом 802.11a (ch36), iPhone 7 Plus подключился в обоих диапазонах с первого раза, без сбоев ассоциации; в логе видны все четыре шага authenticated → associated → AP-STA-CONNECTED → EAPOL-4WAY-HS-COMPLETED. Практический вывод: ACH подключается чище всего при настройке «отключить 802.11n, чистый g / чистый a».

**WPA3-SAE**: при поднятии SAE-only AP ключевые параметры — `sae_pwe=0` (hunting-and-pecking) вместе с `ieee80211w=2`, только тогда iPhone 7 Plus подключается; при `sae_pwe=2` подключения не будет. Это тот же подводный камень совместимости, на который наткнулась ACHM из той же серии.

## 4. Продвинутые возможности и handshake: допустимый диапазон и честные ограничения

| Продвинутая возможность | Результат | Пояснение / доказательство |
|---|---|---|
| VIF (STA + monitor одновременно) | ✅ подтверждено на практике | Основной интерфейс managed и `mon9` (monitor) одновременно up, monitor VIF за 8 секунд перехватил 100 фреймов |
| Перехват WPA handshake | ✅ сквозной (.22000) подтверждён | Инъекция в обоих диапазонах 100%; 19.11.2026 в дополнительном тесте в 5G на ch36 перехвачен полный 4-way, hcxpcapngtool экспортировал 47 hashline `.22000` |
| macchanger (смена MAC) | ✅ | Задание случайного MAC и восстановление работают нормально (нужно сначала `ip link down`) |
| Ad-hoc (IBSS) | 🟡 один узел | Одноузловой `Joined IBSS` успешен; peer link не проверялся из-за отсутствия второго устройства |
| Active monitor | ❌ | `Operation not supported (-95)` |
| Mesh (802.11s) | ❌ | `Operation not supported (-95)` |
| Wi-Fi Direct (P2P) | ❌ | `Operation not supported (-95)` |

**О возможности перехвата handshake нужно сказать ясно**: инъекция ACH в обоих диапазонах — 100%, а именно инъекция является пусковым звеном сквозного рабочего процесса «deauth собственного тестового телефона → перехват полного 4-way (M1–M4) → экспорт в hashcat `.22000` через hcxpcapngtool». 19.11.2026 в дополнительном тесте на собственном iPhone 15 Pro, в 5 ГГц на ch36, был перехвачен полный 4-way обмен и с помощью hcxpcapngtool экспортировано 47 hashline `.22000`, поэтому сквозной перехват handshake у ACH подтверждён на практике. В нашей сводной таблице 9 карт сквозной сценарий (`.22000`) подтверждён у 7 из 9 моделей: AWUS036ACM, AWUS036ACHM, AWUS036ACH, AWUS036ACS, AWUS036EACS, AWUS036AX и AWUS036AXER. Весь перехват — только в собственных или авторизованных сетях.

**VIF**: во флагах `iw phy` написано interface combinations are not supported, но на реальном оборудовании основной интерфейс managed и отдельно поднятый monitor-интерфейс `mon9` могут быть up одновременно, и `mon9` за 8 секунд перехватил 100 фреймов — то есть «выход в интернет и одновременно перехват» на ACH работает. Стоит отметить: phy эту комбинацию не гарантирует, поэтому для долгих или высоконагруженных сценариев рекомендуется серия mt76 (ACM / ACHM).

**Три ограничения, которые стоит особо отметить:**

1. **Не поддерживаются Active monitor, Mesh (802.11s) и Wi-Fi Direct (P2P)**: все три на практике возвращают `Operation not supported (-95)`. Если нужны эти три возможности, используйте карты серии mt76 (у phy ACM / ACHM заявлены mesh / P2P / active-monitor).
2. **Зависание RX в 5G (известное поведение `rtw88_8812au`)**: сразу после подключения карты 5G monitor / injection работают нормально, но после многократного переключения режимов или смены regdomain приём в 5G может зависнуть (перехватывается 0 пакетов), причём программно это не восстановить — только физическое переподключение или перезагрузка. Рекомендуем перед тестом в 5G один раз переподключить карту и выполнять пункты 5G в первую очередь. Здесь же дополним условие, при котором инъекция в 5G может уйти в эфир: при `country 00` по умолчанию весь 5G — passive / no-IR (TX запрещён), и направленная инъекция просто не уйдёт; нужно задать регуляторный домен, разрешающий TX (`iw reg set US` разблокирует ch36 / ch149, а `TW` открывает только ch149 и выше, без ch36), а после теста вернуть `TW`. При этом «свежеподключённая карта» означает физическое переподключение до переинициализации USB: в `dmesg` должны появиться `USB disconnect` и `renamed from wlan0`, а номер bus должен измениться — только тогда это засчитывается; если 5G уже завис, aireplay вернёт `No such BSSID available`.
3. **hcxdumptool на этой платформе выдаёт `failed to arm` на всех картах, кроме AWUS036EACS в 2.4 ГГц**: ему нужен active-monitor, а rtw88 / rtw89 / mt7921u его не поддерживают; для перехвата handshake используйте путь airodump-ng + aireplay-ng.

## 5. Сценарии применения и рекомендации по выбору (возврат к сводной таблице Hub)

Если вернуть ACH в контекст всей линейки, её позиционирование очевидно: две антенны с высоким усилением, инъекция в обоих диапазонах 100%, сквозной WPA handshake (.22000) подтверждён на практике — это прагматичный выбор для клиентов, которым «нужна стабильная инъекция и хотелось бы более сильного приёма».

- **Пентест (инъекция + handshake)**: первая группа выбора — AWUS036EACS / AWUS036ACH / AWUS036ACS, у всех трёх инъекция в обоих диапазонах на высоком уровне.
- **Максимальный приём / дальний monitor**: AWUS036AXER и AWUS036ACH, причём ACH сильна благодаря двум антеннам высокого усиления.
- **Нужны mesh 802.11s / active-monitor / P2P**: ACH (Realtek rtw88) этого не умеет (на практике возвращает `-95`), используйте карты на драйвере mt76 — AWUS036ACM / AWUS036ACHM; IBSS у ACH поднимается только на одном узле, peer-link не проверялся.
- **Нужна только чистая AP или обычное подключение без инъекции**: MediaTek AWUS036AXM / AXML стабильнее, но учтите, что инъекция у них на этой платформе не работает, для пентеста они не подходят.

Предостережение в одной фразе: если требование клиента именно инъекция и handshake, не выбирайте AWUS036AXM / AXML (инъекция чипа MT7921 на этой платформе на практике не работает, нельзя ни выполнить deauth, ни перехватить handshake); под такое требование ACH, напротив, надёжный кандидат. При выборе не смотрите только на цифры полосы: стабильность приёма за счёт двух антенн высокого усиления на реальной дистанции перехвата часто ощущается сильнее, чем бумажные характеристики. Решения по выбору и общие для платформы подводные камни — см. в сводной таблице Hub: [Полная матрица Monitor / Injection / AP 9 беспроводных карт ALFA на ASUS GX10 (ARM64)](/ru/blog/alfa-9-cards-arm64-gx10-ubuntu-matrix/).

## Часто задаваемые вопросы (FAQ)

**В: Нужно ли устанавливать драйвер для AWUS036ACH в Kali или Ubuntu?**
Зависит от версии ядра. В ядре Linux 6.13 и выше (в этот раз тестировали Ubuntu 24.04 / ядро 6.17) драйвер rtw88_8812au уже встроен, адаптер определяется сразу — без компиляции и без DKMS; только для ядра ниже 6.13 нужно отдельно ставить lwfinger/rtw88 через DKMS. Для Kali сначала проверьте версию ядра командой uname -r; на реальном оборудовании с Kali мы это в этот раз не проверяли.

**В: Как себя показывают режим monitor и инъекция пакетов у AWUS036ACH?**
И 2.4 ГГц, и 5 ГГц входят в режим monitor; направленная инъекция aireplay-ng по каждой точке и в 2.4 ГГц (по 4 точкам доступа), и в 5 ГГц (по YUPITEK ch36) даёт 30/30 = 100%. Перед инъекцией в 5 ГГц нужно сначала задать регуляторный домен, разрешающий передачу (например, iw reg set US): при домене country 00 по умолчанию передача в 5 ГГц запрещена, и инъекция не уйдёт в эфир.

**В: Может ли AWUS036ACH перехватывать WPA handshake?**
Да, и сквозной сценарий подтверждён на практике. Инъекция в обоих диапазонах 100%; 19.11.2026 в дополнительном тесте на собственном iPhone 15 Pro, в 5 ГГц на ch36 был перехвачен полный 4-way обмен, и с помощью hcxpcapngtool экспортировано 47 hashline формата hashcat .22000. Только в собственных или авторизованных сетях.

**В: Что делать, если при включении WPA3-точки на AWUS036ACH iPhone 7 Plus не подключается?**
В hostapd нужно задать sae_pwe=0 вместе с ieee80211w=2 — только тогда iPhone 7 Plus подключится; с sae_pwe=2 подключения не будет. Та же настройка критична и для AWUS036ACHM.

**В: Что делать, если приём в 5 ГГц на AWUS036ACH внезапно зависает (перехватывается 0 пакетов)?**
Это известное поведение rtw88_8812au: после многократного переключения режимов или смены регуляторного домена приём в 5 ГГц может зависнуть, и программно это не восстановить — помогает только физическое переподключение или перезагрузка. Рекомендуем перед тестом в 5 ГГц заново переподключить карту и выполнять пункты 5 ГГц в первую очередь.
