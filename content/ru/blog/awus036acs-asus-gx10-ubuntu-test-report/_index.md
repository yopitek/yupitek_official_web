**Кратко (TL;DR)**: по тестам Yupitek (тайваньский дистрибьютор ALFA Network), AWUS036ACS на ASUS GX10 / Ubuntu 24.04 ARM64 (kernel 6.17) не требует установки драйвера и работает в режимах monitor и AP в обоих диапазонах (AP в 5G работает, ширина канала не подтверждена); инъекция 2.4G 100%, 5G 96%, сквозной .22000 пройден, mesh / IBSS не поддерживаются.

> Эта статья — записи Yupitek о реальном тестировании совместимости и возможностей адаптера ALFA AWUS036ACS на свежей платформе Linux, предназначенные для оценки при подборе оборудования.
> Платформа тестирования: ASUS GX10 / Ubuntu 24.04 LTS / ARM64 / kernel `6.17.0-1014-nvidia`. Все данные — это выдержки из реальных тестов Yupitek, проведённых на **собственном оборудовании, в собственной офисной сети Wi-Fi** (SSID `YUPITEK`, 2.4G ch5 / 5G ch36) по отношению к **собственному тестовому смартфону** (Apple iPhone 7 Plus); MAC-адреса частично скрыты.
> ⚠️ **Заявление о законности и границах применения**: Monitor, инъекция и захват handshake выполнялись только в собственных или авторизованных сетях и на собственных устройствах; при работе в режиме AP соблюдайте местное радиочастотное законодательство. Статья посвящена возможностям, совместимости и настройке самого адаптера и **не касается каких-либо атак против чужих сетей**.

## 1. Этот адаптер и платформа тестирования

AWUS036ACS — лёгкий портативный беспроводной адаптер из линейки ALFA; чип — Realtek RTL8811AU, поколение Wi-Fi 5 (802.11ac), один пространственный поток 1x1. Его позиционирование предельно простое: компактный корпус, низкое энергопотребление, одна антенна — это карта, которую берут с собой для полевых обследований, а не тяжёлое решение для борьбы за максимальную пропускную способность или дальность. Поэтому при его оценке вопрос не в том, «насколько он быстр», а в том, «какие практические возможности при такой лёгкой спецификации остаются полностью доступны».

В этом цикле тестов он был помещён в типичный эксплуатационный сценарий: встроенный адаптер GX10 (`wlP9s9`) отвечает за выход в интернет, а AWUS036ACS подключён по USB и выполняет только тестовые задачи. При таком разделении переключение в Monitor или AP не затрагивает собственную сеть хоста. Всё время работы мы касаемся только интерфейса `wlx*`, соответствующего адаптеру ALFA, и не трогаем встроенный адаптер выхода в сеть.

| Параметр | Значение |
|---|---|
| Модель | AWUS036ACS |
| Чип | Realtek RTL8811AU (Wi-Fi 5 / 802.11ac, один поток 1x1) |
| USB ID | `0bda:0811` |
| Драйвер | `rtw88_8821au` (in-kernel, встроен в kernel 6.17) |
| Прошивка | 42.4.0 (по данным dmesg) |
| Платформа | ASUS GX10 / Ubuntu 24.04 LTS / ARM64 / kernel 6.17 |
| Тестовое устройство | Apple iPhone 7 Plus |

## 2. Оборудование и драйвер (установка не нужна)

Этот адаптер определяется на GX10 сразу при подключении, без компиляции и без DKMS. Чип RTL8811AU / RTL8821AU начиная с mainline kernel 6.13 официально включён в семейство встроенных в ядро драйверов Realtek `rtw88`; в kernel 6.17, которым оснащён GX10, уже есть модуль `rtw88_8821au`, и не нужно тянуть с GitHub никаких out-of-tree проектов. (В отличие от старых инструкций по установке: ранние материалы сайта исходили из out-of-tree драйвера `morrownr` или более старого ядра и утверждали, что требуется самостоятельная сборка через DKMS; на встроенном драйвере kernel 6.17 это больше не нужно.) Привычный раньше `morrownr/8821au-20210708` теперь переведён в статус legacy (его рекомендуют только для ядер ниже 6.13, и к тому же его установка добавляет встроенный драйвер в blacklist), так что на новых ядрах идти этим старым путём незачем. Выгода с точки зрения эксплуатации ещё ощутимее: встроенный драйвер обновляется вместе с ядром, пользователям не нужно каждому поддерживать свою ветку, и ничего не упирается в сбои сборки DKMS при каждом обновлении — один и тот же набор операций повторно работает на нескольких обновлениях ядра подряд. Прошивка поставляется вместе с системой через `linux-firmware`; в нашем тесте это 42.4.0, и её тоже не нужно ставить вручную.

Убедимся, что адаптер распознан, драйвер привязан, а интерфейс создан:

```bash
lsusb | grep -i 0bda:0811
# Bus 003 Device 004: ID 0bda:0811 Realtek Semiconductor Corp. Realtek 8812AU/8821AU 802.11ac WLAN Adapter

IF=$(ls /sys/class/net | grep '^wlx' | head -1); echo "IF=$IF"
cat /sys/class/net/$IF/phy80211/name
basename "$(readlink -f /sys/class/net/$IF/device/driver)"
# IF=wlx00c0cabce039 / phy1 / rtw88_8821au
```

Версию прошивки можно проверить через `dmesg` (в нашем тесте — 42.4.0):

```bash
sudo dmesg | grep -i 8821au
# rtw88_8821au ... Firmware version 42.4.0, H2C version 0
```

Заявленные поддерживаемые режимы интерфейса (именно они определяют, какие возможности будут доступны далее):

```bash
iw phy $(cat /sys/class/net/$IF/phy80211/name) info | sed -n '/Supported interface modes/,/Band 1/p'
# IBSS / managed / AP / AP/VLAN / monitor
```

Этот список перечисляет `IBSS / managed / AP / AP/VLAN / monitor`. Здесь важно особо предупредить: хотя IBSS в списке есть, на практике после `ibss join` команда `iw link` показывает Not connected — соединение не устанавливается; mesh, active-monitor и P2P в списке отсутствуют вовсе (подробнее в разделе 4 об ограничениях). Таково текущее состояние оборудования и драйвера RTL8811AU, и это не связано с числом антенн.

Охват диапазонов: 2.4 ГГц ch1–13 (ch14 disabled); 5 ГГц ch36–165 (из них ch52–144 помечены как radar / DFS). По умолчанию regdomain — `TW`, мощность TX: 2.4 ГГц 30 dBm, 5 ГГц UNII-1/2 23 dBm, UNII-3 30 dBm.

## 3. Реальные возможности: Monitor / инъекция / AP / WPA3

Сначала общая сводная таблица ключевых возможностей, затем разбор по пунктам. Все пункты выполнены на собственном AP YUPITEK и собственном iPhone 7 Plus.

| Возможность | 2.4 ГГц | 5 ГГц |
|---|---|---|
| Monitor (приём при мониторинге) | ✅ сильно | ✅ сильно |
| Инъекция (packet injection) | ✅ **100%** (30/30) | ✅ **96%** (29/30, нужно предварительно разблокировать reg) |
| AP (hostapd) | ✅ iPhone подключается + завершает handshake | ✅ **стабильно** (ширина канала не подтверждена) |
| AP WPA3-SAE | Не тестировалось | ✅ iPhone подключается (SAE-only + PMF) |

### 3-1. Monitor (режим мониторинга, 2.4 ГГц + 5 ГГц) ✅

После переключения в monitor на каждом из шести каналов выполнен по одному захвату фиксированной длительности — приём везде нормальный. На загруженных каналах предел захвата в 300 кадров достигается за 6 секунд:

| Канал | Захвачено кадров (frames) |
|---|---|
| ch1 / 2412 | 300 |
| ch6 / 2437 | 300 |
| ch11 / 2462 | 146 |
| ch36 / 5180 | 300 |
| ch149 / 5745 | 141 |
| ch157 / 5785 | 154 |

И в 2.4 ГГц, и в 5 ГГц приём стабилен. Для портативного адаптера с одной антенной такого качества приёма достаточно для полевого обследования каналов и диагностики пакетов. Низкое число кадров на ch11, ch149 и ch157 объясняется тем, что на этих каналах в момент измерения эфирного трафика просто было мало, а не тем, что адаптер его не принимает; на загруженных ch1, ch6 и ch36 предел в 300 кадров исчерпывается за шесть секунд, так что приём явно не является его узким местом.

### 3-2. Инъекция (packet injection) ✅

Тест направленной инъекции выполнен командой `aireplay-ng --test` по собственному AP YUPITEK. В 2.4 ГГц достигнуто 100% (30/30, `Injection is working!`), в 5 ГГц — 96% (29/30). У 5 ГГц есть нюанс настройки, который стоит учитывать: по умолчанию `reg=TW` блокирует активную передачу в части диапазонов UNII, поэтому перед тестом выполните `sudo iw reg set US` для разблокировки, а после теста верните `sudo iw reg set TW`.

```bash
# 2.4 ГГц (YUPITEK фактически на ch5 / 2432)
sudo iw dev $IF set freq 2432
sudo aireplay-ng --test --ignore-negative-one -a <YUPITEK-BSSID> $IF
# Injection is working!  30/30: 100%  Power: -60.00
```

То, что одноантенный адаптер получает 100% в 2.4 ГГц и 96% в 5 ГГц, уже говорит о весьма надёжной способности к инъекции — именно она является основой для последующего сквозного захвата handshake.

### 3-3. Точка доступа (AP, 2.4 ГГц / 5 ГГц) ✅

С помощью `hostapd` адаптер превращается в базовую станцию; во всех трёх конфигурациях iPhone 7 Plus успешно подключался и завершал 4-way handshake (`EAPOL-4WAY-HS-COMPLETED`):

- **5 ГГц (ширина канала не подтверждена)**: самая стабильная конфигурация — iPhone подключается, handshake завершается, чистое завершение через `AP-DISABLED`.
- **2.4 ГГц (WPA2-PSK)**: iPhone подключается, handshake завершается, после разрыва связи — чистое закрытие. Здесь честно отметим один случай: в предыдущем прогоне с теми же настройками после отключения STA возникала ошибка `key not allowed / Failed to set beacon parameters` с прерыванием, но при повторном тесте воспроизвести её не удалось — мы расцениваем это как эпизодический beacon re-key у rtw88_8821au, а не как устойчивый дефект. В сценариях длительных и частых переподключений всё же стоит быть внимательными либо просто перейти на AP в 5 ГГц.
- **WPA3-SAE (5 ГГц, PMF принудительно; 2.4 ГГц не тестировался)**: ключевые настройки — `wpa_key_mgmt=SAE` (чистый WPA3, без отката к WPA2), `ieee80211w=2` (принудительная Management Frame Protection), `sae_pwe=0` (совместимость со старыми клиентами). iPhone 7 Plus (iOS 15) успешно подключился по SAE. Поскольку AP работает только с SAE и не имеет отката к WPA2, успешная ассоциация означает, что рукопожатие аутентификации SAE состоялось. WPA3-SAE на стороне AP в связке RTL8811AU + rtw88_8821au работоспособен.

## 4. Сквозной handshake и ограничения

### 4-1. Сквозной захват handshake ✅

Это комплексный тест, проверяющий, можно ли по-настоящему «связать» инъекцию и захват в единую цепочку; всё выполнено на собственном AP YUPITEK, собственном iPhone 7 Plus и при наличии авторизации. Последовательность такова: monitor на целевом канале → отправка направленного deauth собственному устройству для запуска переподключения → захват полного 4-way (M1–M4) → преобразование через `hcxpcapngtool --all` в читаемый hashcat формат `.22000`.

Результат теста: `aircrack-ng` определил, что для YUPITEK получен 1 handshake, все четыре сообщения EAPOL M1–M4 присутствуют, клиент — Apple OUI (`b8:53:ac`, подтверждено, что это iPhone 7 Plus), а полученный `.22000` можно напрямую подавать в hashcat. Это означает, что AWUS036ACS обладает полноценной способностью сквозного захвата handshake.

Два практических момента стоит зафиксировать (полная пошаговая настройка — в отдельной статье):

1. **Когда в офисе на одном канале несколько AP с одинаковым именем, не фиксируйте одну точку через `--bssid`** — захватывайте весь канал, чтобы не пропустить устройство, подключённое к другой точке.
2. `hcxpcapngtool` по умолчанию строг и может выдать «not enough M1»; добавьте `--all`, и он выдаст `.22000` из полного набора M1–M4.

Все привычные инструменты Kali, используемые в этой цепочке захвата рукопожатия (handshake) — aircrack-ng, hcxtools — запускаются прямо на Ubuntu 24.04 ARM64; airodump-ng, aireplay-ng и hcxpcapngtool работают исправно.

### 4-2. VIF (виртуальный интерфейс) ✅

`iw dev $IF interface add mon9 type monitor` позволяет создать monitor-VIF и захватить 100 frames; кроме того, с помощью скрипта была построена схема «основной интерфейс подключён к YUPITEK как STA + один AP-VIF» — один чип может одновременно выступать и как STA, и как AP.

### 4-3. Честные ограничения (по результатам реальных тестов)

| Продвинутый режим / инструмент | Статус | Результат теста |
|---|---|---|
| Active monitor | ❌ не поддерживается | `iw set monitor active` → `Operation not supported (-95)` |
| Ad-hoc (IBSS) | ❌ не поддерживается | режим указан в списке, но после `ibss join` `iw link` = Not connected |
| Mesh (802.11s) | ❌ не поддерживается | `set type mp` → `-95` |
| Wi-Fi Direct (P2P) | ❌ не поддерживается | `interface add type __p2pcl` → `-95` |
| hcxdumptool 8.x | ⚠️ не удаётся arm | `failed to arm interface`: rtw88_8821au не предоставляет active-monitor; используйте airodump-ng + aireplay-ng |

Кроме того, нужно знать о двух эксплуатационных ограничениях. Один поток 1x1 определяет его теоретический потолок (HT Max RX 150 Mbps, VHT80 около 433 Mbps), так что пропускная способность изначально не является его сильной стороной. После многократного переключения между monitor / AP приём (RX) иногда ненадолго деградирует (ничего не сканируется); в этом случае помогает однократное физическое переподключение адаптера, после чего работоспособность восстанавливается — имя интерфейса определяется MAC-адресом и после переподключения остаётся прежним.

## 5. Сценарии применения и выбор (лёгкий, портативный, с подключением к Hub)

Если соотнести перечисленные возможности с позиционированием продукта, роль AWUS036ACS становится ясной: это адаптер с полным набором возможностей, но с упором на лёгкость и мобильность. Для каких сценариев он подходит?

- **Быстрое полевое обследование / портативная диагностика**: одна антенна, малый размер, низкое энергопотребление — удобно брать с собой для обследования каналов, проверки сигнала и диагностики пакетов. В связке с центральной платформой вроде GX10 портативный адаптер захватывает данные на месте, а они передаются обратно в Hub для централизованного анализа — разделение ролей чёткое.
- **Обучение и верификация**: всю основную линейку — Monitor / инъекция / AP / WPA3-SAE / сквозной handshake — он проходит полностью, что делает его подходящим для демонстраций и верификации в рамках авторизации.
- **Неподходящие сценарии**: если нужна максимальная пропускная способность, максимальная дальность либо mesh / IBSS / P2P / active-monitor — этот адаптер не тот выбор.

Лёгкость не означает урезанную функциональность. Основная линейка возможностей у него присутствует целиком; в жертву принесены лишь потолок пропускной способности и продвинутые режимы интерфейса. Так что выбор в его пользу зависит от того, что вам нужно — «носить с собой» или «выжимать максимум».

В сравнении с остальной линейкой различия в позиционировании такие:

| Потребность | Рекомендуемый адаптер | Обоснование |
|---|---|---|
| Лёгкий, портативный + полный набор основных возможностей | **AWUS036ACS** | инъекция 2.4G 100%, 5G 96%, сквозной handshake работает, одна антенна, компактность |
| Инъекция 100% в обоих диапазонах / более надёжная верификация проникновения | AWUS036EACS, AWUS036ACH | инъекция 100% в обоих диапазонах, у EACS дополнительно BT |
| Максимальный приём / дальний monitor | AWUS036AXER, AWUS036ACH | перебор каналов находит больше целей / две антенны высокого усиления |
| mesh / IBSS на одном устройстве | AWUS036ACM, AWUS036ACHM | драйвер mt76 позволяет поднять на одном устройстве (Realtek rtw88 не поддерживает) |

Выбор в одной фразе: нужна лёгкость и при этом полный набор основных возможностей — AWUS036ACS подходящий портативный вариант; нужна инъекция 100% в обоих диапазонах или более серьёзная верификация проникновения — смотрите в сторону EACS / ACH.

## Часто задаваемые вопросы (FAQ)

**Q: Нужно ли устанавливать драйвер для AWUS036ACS на Ubuntu 24.04 ARM64?**
На протестированном в статье kernel 6.17 (ASUS GX10) — нет: RTL8811AU обслуживается встроенным драйвером rtw88_8821au, адаптер определяется сразу при подключении, без компиляции и без DKMS. На более старых ядрах сначала проверьте наличие модуля командой `modinfo rtw88_8821au`.

**Q: Поддерживает ли AWUS036ACS monitor mode (режим мониторинга) и packet injection (инъекцию пакетов)?**
Да. Monitor работает и в 2.4 ГГц, и в 5 ГГц; `aireplay-ng --test` показывает инъекцию 100% (30/30) в 2.4G и 96% (29/30) в 5G (предварительно нужно снять ограничения TW командой `iw reg set US`). Active monitor не поддерживается.

**Q: Может ли AWUS036ACS захватить WPA handshake (пакеты рукопожатия) и преобразовать его в hashcat .22000?**
Да. Сквозное тестирование на собственном AP и собственном iPhone 7 Plus: направленный deauth инициирует переподключение, захватывается полный 4-way (M1–M4), затем `hcxpcapngtool --all` выдаёт .22000. Только в собственных или авторизованных сетях.

**Q: Можно ли использовать AWUS036ACS как точку доступа (AP)? Поддерживает ли он WPA3?**
Да. `hostapd` поднимает точки доступа на 2.4G и 5G (ширина канала в 5G не подтверждена), iPhone 7 Plus подключается и завершает 4-way; WPA3-SAE на 5G (SAE-only, ieee80211w=2, sae_pwe=0) также успешно подключается (WPA3 на 2.4G не тестировался).

**Q: Какие режимы AWUS036ACS не поддерживает? Работает ли hcxdumptool?**
Не поддерживаются active monitor, IBSS, mesh (802.11s), Wi-Fi Direct (P2P). hcxdumptool 8.x выдаёт failed to arm interface — используйте вместо него airodump-ng + aireplay-ng. Для mesh / IBSS выбирайте AWUS036ACM / ACHM.
