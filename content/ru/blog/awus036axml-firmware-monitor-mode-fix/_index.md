**ALFA AWUS036AXML** — флагманский адаптер WiFi 6E от ALFA Network, построенный на чипсете MediaTek MT7921AU с поддержкой трёх диапазонов (2,4 / 5 / 6 ГГц). Это один из немногих USB-адаптеров, способных к пассивному мониторингу в диапазоне 6 ГГц в 2026 году, и он демонстрирует превосходную производительность при разведке объектов, захвате пакетов и сборе PMKID.

Однако существует известная проблема, которая застаёт пользователей врасплох: **команды активного режима мониторинга вызывают сбой прошивки**. Запуск таких инструментов, как `aireplay-ng` или `mdk4`, приводит к полному исчезновению интерфейса `wlan0mon`, и для восстановления приходится отключать и повторно подключать адаптер. Это не аппаратный дефект — это ограничение драйвера Linux `mt7921u` и текущей прошивки.

Данное руководство объясняет первопричину, предоставляет шаги диагностики и конкретные исправления с обходными путями.

---

## Проблема: сбои активного режима мониторинга

### Симптом

После включения режима мониторинга и выполнения активной команды, такой как `aireplay-ng --test wlan0mon` или любой операции деаутентификации/инъекции, интерфейс `wlan0mon` исчезает из вывода `ip link` и `iwconfig`. Адаптер перестаёт отвечать и не может быть восстановлен без физического отключения и повторного подключения. В некоторых случаях сразу после сбоя в `dmesg` отображается ошибка прошивки или событие сброса.

Пассивные операции (сканирование с `airodump-ng`, захват необработанных кадров) продолжают работать корректно до и после сбоя, пока не активируется активная инъекция.

### Первопричина

**Чипсет MT7921AU** использует MAC-архитектуру на основе прошивки. Драйвер `mt7921u` ядра Linux зависит от встроенной прошивки чипсета для выполнения определённых операций низкого уровня, включая инъекцию кадров в режиме мониторинга. Текущая комбинация прошивки и драйвера не полностью реализует путь команд, необходимый для активной инъекции в режиме мониторинга в Linux.

**Пассивный мониторинг** (перехват кадров, уже находящихся в эфире) не требует от прошивки передачи чего-либо и работает без сбоев. Проблема ограничена операциями пути передачи: кадры деаутентификации, пробные запросы, флуд ассоциаций и аналогичные активные операции.

{{< alert "triangle-exclamation" >}}
**Известный баг сбоя прошивки.** Это подтверждённая проблема в драйвере Linux `mt7921u` на начало 2026 года. Затрагивает AWUS036AXML и другие USB-адаптеры на базе MT7921AU. Может быть исправлено в будущих обновлениях ядра или прошивки — актуальный статус смотрите в [руководстве по установке драйвера](/ru/blog/install-alfa-driver-kali-ubuntu/).
{{< /alert >}}

## Диагностика: это ваша проблема?

```bash
# Проверить, распознаётся ли адаптер
lsusb | grep -i mediatek

# Проверить загрузку драйвера
lsmod | grep mt7921u

# Проверить версию ядра (должна быть >= 5.18)
uname -r

# Запустить режим мониторинга
sudo airmon-ng start wlan0

# Тест пассивного захвата (должен работать)
sudo airodump-ng wlan0mon

# Тест активной инъекции (может вызвать сбой)
sudo aireplay-ng --test wlan0mon
```

Если адаптер исчезает из `ip link` после `aireplay-ng --test` — баг сбоя прошивки подтверждён.

Дополнительная проверка через логи ядра:

```bash
sudo dmesg | grep -E "mt7921|firmware|reset" | tail -20
```

Ищите сообщения `mt7921u: firmware crash`, `mt7921u: chip reset` или `usb disconnect`, появляющиеся сразу после вызова aireplay-ng.

{{< alert "circle-info" >}}
**Пассивный захват не затронут.** Если `airodump-ng` работает, но `aireplay-ng` вызывает сбой — это именно известный баг MT7921AU. Перейдите к исправлениям ниже.
{{< /alert >}}

## Исправление 1: обновление пакета прошивки

Наиболее эффективный первый шаг — убедиться в наличии последних файлов прошивки MT7921. Старые версии прошивки более склонны к сбоям; обновлённая прошивка улучшает стабильность для ряда активных операций.

```bash
sudo apt update
sudo apt install firmware-misc-nonfree

# Или вручную установить последнюю прошивку mt7921 из репозитория linux-firmware
sudo apt install git
git clone https://git.kernel.org/pub/scm/linux/kernel/git/firmware/linux-firmware.git
sudo cp linux-firmware/mediatek/mt7921* /lib/firmware/mediatek/
sudo modprobe -r mt7921u
sudo modprobe mt7921u
```

После обновления файлов прошивки перезагрузите драйвер и повторите тест активного режима:

```bash
sudo modprobe -r mt7921u && sudo modprobe mt7921u
sudo airmon-ng start wlan0
sudo aireplay-ng --test wlan0mon
```

## Исправление 2: использование последнего ядра

Драйвер `mt7921u` активно поддерживается в основном ядре Linux. Начиная с версии 5.18, патчи стабильности, обработка команд прошивки и улучшения режима мониторинга включались в обновления ядра. Использование более нового ядра — один из наиболее надёжных способов улучшить поведение.

Проверьте текущую версию ядра:

```bash
uname -r
```

Обновление до последнего доступного ядра в Kali Linux:

```bash
sudo apt update && sudo apt full-upgrade -y
sudo reboot
```

Цель: **ядро 6.1 LTS или новее** для наиболее полных патчей драйвера `mt7921u`. Ядро 6.6 и новее содержит дополнительные улучшения стека USB-драйвера MediaTek с положительными отзывами сообщества.

{{< alert "circle-info" >}}
**Улучшение в ядре 6.6+.** Несколько отчётов от сообщества указывают, что ядро 6.6 с обновлённой прошивкой снижает (но не всегда полностью устраняет) сбои активного режима на MT7921AU. После обновления повторно выполните последовательность диагностики для оценки вашей конкретной комбинации.
{{< /alert >}}

## Обходной путь: использование hcxdumptool (пассивный захват PMKID)

Если исправления на уровне прошивки не полностью устраняют сбой, `hcxdumptool` предоставляет высокоэффективный альтернативный рабочий процесс, не требующий никакой инъекции кадров.

`hcxdumptool` работает в **пассивном режиме** — захватывает значения PMKID непосредственно из кадров beacon и probe, транслируемых точками доступа. Кадры деаутентификации не отправляются, инъекции нет, сбоев прошивки нет. AWUS036AXML прекрасно справляется с этим рабочим процессом.

```bash
sudo apt install hcxdumptool hcxtools

# Пассивный захват — без деаутентификации, без сбоя прошивки
sudo hcxdumptool -i wlan0mon -o capture.pcapng --enable_status=1

# Конвертировать в формат hashcat
hcxpcapngtool -o hash.hc22000 capture.pcapng

# Взлом с помощью hashcat
hashcat -m 22000 hash.hc22000 /usr/share/wordlists/rockyou.txt
```

Этот рабочий процесс захватывает PMKID из кадров beacon без какой-либо передачи — полностью пассивный с точки зрения беспроводной среды.

{{< alert "circle-info" >}}
**Захват PMKID работает во всех современных сетях WPA2/WPA3.** Точки доступа транслируют PMKID в своих кадрах beacon независимо от того, ассоциирован ли какой-либо клиент. Вам нужно только находиться в зоне действия AP — клиент не нужен. Идеально для сценариев, где деаутентификация невозможна.
{{< /alert >}}

## Обходной путь: использование AWUS036ACH для активной инъекции

Для задач, реально требующих активной инъекции кадров (принудительный захват WPA-хэндшейка, перечисление WPS и аналогичные операции), **AWUS036ACH** (чипсет RTL8812AU) является проверенным решением со зрелой и хорошо протестированной поддержкой драйвера в Kali Linux.

Рекомендуемая профессиональная конфигурация с двумя адаптерами:

- **AWUS036AXML** → пассивное сканирование и захват на 5 ГГц / 6 ГГц
- **AWUS036ACH** → активная инъекция на 2,4 ГГц / 5 ГГц

Эта комбинация обеспечивает полное покрытие всех диапазонов: инъекция выполняется RTL8812AU (поддержка активного режима в Linux стабильна годами), а AWUS036AXML отвечает за обнаружение в 6 ГГц и высококачественный пассивный захват.

Подробности настройки обоих адаптеров — в [обзоре AWUS036AXML](/ru/blog/awus036axml-wifi-6e-review/) и [руководстве по инъекции пакетов](/ru/blog/packet-injection-guide/).

## Когда активный режим работает

Стоит отметить, что активный режим не всегда даёт сбой. Члены сообщества сообщают о нескольких условиях, при которых MT7921AU демонстрирует стабильное или близкое к стабильному поведение:

- **Ядро 6.6 или новее** с firmware-misc-nonfree 20240610 или новее
- Избегайте `aireplay-ng --deauth` в режиме пакетной отправки (флуд деаутентификации с высокой частотой пакетов вызывает сбои чаще, чем операции с одним кадром)
- Используйте `--deauth 1` или `--deauth 3` вместо непрерывных потоков деаутентификации
- Убедитесь, что адаптер подключён к порту USB 3.0 (ограничения пропускной способности USB 2.0 создают дополнительную нагрузку на конвейер команд прошивки)
- Для инъекции используйте 2,4 ГГц вместо 5 ГГц (низкочастотный диапазон кажется более стабильным в некоторых версиях драйвера)

{{< alert "triangle-exclamation" >}}
**Тестируйте перед реальными испытаниями.** Даже когда активный режим кажется работающим, прошивка MT7921AU может дать сбой в середине операции под нагрузкой. Всегда имейте план восстановления (резервный адаптер или исключительно пассивный рабочий процесс) при использовании AWUS036AXML для активных операций.
{{< /alert >}}

## Проверка актуальности прошивки

```bash
# Проверить дату файла текущей прошивки
ls -la /lib/firmware/mediatek/mt7921*

# Проверить версию драйвера
modinfo mt7921u | grep -E "version|filename"

# Проверить сообщения ядра о загрузке прошивки
sudo dmesg | grep mt7921
```

При успешной загрузке прошивки вывод `dmesg` должен содержать примерно следующее:

```
mt7921u 1-2.3:1.0: firmware init done
mt7921u 1-2.3:1.0: HW/SW Version: ...
```
