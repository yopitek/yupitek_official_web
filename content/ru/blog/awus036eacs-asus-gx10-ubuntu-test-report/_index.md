## 1. Этот адаптер и платформа тестирования

AWUS036EACS — лёгкий портативный USB-адаптер Wi-Fi 5 (802.11ac) от ALFA; чип — Realtek RTL8821CU, один поток 1x1, двухдиапазонный (2.4 ГГц и 5 ГГц), к тому же со встроенным Bluetooth, то есть это комбо-устройство BT + WiFi. В этой статье мы отдельно ставим его на испытательный стол Yopitek и в среде ASUS GX10 (ARM64) с Ubuntu 24.04 по пунктам проверяем, отвечая на вопросы, которые больше всего волнуют клиентов: распознаётся ли драйвер на ARM64, в какие режимы он может входить и до какого уровня дотягивает по производительности.

Сначала чётко обозначим рамки. Это проверка совместимости и границ возможностей собственного товара дистрибьютором, а не обучение атакам. Все измерения возможностей, связанных с инъекцией и handshake, выполнялись исключительно в собственной замкнутой среде по отношению к собственным устройствам и не содержат никаких инструкций по операциям против внешних сетей.

Платформа и методика тестирования аналогичны другим статьям этой серии по отдельным адаптерам:

- Вычислительная платформа: ASUS GX10 (ARM64 / aarch64)
- Операционная система: Ubuntu 24.04 LTS, kernel 6.17.0-1014-nvidia
- Стратегия с драйвером: используется встроенный в ядро (in-kernel) драйвер, адаптер распознаётся сразу при подключении, никакие сторонние модули DKMS не устанавливаются
- Тестовое устройство: Apple iPhone 7 Plus (WPA3-SAE дополнительно перепроверен на iPhone 15 Pro)
- Среда тестирования: собственная офисная сеть Wi-Fi, SSID YUPITEK, 2.4 ГГц ch5 / 5 ГГц ch36, ch157
- Правила безопасности: всё время работы задействуется только интерфейс `wlx*`, встроенная магистраль выхода в сеть не затрагивается; никогда не выполняется `airmon-ng check kill` (он остановит NetworkManager и лишит GX10 выхода в сеть)

## 2. Оборудование и драйвер: правда о комбо-устройстве BT + WiFi

Сначала суть. В таблице ниже — фактическое состояние AWUS036EACS при загрузке на kernel 6.17:

| Параметр | Значение |
|---|---|
| Чип | Realtek RTL8821CU (один поток 1x1) |
| Поколение | Wi-Fi 5 (802.11ac), 2.4 + 5 ГГц |
| Комбо-функция | комбо-устройство BT + WiFi (встроенный Bluetooth) |
| USB ID | `0bda:c820` |
| Драйвер | `rtw88_8821cu` (in-kernel, поддержка USB с kernel 6.2) |
| Прошивка | 24.11.0 (H2C version 12, по данным dmesg) |
| Полоса VHT | только 80 МГц (нет 160 / 80+80) |

По запросу через `iw phy` поддерживаемые режимы интерфейса — `managed` / `AP` / `AP/VLAN` / `monitor` (`IBSS` указан в списке, но на практике join не работает); охват диапазонов — 2.4 ГГц ch1–13 и 5 ГГц ch36–165 (из них ch52–144 — диапазон DFS); среди cipher есть CCMP-256, GCMP-128 / GCMP-256 и CMAC, то есть условия для запуска WPA3 на стороне AP имеются.

С драйвером никаких неопределённостей. Поддержка USB для RTL8821CU включена в mainline `rtw88` начиная с kernel 6.2; в kernel 6.17 на GX10 уже встроен `rtw88_8821cu`, он загружается сразу при подключении, компиляция или DKMS не нужны. В ранних in-kernel версиях был баг режима AP, уже исправленный патчем macid (начиная с linux-next-20240911); в этом тесте на kernel 6.17 все три режима AP завершались корректно. Способ проверки:

```bash
lsusb | grep -i '0bda:c820'
# ID 0bda:c820 Realtek Semiconductor Corp. 802.11ac NIC
sudo dmesg | grep -i 8821cu
# rtw88_8821cu ...: Firmware version 24.11.0, H2C version 12 -> renamed from wlan0
```

После загрузки Wi-Fi-интерфейс получает имя `wlx` + MAC (например, `wlx00c0cab3a52e`), а не `wlan0`; после переподключения имя не меняется, поэтому при написании скриптов на него можно надёжно ссылаться.

По-настоящему стоит обратить внимание на то, что это «комбо-устройство». Если посмотреть через `lsusb -t`, видно, что под одним чипом RTL8821CU висят несколько USB-интерфейсов: функция Bluetooth привязана к `btusb`, а функция Wi-Fi — отдельно к `rtw88_8821cu`.

```
/:  Bus 0X.Port X: Dev X, Class=root_hub, Driver=xhci-hcd
    |__ Port X: Dev X, If 0, Class=Wireless, Driver=btusb               <- Bluetooth
    |__ Port X: Dev X, If 1, Class=Wireless, Driver=btusb               <- Bluetooth
    |__ Port X: Dev X, If 2, Class=Vendor Specific, Driver=rtw88_8821cu <- Wi-Fi
```

(Номера Bus / Port меняются в зависимости от числа переподключений; важно то, что interface 0/1 идут через `btusb`, а Wi-Fi на `rtw88_8821cu` — это interface 2.)

**Риск переподключения комбо-устройства BT + WiFi (обязательно к прочтению перед развёртыванием).** Поскольку Bluetooth и Wi-Fi используют одно и то же USB-устройство, в некоторых USB-портах или при быстром переподключении возможна гонка: Bluetooth уже привязался к `btusb`, но probe интерфейса Wi-Fi зависает, в результате чего `lsusb` видит `0bda:c820`, но интерфейс `wlx` не появляется. В тестах перезагрузка через `modprobe -r` или ручной `bind` чаще всего не помогали (`bind` возвращает `Operation already in progress`). Надёжное решение только одно: вынуть адаптер и подключить его в другой USB-порт — после смены порта перечисление проходит чисто, и интерфейс `wlx` появляется нормально. Это дополнительный эксплуатационный нюанс этого адаптера по сравнению с некомбинированным AWUS036ACS (RTL8811AU); зная о нём заранее, вы не примете это за неисправность адаптера.

## 3. Реальные возможности: Monitor / инъекция / AP / WPA3

В таблице ниже — сводка реальных тестов ключевых возможностей AWUS036EACS; каждый пункт выполнен 2026-11-18 на реальном GX10:

| Возможность | 2.4 ГГц | 5 ГГц | Ключевой результат теста |
|---|---|---|---|
| Monitor | ✅ сильно | ✅ сильно | на большинстве каналов полные 300 frames; «зависание на ch1» (community #453) не воспроизведено |
| Инъекция | ✅ 100% (30/30) | ✅ 100% (30/30) | Power 2.4G -38.27 / 5G -76.10; сильнейшая инъекция среди ac-адаптеров этой серии |
| AP | ✅ чистое завершение | ✅ VHT 80 МГц | `hostapd` поднимает станцию, iPhone 7 Plus подключается и завершает 4-way |
| WPA3-SAE (сторона AP) | ✅ iPhone подключается | Не тестировалось | SAE-only + принудительная PMF (`ieee80211w=2`, `sae_pwe=0`) |
| Захват WPA handshake | — | ✅ сквозной | полный M1–M4, deauth получает 79 ACKs, выдан `.22000` |

Monitor (режим мониторинга) стабилен и в 2.4, и в 5 ГГц. При поочерёдном захвате на шести каналах на большинстве из них получено полные 300 frames. Для 8821cu здесь есть ещё один очень важный положительный результат: давно отслеживаемая сообществом rtw88 проблема GitHub #453 («8821cu на kernel ≥6.9 при поднятой STA залипает в monitor на ch1») в среде GX10 не воспроизвелась — ch36, ch149 и ch157 в 5 ГГц стабильно набирают полные 300 кадров. Для спектральной разведки или разбора пакетов в диапазонах 2.4 / 5 ГГц monitor этого адаптера можно использовать уверенно.

Инъекция (packet injection) показала себя наиболее впечатляюще. По измерению командой `aireplay-ng --test` и в 2.4 ГГц, и в 5 ГГц получено 30/30, 100% — это сильнейшая инъекция среди ac-адаптеров этой серии (одноантенный AWUS036ACS, также 1x1, в 5G даёт лишь 96%). Здесь есть местный тайваньский нюанс: TX в 5 ГГц при regulatory domain TW блокируется, поэтому перед измерением выполните `iw reg set US` для разблокировки, а после — верните `iw reg set TW`.

Что касается AP, то с помощью `hostapd` поочерёдно поднимались три конфигурации — 2.4 ГГц (WPA2), 5 ГГц (VHT 80 МГц) и WPA3-SAE; iPhone 7 Plus во всех случаях подключался и завершал 4-way handshake, а закрытие станции проходило чисто (`AP-DISABLED` / `TERMINATING`). Проблемы beacon re-key, встречающейся на некоторых адаптерах, не возникало — в этом отношении на 2.4G он стабильнее сестринского адаптера ACS. WPA3 использовал SAE-only с принудительной PMF (`ieee80211w=2`, `sae_pwe=0`); iPhone 15 Pro успешно подключился, что подтверждает работоспособность WPA3-SAE на стороне AP у RTL8821CU.

Цепочка инструментов Kali (на уровне платформы) на этом адаптере также полностью поднимается: `airmon-ng` обнаруживает EACS (`rtw88_8821cu`), но `check kill` всё так же использовать не следует; `kismet` успешно запускается с этим адаптером в качестве data source, и на практике выдаёт `.kismet` log около 733 KB; `bettercap` 2.32 с `wifi.recon on` работает нормально (предупреждение о txpower можно игнорировать); `wifite` (git 3.0.0) нашёл более 10 AP, включая собственный YUPITEK (ch5, PWR 84) — в этой версии нет флага `--band`, поэтому каналы задаются через `-c 1,6,11,36,149,157`; `Wireshark` / `tshark` 4.x на monitor ch6 реально захватили и разобрали 325 frames; случайная маскировка MAC через `macchanger` также работает. Этот уровень инструментов идентичен остальным адаптерам серии; различия в основном касаются аппаратных возможностей инъекции и monitor, описанных выше.

## 4. Сквозной handshake: сильная сторона и честные ограничения

Сильная сторона этого адаптера — способность связать инъекцию и захват в единую полностью рабочую цепочку. Между собственным AP YUPITEK и собственным iPhone 7 Plus вся цепочка прошла на реальном железе: отправка deauth собственному iPhone (инъекция — на практике получено 79 ACKs, что подтверждает, что инъектированные пакеты действительно дошли до клиента) → при переподключении iPhone захвачен полный 4-way handshake (рукопожатие: M1, M2, M3, M4 по одному) → преобразование через `hcxpcapngtool --all` в формат hashcat `.22000` (784 bytes, 2 пары EAPOL, RC checked). Весь процесс служил лишь для проверки возможностей адаптера, объектом всё время были собственный AP и собственный смартфон, и он не касается каких-либо чужих сетей.

На практике стоит зафиксировать две ключевые детали: в офисе одновременно на ch36 работает несколько AP с одинаковым именем YUPITEK, поэтому при захвате не фиксируйте `--bssid`, а снимайте весь канал целиком, чтобы не отфильтровать ту точку, к которой на самом деле подключён iPhone; кроме того, `hcxpcapngtool` по умолчанию строг, и для получения `.22000` нужно добавить `--all`.

Честные ограничения тоже изложим сразу и полностью:

- **Не поддерживаются active-monitor / IBSS (Ad-hoc) / Mesh (802.11s) / Wi-Fi Direct (P2P).** Эти режимы в `rtw88` возвращают `-95` (Operation not supported) либо перечислены, но join не работает — это ограничение на уровне драйвера, без решения. Клиентам, которым нужны эксперименты с mesh / IBSS, следует перейти на AWUS036ACM / ACHM от MediaTek.
- **`hcxdumptool` 8.x ограниченно применим.** Он требует active-monitor; на этом адаптере он поднимается только в 2.4 ГГц, а в 5 ГГц выдаёт `failed to arm` (остальные карты серии везде выдают `failed to arm interface`); используйте `airodump-ng` + `aireplay-ng` — инъекция у этого адаптера 100%, так что это ни на что не влияет.
- **VHT только 80 МГц.** Один поток, без 160 МГц или 80+80 — позиционирование именно как лёгкого портативного адаптера, а не как решения для борьбы за пропускную способность.
- **VIF поддерживается частично.** Работает только пассивный monitor-интерфейс совместно с managed на том же канале (программный monitor; на практике 100 frames); независимые двойные VIF не поддерживаются.

## 5. Сценарии применения и выбор

По совокупности результатов позиционирование AWUS036EACS вполне ясно: если нужны двухдиапазонный Monitor + инъекция + верификация сквозного handshake, и при этом хочется компактный портативный адаптер со встроенным Bluetooth — это подходящее решение. Инъекция 100% в обоих диапазонах и чистое поведение AP / WPA3 ставят его в группу первого выбора наряду с AWUS036ACH и AWUS036ACS для беспроводного аудита и обучения по информационной безопасности в рамках авторизации.

В каких случаях стоит выбрать другой адаптер:

- **Если на месте будут частые переподключения или качество USB-портов корпуса неодинаковое** → гонка probe комбо-устройства добавит хлопот, стоит рассмотреть некомбинированный AWUS036ACS (RTL8811AU, тоже 1x1 ac, но без дополнительного фактора Bluetooth).
- **Если нужны эксперименты с mesh / IBSS** → `rtw88` их не поддерживает, переходите на AWUS036ACM / ACHM от MediaTek.
- **Если нужен максимальный приём или дальний monitor** → лучше подойдут двухантенный AWUS036ACH или Wi-Fi 6 AWUS036AXER.
- **Чего избегать**: если задача — injection / handshake, не выбирайте AWUS036AXM / AXML на MT7921 — инъекция на этой платформе просто не работает.

Чтобы разом увидеть горизонтальное сравнение Monitor / инъекции / AP / WPA3 и полную матрицу выбора для всех 9 адаптеров ALFA, вернитесь к сводной таблице: [Самое полное тестирование 2026: полная матрица 9 беспроводных адаптеров ALFA на ASUS GX10](/ru/blog/alfa-9-cards-arm64-gx10-ubuntu-matrix/).

## Часто задаваемые вопросы (FAQ)

**Q: Нужно ли устанавливать драйвер для AWUS036EACS на Ubuntu 24.04 ARM64?**
На протестированном в статье kernel 6.17 (ASUS GX10) — нет: RTL8821CU обслуживается встроенным драйвером rtw88_8821cu, адаптер распознаётся сразу при подключении, без компиляции и без DKMS; имя интерфейса — wlx плюс MAC, после переподключения не меняется.

**Q: Как ведут себя monitor mode (режим мониторинга) и инъекция пакетов у AWUS036EACS?**
Monitor стабилен и в 2.4G, и в 5G, на большинстве каналов захватывается по 300 frames; `aireplay-ng --test` даёт 30/30 (100%) в обоих диапазонах. Перед инъекцией в 5G нужно снять ограничение TW на TX командой `iw reg set US`.

**Q: Может ли AWUS036EACS захватить WPA handshake (пакеты рукопожатия)?**
Да. Сквозное тестирование на собственном AP и собственном iPhone 7 Plus: на deauth получено 79 ACKs, захвачен полный M1–M4, `hcxpcapngtool --all` выдал .22000 (784 bytes, 2 пары EAPOL). Только в собственных или авторизованных сетях.

**Q: Что делать, если после подключения AWUS036EACS виден в lsusb, но сетевого интерфейса wlx нет?**
Это состояние гонки при probe комбо-устройства BT+Wi-Fi: Bluetooth уже привязан к btusb, а rtw88_8821cu для Wi-Fi зависает. На практике перезагрузка модуля и ручной bind чаще всего не помогают; надёжное решение — вынуть адаптер и подключить его в другой USB-порт.

**Q: Поддерживает ли AWUS036EACS mesh, IBSS или hcxdumptool?**
Нет. В rtw88 active-monitor, IBSS, mesh и P2P возвращают -95 или join не работает; hcxdumptool 8.x поднимается только в 2.4 ГГц (в 5 ГГц failed to arm) — используйте airodump-ng + aireplay-ng. VHT только 80 МГц. Для mesh / IBSS выбирайте AWUS036ACM / ACHM.
