## Что такое режим монитора и зачем он нужен для пентестинга

Режим монитора — это специальный режим работы беспроводного сетевого адаптера, позволяющий захватывать **все** фреймы 802.11 в эфире, а не только те, что адресованы вашему устройству. В обычном «управляемом» режиме адаптер принимает лишь пакеты, предназначенные для его MAC-адреса, и отбрасывает всё остальное. Режим монитора полностью снимает этот фильтр.

Для пентестеров беспроводных сетей режим монитора — фундамент. Без него такие инструменты, как **airodump-ng**, **Wireshark** (в режиме захвата беспроводного трафика) или **Kismet**, не могут пассивно перехватывать сетевой трафик. Режим монитора открывает возможности для:

- **Пассивной разведки** — сканирование всех ближайших точек доступа и клиентов без передачи каких-либо фреймов.
- **Захвата рукопожатий** — прослушивание четырёхстороннего рукопожатия WPA/WPA2 при аутентификации клиента.
- **Атак деаутентификации** — отправка управляющих фреймов 802.11 (требует инъекции пакетов в дополнение к режиму монитора).
- **Обнаружения мошеннических точек доступа** — идентификация несанкционированных точек доступа в сети.
- **Анализа протоколов** — глубокая инспекция управляющих, контрольных и информационных фреймов 802.11.

Не каждый WiFi-адаптер поддерживает режим монитора. Эта возможность определяется **чипсетом** и **драйвером**, скомпилированным в ядро. Потребительские адаптеры для домашнего использования почти никогда не совместимы. Адаптеры, специально разработанные для исследований в области безопасности, — например, линейка ALFA Network, — построены на чипсетах и с драйверами, обеспечивающими чистую работу в режиме монитора.

## Предварительные требования

Перед включением режима монитора убедитесь в следующем:

1. Вы работаете в **Kali Linux** (рекомендуется версия 2024.1 и новее) с совместимым ядром.
2. Ваш WiFi-адаптер подключён (USB-адаптеры) или установлен (PCIe/mini-PCIe).
3. У вас есть права **root или sudo**.
4. Вы определили имя своего интерфейса: выполните `ip link` или `iwconfig` и запишите беспроводной интерфейс (обычно `wlan0`, `wlan1` или `wlx...`).

```bash
ip link show
```

Ищите запись, начинающуюся с `wlan` или имеющую длинное имя на основе MAC-адреса, начинающееся с `wlx`.

## Метод 1: Включение режима монитора через airmon-ng

`airmon-ng` — часть набора **aircrack-ng** и наиболее распространённый инструмент переключения режима монитора в Kali Linux. Он автоматически обрабатывает многие граничные случаи, включая остановку процессов, мешающих переключению режима.

### Шаг 1 — Завершение мешающих процессов

NetworkManager, wpa_supplicant и dhclient конкурируют с режимом монитора. Сначала остановите их:

```bash
sudo airmon-ng check kill
```

Ожидаемый вывод:

```
Killing these processes:
  PID Name
  812 wpa_supplicant
  934 NetworkManager
```

> **Примечание:** Это отключит существующие сетевые соединения. Если во время теста нужен доступ в интернет, используйте проводное соединение или второй беспроводной адаптер в управляемом режиме.

### Шаг 2 — Запуск режима монитора

```bash
sudo airmon-ng start wlan0
```

Ожидаемый вывод:

```
PHY     Interface   Driver      Chipset
phy0    wlan0       rtl8812au   Realtek Semiconductor Corp. RTL8812AU 802.11a/b/g/n/ac

(mac80211 monitor mode vif enabled for [phy0]wlan0 on [phy0]wlan0mon)
(mac80211 station mode vif disabled for [phy0]wlan0)
```

Адаптер теперь в режиме монитора, и создан новый виртуальный интерфейс — как правило, **wlan0mon**.

### Шаг 3 — Фиксация канала (опционально, но рекомендуется)

По умолчанию адаптер прыгает по каналам. Зафиксируйте конкретный канал для целенаправленного захвата:

```bash
sudo iwconfig wlan0mon channel 6
```

## Метод 2: Включение режима монитора через iw

Команда `iw` — современная низкоуровневая утилита настройки беспроводной связи. Этот метод даёт больший прямой контроль и полезен, когда `airmon-ng` недоступен или ведёт себя некорректно.

```bash
# Опускаем интерфейс
sudo ip link set wlan0 down

# Устанавливаем режим монитора
sudo iw dev wlan0 set type monitor

# Поднимаем интерфейс
sudo ip link set wlan0 up
```

Все три команды одной строкой:

```bash
sudo ip link set wlan0 down && sudo iw dev wlan0 set type monitor && sudo ip link set wlan0 up
```

Этот метод изменяет существующий интерфейс `wlan0` на месте, а не создаёт новый интерфейс `wlan0mon`. Проверьте применение изменений:

```bash
iw dev wlan0 info
```

Ищите строку `type monitor` в выводе.

## Проверка режима монитора

### С помощью iwconfig

```bash
iwconfig
```

Интерфейс в режиме монитора покажет:

```
wlan0mon  IEEE 802.11  Mode:Monitor  Frequency:2.457 GHz  Tx-Power=20 dBm
          Retry short limit:7   RTS thr:off   Fragment thr:off
          Power Management:off
```

Ключевое поле — **Mode:Monitor**.

### С помощью iw dev

```bash
iw dev
```

Ищите `type monitor` в записи вашего интерфейса. Если отображается `type managed`, режим монитора не был применён успешно.

## Тест с airodump-ng

После активации режима монитора выполните сквозную проверку с `airodump-ng`:

```bash
sudo airodump-ng wlan0mon
```

На экране должен немедленно начать появляться список ближайших точек доступа с BSSID, каналом, уровнем сигнала (PWR), типом шифрования и ESSID. Если экран пустой или появляется ошибка, обратитесь к разделу по устранению неполадок ниже.

Чтобы сканировать только диапазон 5 ГГц:

```bash
sudo airodump-ng --band a wlan0mon
```

Чтобы захватить конкретную сеть и сохранить вывод для последующего анализа:

```bash
sudo airodump-ng -c 6 --bssid AA:BB:CC:DD:EE:FF -w capture wlan0mon
```

## Устранение неполадок

### «Cannot enable monitor mode» или интерфейс исчезает

Обычно это происходит, когда NetworkManager перехватывает интерфейс. Снова выполните `airmon-ng check kill`, затем повторите попытку. Если проблема сохраняется, остановите NetworkManager вручную:

```bash
sudo systemctl stop NetworkManager
sudo systemctl stop wpa_supplicant
```

### Режим монитора возвращается в управляемый режим

Некоторые драйверы автоматически сбрасываются в управляемый режим через несколько секунд. Как правило, это означает, что wpa_supplicant перезапустился в фоне. Проверьте запущенные процессы:

```bash
ps aux | grep -E "wpa_supplicant|NetworkManager"
```

Завершите найденные процессы по PID, затем снова включите режим монитора.

### После airmon-ng интерфейс имеет другое имя

На некоторых системах новый интерфейс может называться `wlan0mon`, `mon0` или иначе. Всегда проверяйте реальное имя через `iwconfig` или `iw dev` после выполнения `airmon-ng start`, прежде чем использовать его с airodump-ng.

### Ошибка «Fixed channel wlan0mon: -1» в airodump-ng

Это означает, что airodump-ng не может менять каналы. Попробуйте:

```bash
sudo iwconfig wlan0mon channel 1
```

Если не помогает, завершите все оставшиеся процессы wpa_supplicant и повторите попытку.

### Проблемы с драйвером RTL8812AU на новых ядрах

Встроенный в ядро драйвер RTL8812AU на очень свежих ядрах иногда не поддерживает режим монитора в полной мере. Установите драйвер сообщества:

```bash
sudo apt install dkms git
git clone https://github.com/aircrack-ng/rtl8812au.git
cd rtl8812au
sudo make dkms_install
```

После установки перезагрузитесь.

## Отключение режима монитора после завершения работы

Всегда возвращайте адаптер в управляемый режим по окончании тестирования. Оставленный в режиме монитора адаптер не позволяет подключаться к обычным сетям.

### Через airmon-ng:

```bash
sudo airmon-ng stop wlan0mon
sudo systemctl start NetworkManager
```

### Через iw:

```bash
sudo ip link set wlan0 down
sudo iw dev wlan0 set type managed
sudo ip link set wlan0 up
sudo systemctl start NetworkManager
```

Проверьте возврат в управляемый режим через `iwconfig` и подключитесь к своей сети.

## Итог

Включение режима монитора в Kali Linux — двухшаговый процесс: остановить мешающие службы, затем переключить режим интерфейса через `airmon-ng` или `iw`.
