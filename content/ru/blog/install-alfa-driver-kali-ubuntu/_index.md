Успех работы USB WiFi-адаптера в Linux нередко целиком определяется одним фактором — драйвером. В отличие от Windows, где производители прилагают драйверы в виде готовых установщиков, Linux использует модули ядра — скомпилированный код, который операционная система загружает для взаимодействия с оборудованием. Понимание этой модели делает устранение неполадок предсказуемым, а установку драйверов — понятной.

В этом руководстве рассматривается установка драйверов для всех основных чипсетов USB WiFi-адаптеров ALFA Network как на Kali Linux 2024/2025, так и на Ubuntu 24.04 LTS.

---

## Как работают USB WiFi-драйверы в Linux

### Модули ядра

Драйвер WiFi в Linux — это **модуль ядра**, файл `.ko`, который загружается в работающее ядро при старте системы или по требованию. При подключении USB-устройства ядро считывает его Vendor ID и Product ID, находит подходящий модуль в своей базе данных и загружает его автоматически.

Для распространённых чипсетов, например MediaTek MT7612U, это происходит незаметно: подключили адаптер — модуль загрузился — интерфейс появился. Для более новых или редких чипсетов встроенного модуля может не существовать, и тогда приходится компилировать его из исходников.

### Сторонние (out-of-tree) драйверы

Когда драйвер не включён в основное ядро (так называемый «сторонний» или «out-of-tree» драйвер), необходимо:

1. Скачать исходный код драйвера
2. Скомпилировать его под заголовочные файлы вашего запущенного ядра
3. Установить полученный файл `.ko` в директорию модулей ядра
4. Загрузить его через `modprobe`

Шаг компиляции требует, чтобы заголовочные файлы ядра были установлены и точно соответствовали запущенному ядру. Это самая частая причина ошибок при установке драйверов.

### DKMS: динамическая поддержка модулей ядра

Обычная `make install` компилирует драйвер только для текущего ядра. Когда Kali или Ubuntu обновляют ядро — а это происходит регулярно — старый драйвер перестаёт загружаться, и приходится пересобирать его вручную.

**DKMS** решает эту проблему, регистрируя исходный код драйвера в системном демоне, который автоматически перекомпилирует зарегистрированные модули при установке нового ядра. Это рекомендуемый подход для любого адаптера, требующего стороннего драйвера.

## Определение чипсета

Нужный вам драйвер зависит исключительно от чипсета, а не от маркетингового названия адаптера. Два адаптера с одинаковым названием, но разными аппаратными ревизиями могут использовать разные чипсеты.

### Таблица соответствия моделей ALFA и чипсетов

| Модель ALFA | Чипсет | USB ID | Драйвер |
|---|---|---|---|
| [AWUS036ACH](/ru/products/alfa/awus036ach/) | RTL8812AU | 0bda:8812 | aircrack-ng/rtl8812au |
| [AWUS036ACHM](/ru/products/alfa/awus036achm/) | MT7610U | 0e8d:7610 | mt76x0u (in-kernel, EOL) |
| [AWUS036ACM](/ru/products/alfa/awus036acm/) | MT7612U | 0e8d:7612 | mt76x2u (встроен в ядро) |
| [AWUS036AX](/ru/products/alfa/awus036ax/) | RTL8832BU | 0e8d:885a | OOK driver (<6.14) |
| [AWUS036AXML](/ru/products/alfa/awus036axml/) | MT7921AUN | 0e8d:7961 | mt7921u (ядро 5.18+) |

### Определение адаптера через lsusb

Подключите адаптер и выполните:

```bash
lsusb
```

Пример вывода:

```
Bus 003 Device 002: ID 0bda:8812 Realtek Semiconductor Corp. RTL8812AU 802.11a/b/g/n/ac
Bus 003 Device 003: ID 0e8d:7612 MediaTek Inc. MT7612U 802.11a/bgn/ac
```

Сравните значение `ID xx:xx` с таблицей выше, чтобы подтвердить чипсет.

## Подготовка системы

Независимо от чипсета, сначала установите общие зависимости для сборки.

**Kali Linux:**

```bash
sudo apt update
sudo apt install -y \
    git \
    dkms \
    build-essential \
    libelf-dev \
    linux-headers-$(uname -r)
```

**Ubuntu 24.04:**

```bash
sudo apt update
sudo apt install -y \
    git \
    dkms \
    build-essential \
    libelf-dev \
    linux-headers-$(uname -r) \
    linux-headers-generic
```

Убедитесь, что заголовочные файлы установлены именно для вашего запущенного ядра:

```bash
uname -r
# Пример: 6.6.9-amd64

ls /lib/modules/$(uname -r)/build
# Директория должна существовать — если нет, заголовочные файлы не установлены
```

## Драйвер RTL8812AU (AWUS036ACH)

RTL8812AU требует стороннего драйвера. Существуют две поддерживаемые сообществом ветки; выбирайте в зависимости от ОС.

### Вариант A: aircrack-ng/rtl8812au (Kali Linux — рекомендуется)

Эта ветка поддерживается командой Aircrack-ng с явной совместимостью с Kali и оптимизированной поддержкой инъекции пакетов:

```bash
git clone https://github.com/aircrack-ng/rtl8812au
cd rtl8812au
make
sudo make install
sudo modprobe 88XXau
```

Проверьте, что интерфейс появился:

```bash
ip link show | grep wlan
# Должен отображаться wlan0 или аналогичный
```

### Вариант B: morrownr/8812au-20210708 (Ubuntu 24.04 — рекомендуется)

Ветка morrownr оптимизирована для Ubuntu и включает удобный скрипт установки с интеграцией DKMS:

```bash
git clone https://github.com/morrownr/8812au-20210708
cd 8812au-20210708
sudo ./install-driver.sh
```

Скрипт автоматически регистрирует драйвер в DKMS. После его выполнения:

```bash
# Перезагружаемся для загрузки нового модуля
sudo reboot

# После перезагрузки проверяем
lsmod | grep 8812au
```

### Ручная регистрация в DKMS (для любой из веток)

Если вы предпочитаете ручное управление:

```bash
# Клонируем драйвер (любую из веток)
git clone https://github.com/aircrack-ng/rtl8812au

# Узнаём версию из Makefile
grep "^MODULE_VERSION" rtl8812au/Makefile
# Записываем версию, например v5.6.4.2 → используем 5.6.4.2

# Копируем исходники в директорию DKMS
sudo cp -r rtl8812au /usr/src/rtl8812au-5.6.4.2

# Регистрируем, собираем, устанавливаем
sudo dkms add -m rtl8812au -v 5.6.4.2
sudo dkms build -m rtl8812au -v 5.6.4.2
sudo dkms install -m rtl8812au -v 5.6.4.2

# Проверяем
dkms status
# Ожидаемый вывод: rtl8812au/5.6.4.2, 6.x.x-kali-amd64: installed
```

### Ожидаемый вывод lsusb и lsmod

После успешной установки:

```bash
lsusb
# Bus 001 Device 003: ID 0bda:8812 Realtek Semiconductor Corp. RTL8812AU ...

lsmod | grep 88XXau
# 88XXau    3461120  0
```

## Драйвер MT7612U (AWUS036ACM, AWUS036ACX)

Чипсет MT7612U — самый простой в работе из всех четырёх, поскольку его драйвер входит в состав основного ядра Linux начиная с **версии 4.19**. На Kali Linux 2022+ и Ubuntu 20.04+ установка драйвера вообще не требуется.

### Проверка версии ядра

```bash
uname -r
```

Если результат — 4.19 или выше (а на любом современном Kali или Ubuntu именно так), модуль `mt76x2u` уже доступен.

### Загрузка модуля

```bash
sudo modprobe mt76x2u
```

Проверьте загрузку:

```bash
lsmod | grep mt76x2u
# mt76x2u    86016  0
# mt76x2_common    61440  1 mt76x2u
# mt76_usb    40960  1 mt76x2u
```

Беспроводной интерфейс должен появиться немедленно:

```bash
ip link show
# wlan0: ...
```

### Автозагрузка модуля

На большинстве систем модуль загружается автоматически при обнаружении адаптера. Чтобы явно обеспечить загрузку при старте:

```bash
echo "mt76x2u" | sudo tee -a /etc/modules
```

### Компиляция не требуется

В этом главное преимущество чипсета MT7612U: никакой компиляции, никаких исходников драйвера, никакой зависимости от заголовочных файлов ядра. Работает «из коробки» на каждом поддерживаемом дистрибутиве. Для тех, кто не хочет возиться с управлением драйверами, [AWUS036ACM](/ru/products/alfa/awus036acm/) — наиболее plug-and-play адаптер для пентестинга из всех доступных.

## Драйвер MT7921AUN (AWUS036AXM, AWUS036AXML — Wi-Fi 6E)

MT7921AUN — это чипсет Wi-Fi 6E от MediaTek. Его Linux-драйвер `mt7921u` был включён в основное ядро начиная с **версии 5.18**.

### Проверка версии ядра

```bash
uname -r
```

**Kali Linux 2022.2 и новее** поставляется с ядром 5.18 или выше — поддерживается.
**Ubuntu 22.04 LTS** поставляется с ядром 5.15 — **не поддерживается** без обновления ядра.
**Ubuntu 24.04 LTS** поставляется с ядром 6.8 — полная поддержка.

### Загрузка модуля (ядро 5.18+)

```bash
sudo modprobe mt7921u
```

Проверка:

```bash
lsmod | grep mt7921u
# mt7921u    57344  0
# mt7921_common    196608  1 mt7921u
```

### Ubuntu 22.04: путь обновления ядра

При работе на Ubuntu 22.04 с ядром 5.15 есть два варианта:

**Вариант A: HWE-ядро** (рекомендуется)

```bash
sudo apt install linux-generic-hwe-22.04
sudo reboot
```

HWE-ядро (Hardware Enablement) для Ubuntu 22.04 — это версия 6.2+, которая поддерживает mt7921u.

**Вариант B: Обновление до Ubuntu 24.04**

Ubuntu 24.04 LTS поставляется с ядром 6.8 и полной поддержкой mt7921u. Это самое чистое долгосрочное решение.

### Wi-Fi 6E и статус режима монитора

По состоянию на 2026 год, драйвер mt7921u обеспечивает стабильную поддержку управляемого режима (подключение к сетям) на диапазонах 2,4 ГГц, 5 ГГц и 6 ГГц. Режим монитора на 2,4 и 5 ГГц работает. **Режим монитора на 6 ГГц** всё ещё дозревает — перед ответственными работами обязательно проверьте актуальное состояние в трекере ошибок драйвера `mt76`.

## DKMS: как сохранить драйверы после обновлений ядра

И Kali Linux, и Ubuntu регулярно обновляют ядро. Без DKMS ваши сторонние драйверы (RTL8812AU) перестанут работать после обновления ядра, пока вы не перекомпилируете их вручную.

При правильной настройке DKMS перекомпиляция происходит автоматически во время `apt upgrade`.

### Проверка, что DKMS управляет вашим драйвером

```bash
dkms status
```

Пример вывода с правильно настроенными драйверами:

```
rtl8812au/5.6.4.2, 6.6.9-amd64: installed
8814au/5.8.7.4, 6.6.9-amd64: installed
```

### Что происходит при обновлении ядра

```
apt upgrade
→ Скачивается новый пакет ядра
→ Срабатывает хук DKMS
→ Исходники rtl8812au перекомпилируются для нового ядра
→ Устанавливается новый .ko файл
→ Система перезагружается на новом ядре
→ Драйвер загружается автоматически
```

Если DKMS завершился с ошибкой во время обновления (видно через `dkms status` — статус «built», но не «installed»), установите вручную:

```bash
sudo dkms install rtl8812au/5.6.4.2 -k $(uname -r)
```

## Устранение неполадок

| Симптом | Вероятная причина | Решение |
|---|---|---|
| Нет интерфейса wlan после подключения | Драйвер не загружен | `sudo modprobe 88XXau` или `sudo modprobe mt76x2u` |
| `modprobe: FATAL: Module not found` | Драйвер не скомпилирован для текущего ядра | Пересобрать драйвер или выполнить `sudo dkms install` |
| Интерфейс появляется и исчезает через несколько секунд | Вмешивается управление питанием | `sudo iwconfig wlan0 power off` |
| `make` завершается с ошибкой «linux/module.h not found» | Заголовочные файлы ядра не установлены | `sudo apt install linux-headers-$(uname -r)` |
| `make` завершается с ошибкой несовпадения версий | Заголовочные файлы не совпадают с запущенным ядром | Сравните `uname -r` и `ls /lib/modules` — переустановите нужные заголовочные файлы |
| Устройство есть в lsusb, но интерфейс не создаётся | Модуль загружен, но интерфейс не инициализирован | Проверьте `dmesg \| tail -30` на наличие ошибок |
| Режим монитора не включается: «Operation not supported» | Версия драйвера не поддерживает режим монитора | Используйте ветку aircrack-ng вместо пакетного драйвера дистрибутива |
| Тест инъекции aireplay-ng: 0% | Интерфейс не в режиме монитора | Проверьте через `iwconfig`, перезапустите `airmon-ng start` |
| Драйвер работает, но не загружается после перезагрузки | Модуль не добавлен в initramfs | `sudo update-initramfs -u` или используйте DKMS |
| Сборка DKMS завершается с ошибкой после обновления ядра | Отсутствуют заголовочные файлы для нового ядра | `sudo apt install linux-headers-$(uname -r)` |

### Подробные диагностические команды

```bash
# Все загруженные модули беспроводной сети
lsmod | grep -E "8812|8814|mt76|mt79"

# Сообщения ядра о USB и беспроводных событиях
dmesg | grep -iE "rtl|mt76|mt79|usb 802|wlan"

# Список всех беспроводных интерфейсов
iw dev

# Какой драйвер использует конкретный интерфейс
ethtool -i wlan0 | grep driver

# Детали USB-устройства
lsusb -v -d 0bda:8812 2>/dev/null | grep -E "idVendor|idProduct|iProduct"

# Статус DKMS для всех зарегистрированных модулей
dkms status
```

## Итог

Установка WiFi-драйвера в Linux следует простому алгоритму:

1. **Определите чипсет** с помощью `lsusb` и таблицы соответствия выше
2. **MT7612U или MT7921AUN (на ядре 5.18+)?** → Просто выполните `modprobe` — готово
3. **RTL8812AU ил?** → Клонируйте нужный репозиторий, выполните `make && sudo make install`, включите DKMS для сохранения
4. **Что-то не работает?** → Смотрите таблицу устранения неполадок, проверьте совпадение заголовочных файлов с ядром, изучите `dmesg`

Преимущество адаптеров ALFA Network в том, что для всех четырёх основных чипсетов существуют хорошо задокументированные, активно поддерживаемые решения. Вы никогда не окажетесь в ситуации отсутствия поддержки.
