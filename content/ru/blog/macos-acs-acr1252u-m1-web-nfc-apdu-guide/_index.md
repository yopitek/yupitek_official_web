> **⚠️ Самое важное ограничение поддержки — сначала (прочитайте перед покупкой)**

> 2. **Safari на macOS и iOS (любой браузер) вообще не поддерживают Web NFC**; на iOS доступ к NFC возможен только через нативный фреймворк Core NFC (требуется написать приложение).
> 3. **Web NFC в браузере использует «встроенный в устройство контроллер NFC»** (например, телефон Android или ноутбук ChromeOS), **а не** внешний USB-считыватель. Внешний ACR1252U-M1 работает по стандарту PC/SC и управляется командами APDU из локальных программ — это два отдельных пути, поэтому перед покупкой уточните свою целевую платформу.

## Вступление: одна NFC-карта, два пути разработки

Представьте, что у вас есть метка NTAG215 для контроля доступа или защиты продукции, и вы хотите превратить её в данные, которые можно читать и записывать в «браузере». Одновременно вы хотите написать на macOS утилиту, которая заставит считыватель «пикнуть один раз и загореться зелёным» с помощью байтов.

Эти две задачи соответствуют двум совершенно разным технологиям:

1. **Web NFC API**: в поддерживаемых браузерах (Chromium на Android／ChromeOS) несколько строк JavaScript читают и записывают метки NDEF напрямую — без какого-либо аппаратного считывателя.
2. **APDU (Application Protocol Data Unit)**: через стандарт PC/SC локальные программы (Swift, Python…) отправляют считывателю байтовые команды, расширяя управление за пределы карты на само устройство — например, на зуммер и двухцветный светодиод считывателя.

**ACS ACR1252U-M1** подходит в качестве первого считывателя для разработки, потому что он соответствует стандарту **CCID** и имеет сертификацию **PC/SC** и **NFC Forum**: на macOS он работает **сразу после подключения, без установки сторонних драйверов**. Ниже три раздела: «почему нативная поддержка важна», «как применять Web NFC на практике» и «как управлять светом и звуком через APDU», а в конце — контрольный лист перед покупкой.

## 1. CCID и PC/SC на Mac с Apple Silicon: почему «нативная поддержка» важна для разработчиков

### 1.1 Три термина по порядку: CCID, PC/SC и нативная поддержка

| Термин | Полное название | Объяснение в одной фразе |
|---|---|---|
| CCID | Chip Card Interface Device | **Стандартный класс USB (USB Class)**, определяющий, как считыватели смарт-карт общаются по USB. У устройств, совместимых с CCID, протоколом управляет операционная система. |
| PC/SC | Personal Computer/Smart Card | **Стандарт API**, позволяющий приложениям обращаться к считывателям смарт-карт через единый интерфейс, независимо от чипа внутри. |
| Нативная поддержка | Driverless / Built-in Driver | Операционная система **встроила** драйвер этого класса; пользователь подключает устройство — и оно работает, без «установки диска с драйвером производителя». |

Простыми словами: CCID оформляет «как считыватель разговаривает с компьютером» в единую USB-спецификацию, а PC/SC оформляет «как приложения вызывают считыватель» в единый API. Когда есть и то и другое, операционная система поддерживает устройство на уровне ядра — это и есть «нативная поддержка».

ACR1252U-M1 имеет сертификации **CCID, PC/SC, NFC Forum и FeliCa Performance** (как указано в спецификации). Это значит, что он работает по принципу plug-and-play на **любой** операционной системе, реализующей эти два стандарта.

### 1.2 Почему это особенно важно на Apple Silicon

В эпоху Apple Silicon (M1／M2／M3／M4) macOS значительно ужесточила ограничения на сторонние драйверы:

- **Расширения ядра (Kernel Extension / kext) считаются переходной технологией**: обновления системы и безопасность загрузочного диска (Secure Boot) жёстко блокируют неподписанные и не прошедшие нотаризацию драйверы. Поддерживать драйвер macOS, который пользователи действительно могут «установить», стоит очень дорого, и многие продукты просто отказываются от этого.
- **В macOS встроен фреймворк Smart Card Services**, который уже включает поддержку считывателей CCID. Поэтому считывателю, совместимому с CCID, **не нужен драйвер производителя на macOS** — операционная система распознаёт его сама.

В этом и есть настоящая ценность «нативной поддержки»: вам не нужно ждать от производителя новый драйвер для серии M и не нужно беспокоиться о Team ID или нотаризации. **Крупные обновления macOS также не влияют на работу считывателя**.

Проверка того, что система распознала считыватель (на macOS):

```bash
# Просмотр считывателей смарт-карт (появление ACR1252U / ACS означает, что система его перечислила)
system_profiler SPCardReaderDataType

# После установки pcsc-tools (пакет brew) можно следить в реальном времени через pcsc_scan
brew install pcsc-tools
pcsc_scan
```

### 1.3 Практическое значение для разработчиков

| Сценарий разработки | Считыватель без CCID | ACR1252U-M1 (CCID／PC/SC) |
|---|---|---|
| Установка драйвера на macOS | Установщик производителя + подпись и нотаризация | **Без установки, подключил и работай** |
| После крупного обновления macOS | Часто выходит из строя (истёкшая подпись или отклонённый kext) | Не затрагивается |
| Смена компьютера для разработки | Переустановка драйвера на каждой машине | Просто подключить |
| Кроссплатформенность (macOS／Linux／Windows) | Драйверы разных производителей несовместимы | Одни и те же команды PC/SC |
| Защита безопасности macOS | Некоторые требуют снижения уровня безопасности для загрузки | **Отключать защиту не нужно вообще** |

> **Красная линия безопасности**: этот продукт и все сценарии статьи работают при настройках безопасности macOS по умолчанию (полная безопасность, защита целостности системы SIP включена). Если на другой платформе драйвер не загружается, **не обходите это отключением Secure Boot или снижением уровня безопасности** — правильный путь: устройство, совместимое со стандартом CCID, или поддерживаемая ОС процедура подписи.

## 2. Web NFC API на практике: чтение и запись NTAG213 / NTAG215 в браузере

### 2.1 Сначала проверьте охват поддержки (ключевой момент Support Reduction)

Web NFC API (интерфейсы `NDEFReader`／`NDEFWriter`) **есть не во всех браузерах**. В таблице ниже — фактическое положение дел на 2026 год:

| Среда | Браузер | Web NFC (NDEFReader) | Примечания |
|---|---|---|---|
| Android | Chrome／Edge／Samsung Internet (на базе Chromium) | ✅ Поддерживается | Требуется HTTPS или localhost, а также жест пользователя |
| ChromeOS | Встроенный Chrome в ChromeOS | ✅ Поддерживается | Устройство должно иметь контроллер NFC |
| macOS, настольный | Chrome／настольный Edge | ❌ Не поддерживается | **В настольном Chrome нет Web NFC** |
| macOS, настольный | Safari | ❌ Не поддерживается | Нет ни в одной версии Safari |
| Windows／Linux, настольный | Настольные Chrome／Edge／Firefox | ❌ Не поддерживается | Web NFC не открыт для настольных версий |
| iOS (iPhone／iPad) | Любой браузер (включая Chrome и Edge iOS) | ❌ Не поддерживается | Все браузеры iOS используют WebKit; для NFC — только Core NFC в нативном приложении |

**Вывод**: чтобы «по-настоящему» работать с NFC-метками в браузере, вам нужен **телефон Android или устройство ChromeOS**. На настольном macOS ценность ACR1252U-M1 — в **разработке локальных программ через PC/SC**, о которой говорится во второй и третьей главах: чтение и запись тех же меток или отправка команд APDU для управления считывателем.

> **Ещё одно ключевое заблуждение**: Web NFC в браузере использует **встроенный в устройство чип NFC** (контроллер NFC телефона или ноутбука ChromeOS); **внешний USB-считыватель браузерный Web NFC не использует никогда**. Так что «подключил ACR1252U-M1 к Chromebook — и веб-страница читает карты» — это не так. Аппаратный источник у двух путей разный.

### 2.2 Нужные метки: NTAG213 и NTAG215

Формат NDEF, который использует Web NFC, чаще всего сочетается с метками **NFC Forum Type 2**, то есть семейством **NTAG213 / NTAG215 / NTAG216** от NXP (часто применяется в контроле доступа, визитках, защите от подделок, заменителях Amiibo и т. д.):

| Параметр | NTAG213 | NTAG215 |
|---|---|---|
| Память пользователя | 144 bytes | 504 bytes |
| Доступная ёмкость NDEF | около 137 bytes | около 496 bytes |
| Типичное применение | Короткие ссылки, одна визитка, небольшие данные | Данные среднего объёма (более длинный JSON／несколько записей) |
| Скорость чтения/записи | 106 kbps (фактически определяет считыватель) | 106 kbps |
| Безопасность | Защита одним паролем | Защита одним паролем |

> О ёмкости: в 137 bytes помещается примерно 130 английских символов; для среднего контента до 1 КБ или для эксперимента «несколько записей на одной карте» выбирайте NTAG215. На начальном этапе разработки рекомендуется **запастись пачкой пустых меток** (пустые, незаблокированные, без пароля) — удобно перезаписывать многократно.
>
> Про «блокировку» нужно различать два случая: после **установки пароля** вы всё ещё можете пройти проверку командой PWD_AUTH и продолжить запись; по-настоящему необратимо — **запись битов блокировки (Lock Bits)**: как только они заблокированы, право записи не вернётся никогда.

### 2.3 Пример чтения (NDEFReader.scan)

Сначала откройте страницу **HTTPS (или localhost)** в Android Chrome／ChromeOS Chrome и поднесите метку к зоне NFC-антенны устройства. Пример:

```html
<!DOCTYPE html>
<html lang="zh-Hant">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Web NFC 讀寫示範</title>
</head>
<body>
  <h1>Web NFC 讀寫示範</h1>
  <button id="btnScan">開始掃描</button>
  <button id="btnWrite">寫入標籤</button>
  <pre id="output"></pre>

  <script>
    const out = (msg) => {
      document.getElementById('output').textContent += msg + '\n';
    };

    if (!('NDEFReader' in window)) {
      out('此瀏覽器不支援 Web NFC（NDEFReader）。\n請改用 Android Chrome 或 ChromeOS Chrome。');
    }

    // 讀取：scan() 需使用者手勢觸發
    document.getElementById('btnScan').addEventListener('click', async () => {
      try {
        const reader = new NDEFReader();
        await reader.scan();
        out('已開始掃描，請將標籤靠近手機 NFC 感應區…');

        reader.onreading = (event) => {
          out('--- 讀取到標籤 ---');
          out('序列號（Serial Number）：' + event.serialNumber);
          for (const record of event.message.records) {
            out('recordType：' + record.recordType);
            if (record.recordType === 'text' || record.recordType === 'url') {
              out('內容：' + record.data);
            } else {
              out('內容（二進位 ByteArray）：' + new Uint8Array(record.data));
            }
          }
        };

        reader.onreadingerror = () => out('讀取錯誤：請確認標籤是否支援 NDEF。');
      } catch (err) {
        out('scan() 失敗：' + err.name + ' / ' + err.message);
      }
    });
  </script>
</body>
</html>
```

> Для меток NTAG213／NTAG215 (Type 2) `event.message` разбивает NDEF-сообщение метки на `records`: у типов `text` и `url` поле `record.data` уже является строкой; остальные типы приходят как `ArrayBuffer` и требуют преобразования.

### 2.4 Пример записи (NDEFReader.write)

Замените обработчик кнопки выше на:

```javascript
// 寫入：write() 同樣需使用者手勢，且標籤需在感應範圍內
document.getElementById('btnWrite').addEventListener('click', async () => {
  try {
    const writer = new NDEFReader();

    // 方式一：直接寫一段文字（自動包成 text 記錄）
    // await writer.write('Yupitek Web NFC 測試');

    // 方式二：寫入一筆網址記錄（適合名片、導流）
    await writer.write({
      records: [
        { type: 'url', data: 'https://www.yupitek.com' },
        { type: 'text', data: 'ALFA / ACS 產品技術部落格' },
      ],
    });

    out('寫入成功！');
  } catch (err) {
    out('寫入失敗：' + err.name + ' / ' + err.message);
  }
});
```

После записи поднесите ту же метку к ACR1252U-M1 (или к любому инструменту чтения с поддержкой NDEF), чтобы убедиться, что содержимое записано правильно.

### 2.5 Частые ошибки (подсказки по Debugging)

| Симптом | Причина | Способ решения |
|---|---|---|
| Страница сообщает «NDEFReader is not defined» | Настольные Chrome／Safari／Firefox не поддерживают Web NFC | Используйте Android Chrome или ChromeOS; на macOS — путь PC/SC |
| `scan()` выбрасывает NotAllowedError | Нет жеста пользователя или страница не HTTPS | Вызывайте после нажатия кнопки; для локальной разработки используйте `http://localhost` |
| Метка определяется, но onreadingerror срабатывает постоянно | Недостаточная ёмкость, повреждённый формат или карта не поддерживает NDEF | Попробуйте пустую незаблокированную NTAG213/215 |
| Запись обрывается на середине | Метка заблокирована (Lock Bits) или превышена ёмкость | Проверьте ёмкость (137／496 bytes) и биты блокировки; заблокированные метки не восстанавливаются |
| Нет событий после ухода с вкладки／выключения экрана | Web NFC работает только когда вкладка **на переднем плане и в фокусе** | Держите вкладку открытой; фоновое сканирование — не предназначение Web NFC |

> **Предупреждение о безопасности (чего делать не нужно)**: Web NFC может читать и записывать только то, «что метка позволяет». Если карта реализует проверку пароля, защищённый канал ISO 14443-4 или шифрование (например, серверную проверку в системе контроля доступа), **браузер не может — и не должен — обходить её механизм безопасности**. Все уроки этой статьи ограничены пустыми метками и тестовыми картами, которые принадлежат вам или на использование которых у вас есть разрешение.

## 3. Разработка команд APDU: управление зуммером и двухцветным светодиодом с помощью байтов

APDU — это «низкоуровневый язык» мира смарт-карт и считывателей. Web NFC упаковывает формат данных за вас; но **управление самим считывателем ACR1252U-M1 на macOS — светом и зуммером — требует прямой отправки APDU**.

### 3.1 Базовая структура APDU

Команда, отправляемая считывателю／карте, — это последовательность байтов следующего формата:

```
CLA  INS  P1  P2  Lc   Data(0~N bytes)   Le
└─класс команды┘└─команда┘└─параметры┘  └─длина данных┘  └─ожидаемая длина ответа┘
```

- **CLA**: класс команды (0x00 = стандарт ISO 7816; 0xFF = собственное пространство команд производителя).
- **INS**: код команды (0xA4 = SELECT, 0x20 = VERIFY, 0xCA = GET DATA…).
- **P1 P2**: два байта параметров.
- **Lc**: длина следующих за ним Data (можно опустить).
- **Le**: ожидаемая длина ответа (Response) (можно опустить).

Ответ — это данные плюс два завершающих байта **SW1 SW2**; распространённые значения: `90 00` (успех), `6A 82` (файл не найден), `63 00` (проверка не пройдена).

### 3.2 Подготовка среды разработки на macOS

В macOS уже встроена поддержка PC/SC, поэтому достаточно установить `pyscard` для Python, чтобы сразу отправлять APDU:

```bash
# Установка pcsc-tools (включает pcsc_scan, удобно для проверки считывателя)
brew install pcsc-tools

# Установка pyscard (через системный фреймворк PC/SC в macOS)
pip install pyscard

# Проверка, что pyscard видит считыватели
python3 -c "from smartcard.System import readers; print(readers())"
# Ожидаемый вывод, примерно: ['ACS ACR1252U ... 00 00']
```

### 3.3 Первая APDU: Echo и версия прошивки

ACR1252U-M1 поддерживает стандартную «команду Echo» от ACS — её можно использовать как тест соединения; затем прочитайте версию прошивки, чтобы убедиться, что связь с компьютером в порядке:

```python
from smartcard.System import readers
from smartcard.util import toHexString

reader = readers()[0]
conn = reader.createConnection()
conn.connect()

# 1) Echo: возвращает ASCII "12345678"
sw, data = conn.transmit([0xFF, 0x00, 0x00, 0x00, 0x00])
print('Echo SW :', toHexString(sw))
print('Echo 回傳:', ''.join(chr(b) for b in data))

# 2) Версия прошивки
sw, data = conn.transmit([0xFF, 0x00, 0x48, 0x00, 0x00])
print('Firmware:', toHexString(data))
```

Появление `12345678` означает, что канал PC/SC исправен и прошивка считывателя отвечает нормально.

### 3.4 Отправка APDU на карту: пример MIFARE DESFire

Представьте бесконтактную карту как «байтовую почтовую систему»: вы отправляете команду — она возвращает данные. На примере тестовой карты **MIFARE DESFire**, поддерживающей настоящий APDU (ISO 14443-4), отправьте команду «Get Version» (`90 60 00 00 00`):

```python
# DESFire GetVersion: первый байт ответа 0x04 означает семейство DESFire (EV1/EV2/EV3)
sw, data = conn.transmit([0x90, 0x60, 0x00, 0x00, 0x00])
print('SW  :', toHexString(sw))
print('Data:', toHexString(data))
# Например: 04 01 01 00 04 12 08 01
#           └DESFire┘└строка версии┘     └прошивка/аппаратура/партия производства…┘
```

> Если DESFire под рукой нет, можно использовать **команду PPSE** для пассивного зондирования любой бесконтактной платёжной карты EMV: `00 A4 04 00 0E 32 50 41 59 2E 53 59 53 2E 44 44 46 30 31 00` (SELECT "2PAY.SYS.DDF01"). Только на своих тестовых картах.

### 3.5 Управление зуммером и двухцветным (красным／зелёным) светодиодом

В корпусе ACR1252U-M1 установлены **двухцветный светодиод (красный／зелёный)** и **однотональный зуммер** — оба «управляются пользователем». Это самый распространённый способ обратной связи о состоянии в приложениях: проверка карты пройдена → один писк + зелёный свет; проверка не пройдена → красное мигание. Результат виден, не глядя на экран.

Для управления такими функциями «корпуса считывателя» используется **собственное пространство команд производителя** (команды APDU с префиксом `FF`; `CLA=0xFF` — зарезервированная область команд производителя). Типовая структура такая (**соответствие байтов зависит от версии прошивки; перед разработкой сверяйтесь с официальным документом ACS «ACR1252U-M1 Application Programming Interface»**):

```
FF  00  40  00  04  00  00  <LED>  <BUZZER>
└─префикс команды производителя─┘   └Len┘ └─параметры─┘  └свет┘ └длина писка┘
```

| Параметр | Пример значения | Смысл (по примеру прошивки) |
|---|---|---|
| LED | 0x00 | Выключен |
| LED | 0x01 | Красный свет |
| LED | 0x02 | Зелёный свет |
| LED | 0x03 | Красный＋зелёный одновременно |
| BUZZER | 0x00 | Без писка |
| BUZZER | 0x04 | Писк около 1 секунды (единица времени — по официальному документу)|

```python
# Зелёный свет + короткий писк (пример байтов; сверьтесь с официальным API-документом вашей прошивки)
sw, data = conn.transmit([0xFF, 0x00, 0x40, 0x00, 0x04, 0x00, 0x00, 0x02, 0x04])
print('LED/Buzzer 回應:', toHexString(sw))   # ожидается 90 00 (успех)

# Выключить
sw, data = conn.transmit([0xFF, 0x00, 0x40, 0x00, 0x04, 0x00, 0x00, 0x00, 0x00])
```

> **Замечание для разработки**: определения байтов и единицы времени могут различаться между версиями прошивки. Правильный порядок: сначала прочитайте версию прошивки командой из `3.3`, затем сверьтесь с официальным API-документом этой версии, чтобы подтвердить определения байтов `LED`／`BUZZER`, и проверьте реальным ответом `SW1 SW2 = 90 00`. Цель примеров в этой статье — показать метод разработки «управление корпусом устройства байтами», а не обход механизма проверки какой-либо карты.
>
> **Красная линия безопасности**: управление зуммером и светодиодом — это **видимое поведение самого считывателя** и не связано с тем, «можно ли скопировать или подделать содержимое карты». Эта статья **не предоставляет** и не затрагивает никаких методов копирования бесконтактных карт доступа, обхода паролей или проверок безопасности карт; все тесты APDU проводите только на картах и устройствах, которые принадлежат вам или на использование которых у вас есть явное разрешение.

## 5. Заключение

Для разработчиков на Apple Silicon «нативная поддержка» — не прилагательное, а **проверяемый инженерный факт**. Благодаря стандартам CCID / PC/SC ACR1252U-M1 позволяет начать разработку на macOS без установки каких-либо драйверов. В сочетании с Web NFC (Chromium／Android／ChromeOS) и PC/SC APDU (локально на macOS) одна и та же партия меток NTAG213／NTAG215 позволяет полностью отработать «чтение, запись, управление» на обоих технических путях.

Запомните две вещи: **сначала проверьте охват поддержки вашего браузера** (Web NFC ограничен Chromium на Android／ChromeOS), **затем решите, нужно ли вам управлять корпусом считывателя** (это работа APDU). Остальное — дело байтов.

| Симптом | Что проверить | Частая причина и решение |
|---|---|---|
| `system_profiler SPCardReaderDataType` не показывает считыватель на macOS | Сменить порт USB-A／проверить кабель | Проблема кабеля или питания; ACR1252U-M1 не требует дополнительных драйверов, **не скачивайте сторонние kext** |

| Ответ APDU `6F 00` или неожиданный код SW | Проверить длину команды и префикс | Пространство команд производителя — по официальному API-документу; байты нельзя собирать произвольно |
| Зуммер／светодиод не реагируют | Проверить версию прошивки, затем таблицу команд | Байты управления светом зависят от версии прошивки; ориентируйтесь на официальный документ этой версии |
