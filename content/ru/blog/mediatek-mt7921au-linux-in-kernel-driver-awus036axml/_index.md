## Вступление: те дни, когда «после каждого обновления системы приходилось перекомпилировать драйвер»

Если вы пользовались USB-адаптером на чипсете класса Realtek RTL8812AU (например, популярным AWUS036ACH), вам, скорее всего, знакомо нечто подобное:

1. Вы установили драйвер, поддерживаемый сообществом; интернет и мониторинг работают нормально.
2. В один из дней вы выполняете `sudo apt upgrade`, и ядро Linux обновляется до новой версии.
3. После перезагрузки адаптер исчезает из системы — интерфейс Wi-Fi (`wlan0` / `wlan1`) не появляется вовсе.
4. Приходится **заново скачивать исходный код, устанавливать DKMS и перекомпилировать модуль ядра**, теряя на это всю вторую половину дня.

Проблема не в самом продукте, а в форме существования драйвера. Большинство драйверов Realtek для Linux не включены в ядро Linux (mainline). Чтобы ими пользоваться, нужно «прикручивать» внешний исходный код к системе. При каждом обновлении ядра эту прикрутку приходится перекомпилировать, иначе она перестаёт соответствовать новой версии ядра и выходит из строя.

А герой сегодняшней статьи — ALFA AWUS036AXML на базе MediaTek MT7921AU — идёт совершенно другим путём: его драйвер **изначально живёт внутри ядра Linux**.

## 1. Почему компиляция драйвера Realtek ломается при обновлении ядра Linux

### 1.1 Суть: модули ядра (Kernel Module) жёстко привязаны к версии ядра

Ядро Linux загружает драйверы устройств динамически, в виде «модулей». Ключевой момент: **модуль компилируется под конкретную версию ядра**. После крупного обновления ядра (например, 6.8 → 6.9) старые модули обычно не загружаются на новом ядре — их нужно перекомпилировать.

### 1.2 DKMS: спаситель автоматической перекомпиляции и новая головная боль

DKMS (Dynamic Kernel Module Support) создан именно для решения проблемы «ядро обновилось — модуль нужно перекомпилировать». При каждом обновлении ядра он **автоматически перекомпилирует драйвер за вас**. Звучит прекрасно, но на практике вы всё равно столкнётесь со следующим:

- **Проблемы с инструментарием**: для компиляции нужны `build-essential`, `dkms` и нативные заголовочные файлы ядра (`linux-headers-$(uname -r)`). Если чего-то не хватает, сборка DKMS сразу падает.
- **Несовместимость версий**: самое неприятное — когда ядро обновляется раньше, чем драйвер на GitHub успевает подстроиться под новые изменения API. Вы никогда не знаете, не станет ли очередной `apt upgrade` тем самым.
- **Secure Boot / подпись модулей ядра**: если в системе включён Secure Boot, неподписанные модули ядра отклоняются, и интерфейс адаптера не появляется вовсе. Решается это не отключением защиты, а импортом самоподписанного сертификата через механизм MOK (Machine Owner Key). Ещё одна лишняя операция.
- **Мучительный выбор версии сообщества**: у одного и того же чипсета на GitHub несколько веток — `aircrack-ng/rtl8812au`, `morrownr/8812au-20210820` и другие — с разными версиями и разным диапазоном поддержки ядер. Ошибётесь с выбором — компиляция насмарку.

### 1.3 Настоящая цена — ваше время

Если вы компилируете один раз при установке — это нормально; но **пока система продолжает обновляться, этот драйвер становится вашей постоянной обязанностью по обслуживанию**. Для специалистов по тестированию на проникновение и разработчиков встраиваемых систем ценное время должно уходить на инструменты и скрипты, а не на перекомпиляцию драйвера сетевого адаптера.

## 2. MediaTek MT7921AU: почему «нативная поддержка, plug-and-play» работает

### 2.1 Как достигается нативная поддержка: mt76 и mt7921u

Драйверы Wi-Fi-чипсетов MediaTek давно живут внутри фреймворка беспроводных драйверов mt76 в ядре Linux. Серия MT7921 включает версии PCIe и USB:

- Серия MT7921 вошла в основное ядро (mainline) начиная с Linux Kernel 5.12 (версии PCIe / M.2);
- В AWUS036AXML используется драйвер `mt7921u` для USB, нативно включённый в mainline начиная с Linux Kernel 5.18.

Иными словами, **не нужно скачивать исходный код с GitHub, не нужен DKMS, не нужно ничего компилировать самому**. Если ядро вашего дистрибутива достаточно свежее, достаточно подключить адаптер и добавить файлы прошивки (firmware) — и всё готово. Интерфейс появится в `ip link`.

### 2.2 Вам нужна только прошивка (Firmware), а не исходный код драйвера

Многие думают, что «не нужно компилировать» означает «не нужно ничего устанавливать». Это не так: «не нужно компилировать драйвер» не значит «не нужно устанавливать вообще ничего». MT7921AU требует **файлы прошивки (firmware)**, а не исходный код драйвера. Прошивка управляется как пакет дистрибутива — обычно достаточно одной команды:

```bash
sudo apt update
sudo apt install linux-firmware firmware-misc-nonfree   # семейство Debian / Kali
sudo reboot
```

В Ubuntu обычно так:

```bash
sudo apt update
sudo apt install linux-firmware
sudo reboot
```

Прошивка — это пакет, который «следует за дистрибутивом»; обновление ядра её не сломает. Именно в этом принципиальная разница в стоимости обслуживания по сравнению с «драйвером DKMS».

Минимальные требования к ядру по дистрибутивам — всё в одной таблице:

| ОС / дистрибутив | Минимальное ядро | Нужна ли компиляция драйвера? |
|---|---|---|
| Kali Linux (Rolling) | 6.x (включает `mt7921u`) | Нет, достаточно добавить прошивку |
| Debian 12 | 6.1 LTS | Нет |
| Ubuntu 22.04+ / 24.04 LTS | 5.18 и выше (рекомендуется ядро HWE) | Нет |
| Raspberry Pi OS (Bookworm) | 6.1 LTS | Нет |
| Старые дистрибутивы Linux | ниже 5.18 | Требуется дополнительное развёртывание; не рекомендуется |
| Windows 10 / 11 | — | Драйвер производителя |
| macOS (Intel / Apple Silicon) | Не поддерживается | **Драйвера нет — не покупайте** |

> **⚠️ Самое важное предупреждение о поддержке перед покупкой**: AWUS036AXML **не поддерживает macOS**. Ни для Intel, ни для Apple Silicon драйвера MT7921AU для macOS сейчас не существует. Если macOS — ваша основная среда, такие внешние USB-адаптеры Wi-Fi 6 / 6E для вас бесполезны — сразу исключите их из рассмотрения, а не обнаруживайте это после покупки.

### 2.3 Почему «нативная поддержка» особенно важна для разработчиков Kali

В Kali Linux ядро обновляется очень часто (это дистрибутив с плавающим выпуском, Rolling). Пользователи RTL8812AU замирают при каждом обновлении. `mt7921u`, напротив, сопровождается и тестируется вместе с ядром — **каким бы новым ни было ядро, драйвер за ним успевает**. ALFA позиционирует этот продукт именно для тестов безопасности: режим монитора (Monitor Mode) и инъекция пакетов (Packet Injection) — стандартные функции, работающие сразу из коробки.

## 3. AWUS036AXML в Kali Linux: plug-and-play и режим монитора на практике

### 3.1 Подключить, проверить, работать: три шага

Подключите адаптер к порту USB-C (в комплекте кабель 2-in-1 USB-C/USB-A) и выполните:

```bash
lsusb                 # должно появиться устройство MediaTek с ID 0e8d:7961
ip link               # должен появиться интерфейс wlanX
sudo apt install linux-firmware firmware-misc-nonfree
sudo reboot
```

После перезагрузки проверьте интерфейс:

```bash
iwconfig              # wlanX должен отображаться в режиме Managed
ip addr show wlanX    # адрес получается нормально
```

Даже для подключения по умолчанию NetworkManager в обычных дистрибутивах (включая Kali) видит его напрямую — **никакие сайты с исходным кодом на GitHub не нужны**.

Когда я впервые подключил AXML к Kali, увидев `0e8d:7961` в `lsusb`, я сразу успокоился — без clone, без компиляции; после перезагрузки интерфейс появился сам.

### 3.2 Тест режима монитора и инъекции пакетов

Предположим, ваш интерфейс — `wlan1`:

```bash
sudo ip link set wlan1 down
sudo iw dev wlan1 set type monitor
sudo ip link set wlan1 up
iw dev wlan1 info     # убедитесь, что type показывает monitor
```

Поздравляем: `wlan1` теперь пассивно прослушивает кадры 802.11, и можно подключать Wireshark или набор aircrack-ng и продолжать работу.

Затем проверяем инъекцию пакетов:

```bash
sudo aireplay-ng --test wlan1
```

Появление `Injection is working!` (или эквивалентного вывода) означает, что инъекция работает. В нативном драйвере `mt7921u` эта возможность встроена — никаких дополнительных Hacks не нужно.

### 3.3 Режим слияния (VIF / Fusion): управление и мониторинг одновременно

Многие сценарии тестирования на проникновение требуют, чтобы адаптер «оставался клиентом в интернете и одновременно мониторил». Нативный драйвер поддерживает это через виртуальные интерфейсы (Virtual Interface):

```bash
sudo iw dev wlan1 interface add mon0 type monitor
sudo ip link set mon0 up
```

При этом `wlan1` остаётся в режиме managed (для интернета), а `mon0` занимается мониторингом. Чтобы стабильно добиться этого на драйвере RTL8812AU, обычно приходится править кучу конфигурационных файлов — нативный драйвер просто отдаёт вам эту возможность.

> **⚠️ Красная линия законного использования**: объектами тестирования режима монитора, инъекции пакетов, Evil Twin и подобных возможностей **могут быть только сети, которыми вы владеете или на тестирование которых у вас есть явное разрешение** (собственная лаборатория, разрешённый компанией тестовый сегмент). Любая несанкционированная разведка или вторжение в сети может нарушать местные законы. Соблюдайте правовые границы; данная статья — техническое описание для академических и инженерных целей.

## 4. Оценочный лист перед покупкой: «нативный, без компиляции» или «адаптер на DKMS»?

Чтобы снизить расходы на поддержку после покупки, сначала пройдите эту простую оценку, а затем решайте, покупать AWUS036AXML или AWUS036ACH.

### 4.1 Быстрое сравнение двух адаптеров

| Параметр оценки | AWUS036AXML (MT7921AU) | AWUS036ACH (RTL8812AU) |
|---|---|---|
| Беспроводные характеристики | Wi-Fi 6E, три диапазона (2,4/5/6 ГГц) | AC1200, два диапазона (2,4/5 ГГц) |
| Интерфейс USB | USB-C (USB 3.2 Gen 1) | USB 3.0 Type-A |
| Драйвер Linux | `mt7921u` **нативно в ядре 5.18+** | Требуется внешняя компиляция через DKMS |
| Сложность установки | Достаточно добавить прошивку | Инструментарий + компиляция + (при Secure Boot) подпись |
| Влияние обновления ядра | Никакого | Перекомпиляция после каждого обновления |
| Режим монитора | Нативная поддержка | Поддерживается |
| Инъекция пакетов | Нативная поддержка | Поддерживается |
| macOS | Не поддерживается | Не поддерживается |
| Для кого | Современные Linux / Kali / встраиваемые системы | Старые системы или сценарии с 2,4/5 ГГц |

### 4.2 Чек-лист решения за полминуты

Чем больше пунктов совпадает с описанием ниже, **тем более оправдан прямой выбор AWUS036AXML**:

- [ ] Моя основная система — **Kali Linux / Ubuntu / Debian** с ядром 5.18 и выше.
- [ ] Мне нужно, чтобы **работало сразу после подключения**, без `dkms`, `github clone` и инструментария компиляции.
- [ ] Мне нужна нативная поддержка семейства `mt76`, и обновления ядра не должны влиять на адаптер.
- [ ] Мне нужен **диапазон 6 ГГц** (окружение с роутером Wi-Fi 6E).
- [ ] Основные сценарии: мониторинг, инъекция пакетов, Soft AP, режим слияния (VIF).
- [ ] Я буду подключать адаптер к ноутбуку или одноплатному компьютеру прилагаемым кабелем 2-in-1 USB-C / USB-A.

И наоборот: если 6 ГГц вам не нужен, система работает на старом ядре ниже 5.18 и вы знакомы с процедурой обслуживания DKMS, у AWUS036ACH всё ещё есть своё место. Но будьте готовы: при каждом обновлении ядра драйвер придётся перекомпилировать.

## 5. Заключение

Для современных разработчиков Linux и Kali время — самый большой ресурс. **MediaTek MT7921AU (AWUS036AXML) снимает с вас бесконечное бремя «обслуживания драйвера»**. Драйвер живёт в ядре, прошивка ставится одним пакетом, мониторинг и инъекция работают из коробки — плавающих обновлений ядра можно не бояться.

Перед покупкой достаточно проверить две вещи: **ядро системы ≥ 5.18** и **не macOS**. Остальное сделает нативный драйвер.

## Приложение: быстрый приём устранения неполадок (для поддержки и пользователей)

Если после подключения адаптера интерфейс не появился, проверяйте по порядку:

1. Показывает ли `lsusb` устройство `0e8d:7961` (MediaTek)? → Если нет, смените порт USB или проверьте питание.
2. Выполните `sudo apt install linux-firmware firmware-misc-nonfree` и перезагрузитесь → неустановленная прошивка — причина номер один.
3. Появляется ли `wlanX` в `ip link`? → Если нет, проверьте, что версия ядра (`uname -r`) ≥ 5.18.
4. **Сначала убедитесь, что ОС — не macOS** — для этого продукта нет драйвера macOS; по таким обращениям в ремонт не обращайтесь.
5. Если всё вышеперечисленное в порядке, а мониторинг всё равно не работает, проверьте, не используется ли по ошибке режим managed (`iw dev wlanX info` — посмотреть type).
