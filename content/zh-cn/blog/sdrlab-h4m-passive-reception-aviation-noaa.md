> - 嚴禁使用任何手段强化、改装本机为发射用途。

## 一、软件定義无线电（SDR）與被动接收的基本原理

### 1.1 什么是「软件定義无线电」？

傳统收音机把「选台、解调、放大」全部用硬件电路完成；而**软件定義无线电（Software Defined Radio, SDR）**把大部分工作交给通用硬件（模拟→数字转换后的数据流）與电脑里的软件搞定。硬件负責把天线抓到的高频信号降下来、数字化，剩下的解调（AM / FM / 解码 APT 衛星雲圖）全部由 **GQRX、SDR#、CubicSDR、GNU Radio** 这些开源软件在 CPU 上即时運算。

SDRlab H4M 的內部架构正是兩種关键芯片的组合：

| 元件 | 芯片 | 任务 |
|------|------|------|
| 调諧器（Tuner） | **R820T2** | 把 0.5MHz – 1.7GHz 的高频信号篩选並降频到中频 |
| 数字解调芯片 | **RTL2832U** | 8-bit ADC 数字化 + USB 將 I/Q 数据流送往电脑 |
| 晶振 | 溫度补償晶振（TCXO） | 提供稳定参考频率，避免频率漂移 |

硬件光譜范围涵蓋 **0.5 MHz（长波）到 1700 MHz（L 波段）**，因此 FM 广播、航空 AM、氣象衛星、ADS-B、甚至業余无线电都能收。最高稳定采樣带宽约 **2.4 MHz**（极限可达 3.2 MHz）。

### 1.2 什么是「被动接收」？

SDRlab H4M 的原理非常「老实」：**它只听，不发**。天线把空中的电磁波转成微弱的电压信号，接收器把这些信号放大、数字化后交给电脑。整个過程**不会向空中发射任何能量**，也因此是各國无线电法规中最友善、门檻最低的合法应用类型。

### 1.3 为什么鋁合金外殼对於「听得到微弱信号」至关重要？

这是 SDRlab H4M 最容易被忽略、卻最能影响成败的设計。

RTL-SDR 这类接收器非常灵敏，灵敏到连**不想要的东西**也一起收进来——尤其当你把它插在电脑旁：USB 供电的开关式电源雜訊、主机板高频频輻射、螢幕排线的电磁干扰，都会「灌进」接收前端，蓋過你真正想听的微弱信号（例如 800 公里外的衛星）。

鋁合金外殼在这里扮演三个角色：

1. **法拉第笼式的电磁屏蔽（EMI Shielding）**：金屬外殼形成局部屏蔽，阻擋来自电脑與週邊的环境射频雜訊，显着提升信号对雜訊比（SNR）。对於 NOAA 衛星这種只有幾秒鐘强的微弱信号，这往往是「收得到 / 收不到」的分水嶺。
2. **被动散热與频率稳定性**：鋁合金同时是良好的散热片。R820T2 调諧器对溫度敏感，溫度稳定 = 参考频率稳定，长期监听时不易漂移。
3. **靜电保护（ESD）與耐用性**：鋁殼接地能导走天线感应的靜电，延长前端芯片壽命。

一句话總結：**好的屏蔽不增加你的信号，而是帮你把雜訊擋在外面**——这在密集的城市电磁环境里，CP 值极高。

## 二、实作：接收 118–137 MHz 航空 AM 語音（GQRX / SDR#）

118 MHz 到 137 MHz（VHF 航空通訊频段）是航空器與地面塔台之间的**振幅调变（AM）語音通訊**。航班在起降階段会與塔台、近场台聯絡，內容包含高度、航向、跑道分配等。这是最容易入门、也最「有感」的频譜体验。

### 2.1 事前准備

- SDRlab H4M × 1
- 一台电脑（Windows / Linux / macOS 皆可）
- 天线：随附的偶极天线或伸縮天线即可，若要更好可用 V-Dipole 或调整天线长度到约 **1.1 公尺（=137MHz 半波长）** 附近
- 免費软件：**GQRX**（Linux/macOS）或 **SDR#（SDRSharp）**（Windows）

### 2.2 在 Linux 上用 GQRX

1. **安装**：
   ```bash
   sudo apt update
   sudo apt install -y rtl-sdr gqrx
   ```
2. **釋出 USB 装置**：RTL-SDR 会被 Linux 內建 TV 调諧器驅动（`dvb_usb_rtl28xxu`）搶佔，需先卸载再交给 `librtlsdr`：
   ```bash
   sudo rmmod dvb_usb_rtl28xxu
   # 一勞永逸：將 blacklist 寫入 /etc/modprobe.d/blacklist-rtl.conf
   # blacklist dvb_usb_rtl28xxu
   ```
3. **启动 GQRX**，第一次执行会跳出接收器设定視窗：
   - **Device** 选择 `Realtek RTL2838UHIDIR`（或对应 RTL-SDR 装置）
   - 确認采樣率（Sample Rate）设为 2.4 MHz 或 2.048 MHz
   - 點 **Start**
4. **切换到航空波段**：
   - 在频率输入框输入 `127600000`（可先试你所在机场进场频率，或在网络上搜尋当地的 ATIS／塔台频率）
   - **Mode（模式）选 `AM`**
   - 濾波器带宽（bandwidth）设 **8–12 kHz**（航空 AM 为窄频，太寬会收雜訊）
5. 若听到「沙沙声中夾着中文或英文語音」就成功了一半；试着在 118–137 间慢慢扫台。

### 2.3 在 Windows 上用 SDR#（SDRSharp）

1. **下载 SDR#**：到 RTL-SDR 官方网站下载 SDR# 压縮包並解压縮。
2. **安装 Zadig 驅动**（关键步驟）：把 RTL2832U 从 Windows 內建驅动切换成 **WinUSB**。开启 `zadig.exe` → Options 勾选 List All Devices → 选 RTL2832U → 點 **Replace Driver**。
3. 开启 `SDRSharp.exe`，在左上角确認装置被偵测，勾选 **RTL-SDR（Tuner A）**，按下播放键。
4. **Mode 选 `AM`**，频率输入 `118.000` – `137.000` MHz 之间的频率（注意显示单位为 MHz），再微调带宽與音量即可收听。

### 2.4 客服減量：航空接收常见排障檢查清单（Support Intake）

遇到「完全没有声音」时，依序檢查，並在聯繫客服前先完成此表：

| 症状 | 依序檢查 | 最常见原因 |
|------|---------|-----------|
| 电脑抓不到装置 | 1. USB 接孔换一个 ● 2. 线材再接一次 ● 3. 重新插拔 | USB 供电不足／接觸不良 |
| 扫不到任何台 | 1. 天线是否接上 ● 2. SMA 是否鎖緊 ● 3. 频率是否在 118–137MHz ● 4. 是否靠近窗邊 | 天线没接好或位置封闭 |
| 只有雜音没有語音 | 1. Mode 是否为 AM ● 2. 濾波带宽是否 8–12kHz ● 3. 机场是否太远 | 模式／带宽设定错误 |
| Linux 显示被佔用 | 执行 `lsusb` 看是否为 dvb_usb 驅动 | 需 blacklist `dvb_usb_rtl28xxu` |
| Windows 装置无法描述 | 重新执行 Zadig 套用 WinUSB | 驅动未正确替换 |

> 💡 客服小技巧：聯繫 yupitek 客服时，**附上 `lsusb` 或装置管理员截圖 + 你测试的频率與模式**，能让技术人员直接定位問题，来回时间縮短一半以上。

## 三、进階：解码 NOAA 氣象衛星即时 APT 模拟雲圖

听完語音后，接下来的进階关卡是把 **750 公里外的氣象衛星**「看」在螢幕上。这一步需要一點耐心與天线擺位，但成功那一刻的成就感无可取代。

### 3.1 原理：NOAA POES 衛星與 APT 信号

美國國家海洋暨大氣總署（NOAA）的 **NOAA-15、NOAA-18、NOAA-19** 三顆极軌氣象衛星每天多次通過台灣上空，持续广播 **APT（Automatic Picture Transmission）模拟信号**——把红外线與可见光雲圖以每分鐘 120 行的方式扫描广播：

| 衛星 | 下行频率（MHz） | 信号形式 | 带宽 |
|------|----------------|---------|------|
| NOAA-19 | **137.100** | APT 模拟 FM | ~34 kHz |
| NOAA-15 | **137.620** | APT 模拟 FM | ~34 kHz |
| NOAA-18 | **137.9125** | APT 模拟 FM | ~34 kHz |

衛星一次通過只有 **8–12 分鐘**，且信号强度随高度角劇烈变化，因此「預测軌道 + 正确天线 + 对的软件」三者缺一不可。

### 3.2 硬件擺位

1. **天线建议**：使用 **V-Dipole**（兩根 53 公分、夾角 120° 的偶极天线），这是業界公認 137 MHz 最划算的选择。
2. **視野**：让天线朝向天空开闊处（东南东或西南西方向），避开建築與金屬遮蔽。地平面愈乾淨，信号愈好。
3. **接收器设定（GQRX 范例，以 NOAA-19 为例）**：
   - 频率 `137.100 MHz`
   - **Mode：FM（WFM）**
   - 濾波带宽 **约 40 kHz**
4. **預测通過时间**：使用 **GPredict**（Linux/Windows）或 Heavens-Above 网站，查詢下一次 NOAA-19 高度角 > 30° 的通過时段。

### 3.3 解码流程（WXtoImg / SatDump）

1. **录製信号**：在衛星通過期间，用 GQRX 或 SDR# 將音訊录下来（或直接用虚拟音訊线把 FM 音訊送给解码器）。
2. **解码**：开启 **WXtoImg**（老牌免費软件）或跨平台开源的 **SatDump**，餵入音訊档，自动同步行扫描线並输出全彩衛星雲圖。
3. **產出**：约 10 分鐘后，你会得到一张覆盖东亞海域與台灣上空的可见光或红外线雲圖。
4. **进階細節**：衛星通過时会產生**都卜勒频移**（逼近时频率偏高、远离时偏低），进階玩家可在通過中途手动微调 ±3 kHz，或用自动追蹤频率的解码器提升成功率。

> 💡 第一次失败很正常——軌道預测误差、天线角度、遮蔽物都会影响成败。把每次通過的「频率误差 + 天线位置」記录下来，通常第二次第三次就能收到清晰雲圖。
