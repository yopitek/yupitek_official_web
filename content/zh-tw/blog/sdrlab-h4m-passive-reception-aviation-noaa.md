## 一、軟體定義無線電（SDR）與被動接收的基本原理

### 1.1 什麼是「軟體定義無線電」？

傳統收音機把「選台、解調、放大」全部用硬體電路完成；而**軟體定義無線電（Software Defined Radio, SDR）**把大部分工作交給通用硬體（類比→數位轉換後的資料流）與電腦裡的軟體搞定。硬體負責把天線抓到的高頻訊號降下來、數位化，剩下的解調（AM / FM / 解碼 APT 衛星雲圖）全部由 **GQRX、SDR#、CubicSDR、GNU Radio** 這些開源軟體在 CPU 上即時運算。

SDRlab H4M 的內部架構正是兩種關鍵晶片的組合：

| 元件 | 晶片 | 任務 |
|------|------|------|
| 調諧器（Tuner） | **R820T2** | 把 0.5MHz – 1.7GHz 的高頻訊號篩選並降頻到中頻 |
| 數位解調晶片 | **RTL2832U** | 8-bit ADC 數位化 + USB 將 I/Q 資料流送往電腦 |
| 晶振 | 溫度補償晶振（TCXO） | 提供穩定參考頻率，避免頻率漂移 |

硬體光譜範圍涵蓋 **0.5 MHz（長波）到 1700 MHz（L 波段）**，因此 FM 廣播、航空 AM、氣象衛星、ADS-B、甚至業餘無線電都能收。最高穩定採樣頻寬約 **2.4 MHz**（極限可達 3.2 MHz）。

### 1.2 什麼是「被動接收」？

SDRlab H4M 的原理非常「老實」：**它只聽，不發**。天線把空中的電磁波轉成微弱的電壓訊號，接收器把這些訊號放大、數位化後交給電腦。整個過程**不會向空中發射任何能量**，也因此是各國無線電法規中最友善、門檻最低的合法應用類型。

### 1.3 為什麼鋁合金外殼對於「聽得到微弱訊號」至關重要？

這是 SDRlab H4M 最容易被忽略、卻最能影響成敗的設計。

RTL-SDR 這類接收器非常靈敏，靈敏到連**不想要的東西**也一起收進來——尤其當你把它插在電腦旁：USB 供電的開關式電源雜訊、主機板高頻頻輻射、螢幕排線的電磁干擾，都會「灌進」接收前端，蓋過你真正想聽的微弱訊號（例如 800 公里外的衛星）。

鋁合金外殼在這裡扮演三個角色：

1. **法拉第籠式的電磁屏蔽（EMI Shielding）**：金屬外殼形成局部屏蔽，阻擋來自電腦與週邊的環境射頻雜訊，顯著提升訊號對雜訊比（SNR）。對於 NOAA 衛星這種只有幾秒鐘強的微弱訊號，這往往是「收得到 / 收不到」的分水嶺。
2. **被動散熱與頻率穩定性**：鋁合金同時是良好的散熱片。R820T2 調諧器對溫度敏感，溫度穩定 = 參考頻率穩定，長期監聽時不易漂移。
3. **靜電保護（ESD）與耐用性**：鋁殼接地能導走天線感應的靜電，延長前端晶片壽命。

一句話總結：**好的屏蔽不增加你的訊號，而是幫你把雜訊擋在外面**——這在密集的城市電磁環境裡，CP 值極高。

## 二、實作：接收 118–137 MHz 航空 AM 語音（GQRX / SDR#）

118 MHz 到 137 MHz（VHF 航空通訊頻段）是航空器與地面塔台之間的**振幅調變（AM）語音通訊**。航班在起降階段會與塔台、近場台聯絡，內容包含高度、航向、跑道分配等。這是最容易入門、也最「有感」的頻譜體驗。

### 2.1 事前準備

- SDRlab H4M × 1
- 一台電腦（Windows / Linux / macOS 皆可）
- 天線：隨附的偶極天線或伸縮天線即可，若要更好可用 V-Dipole 或調整天線長度到約 **1.1 公尺（=137MHz 半波長）** 附近
- 免費軟體：**GQRX**（Linux/macOS）或 **SDR#（SDRSharp）**（Windows）

### 2.2 在 Linux 上用 GQRX

1. **安裝**：
   ```bash
   sudo apt update
   sudo apt install -y rtl-sdr gqrx
   ```
2. **釋出 USB 裝置**：RTL-SDR 會被 Linux 內建 TV 調諧器驅動（`dvb_usb_rtl28xxu`）搶佔，需先卸載再交給 `librtlsdr`：
   ```bash
   sudo rmmod dvb_usb_rtl28xxu
   # 一勞永逸：將 blacklist 寫入 /etc/modprobe.d/blacklist-rtl.conf
   # blacklist dvb_usb_rtl28xxu
   ```
3. **啟動 GQRX**，第一次執行會跳出接收器設定視窗：
   - **Device** 選擇 `Realtek RTL2838UHIDIR`（或對應 RTL-SDR 裝置）
   - 確認採樣率（Sample Rate）設為 2.4 MHz 或 2.048 MHz
   - 點 **Start**
4. **切換到航空波段**：
   - 在頻率輸入框輸入 `127600000`（可先試你所在機場進場頻率，或在網路上搜尋當地的 ATIS／塔台頻率）
   - **Mode（模式）選 `AM`**
   - 濾波器頻寬（bandwidth）設 **8–12 kHz**（航空 AM 為窄頻，太寬會收雜訊）
5. 若聽到「沙沙聲中夾著中文或英文語音」就成功了一半；試著在 118–137 間慢慢掃台。

### 2.3 在 Windows 上用 SDR#（SDRSharp）

1. **下載 SDR#**：到 RTL-SDR 官方網站下載 SDR# 壓縮包並解壓縮。
2. **安裝 Zadig 驅動**（關鍵步驟）：把 RTL2832U 從 Windows 內建驅動切換成 **WinUSB**。開啟 `zadig.exe` → Options 勾選 List All Devices → 選 RTL2832U → 點 **Replace Driver**。
3. 開啟 `SDRSharp.exe`，在左上角確認裝置被偵測，勾選 **RTL-SDR（Tuner A）**，按下播放鍵。
4. **Mode 選 `AM`**，頻率輸入 `118.000` – `137.000` MHz 之間的頻率（注意顯示單位為 MHz），再微調頻寬與音量即可收聽。

### 2.4 客服減量：航空接收常見排障檢查清單（Support Intake）

遇到「完全沒有聲音」時，依序檢查，並在聯繫客服前先完成此表：

| 症狀 | 依序檢查 | 最常見原因 |
|------|---------|-----------|
| 電腦抓不到裝置 | 1. USB 接孔換一個 ● 2. 線材再接一次 ● 3. 重新插拔 | USB 供電不足／接觸不良 |
| 掃不到任何台 | 1. 天線是否接上 ● 2. SMA 是否鎖緊 ● 3. 頻率是否在 118–137MHz ● 4. 是否靠近窗邊 | 天線沒接好或位置封閉 |
| 只有雜音沒有語音 | 1. Mode 是否為 AM ● 2. 濾波頻寬是否 8–12kHz ● 3. 機場是否太遠 | 模式／頻寬設定錯誤 |
| Linux 顯示被佔用 | 執行 `lsusb` 看是否為 dvb_usb 驅動 | 需 blacklist `dvb_usb_rtl28xxu` |
| Windows 裝置無法描述 | 重新執行 Zadig 套用 WinUSB | 驅動未正確替換 |

> 💡 客服小技巧：聯繫 yupitek 客服時，**附上 `lsusb` 或裝置管理員截圖 + 你測試的頻率與模式**，能讓技術人員直接定位問題，來回時間縮短一半以上。

## 三、進階：解碼 NOAA 氣象衛星即時 APT 類比雲圖

聽完語音後，接下來的進階關卡是把 **750 公里外的氣象衛星**「看」在螢幕上。這一步需要一點耐心與天線擺位，但成功那一刻的成就感無可取代。

### 3.1 原理：NOAA POES 衛星與 APT 訊號

美國國家海洋暨大氣總署（NOAA）的 **NOAA-15、NOAA-18、NOAA-19** 三顆極軌氣象衛星每天多次通過台灣上空，持續廣播 **APT（Automatic Picture Transmission）類比訊號**——把紅外線與可見光雲圖以每分鐘 120 行的方式掃描廣播：

| 衛星 | 下行頻率（MHz） | 訊號形式 | 頻寬 |
|------|----------------|---------|------|
| NOAA-19 | **137.100** | APT 類比 FM | ~34 kHz |
| NOAA-15 | **137.620** | APT 類比 FM | ~34 kHz |
| NOAA-18 | **137.9125** | APT 類比 FM | ~34 kHz |

衛星一次通過只有 **8–12 分鐘**，且訊號強度隨高度角劇烈變化，因此「預測軌道 + 正確天線 + 對的軟體」三者缺一不可。

### 3.2 硬體擺位

1. **天線建議**：使用 **V-Dipole**（兩根 53 公分、夾角 120° 的偶極天線），這是業界公認 137 MHz 最划算的選擇。
2. **視野**：讓天線朝向天空開闊處（東南東或西南西方向），避開建築與金屬遮蔽。地平面愈乾淨，訊號愈好。
3. **接收器設定（GQRX 範例，以 NOAA-19 為例）**：
   - 頻率 `137.100 MHz`
   - **Mode：FM（WFM）**
   - 濾波頻寬 **約 40 kHz**
4. **預測通過時間**：使用 **GPredict**（Linux/Windows）或 Heavens-Above 網站，查詢下一次 NOAA-19 高度角 > 30° 的通過時段。

### 3.3 解碼流程（WXtoImg / SatDump）

1. **錄製訊號**：在衛星通過期間，用 GQRX 或 SDR# 將音訊錄下來（或直接用虛擬音訊線把 FM 音訊送給解碼器）。
2. **解碼**：開啟 **WXtoImg**（老牌免費軟體）或跨平台開源的 **SatDump**，餵入音訊檔，自動同步行掃描線並輸出全彩衛星雲圖。
3. **產出**：約 10 分鐘後，你會得到一張覆蓋東亞海域與台灣上空的可見光或紅外線雲圖。
4. **進階細節**：衛星通過時會產生**都卜勒頻移**（逼近時頻率偏高、遠離時偏低），進階玩家可在通過中途手動微調 ±3 kHz，或用自動追蹤頻率的解碼器提升成功率。

> 💡 第一次失敗很正常——軌道預測誤差、天線角度、遮蔽物都會影響成敗。把每次通過的「頻率誤差 + 天線位置」記錄下來，通常第二次第三次就能收到清晰雲圖。
